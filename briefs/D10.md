# D10 実装指示文：満月に光る花の冠を川に流す

## 1. ゲームの概要と狙い

5歳の女の子が、文字を一切読まず、指1本で直感的に遊べる写実3Dウェブゲームを制作してください。

満月の光が降り注ぐ幻想的な川を舞台に、花の冠を指で送り出し、川に並ぶ石造りのゲートを一つずつ目覚めさせます。すべてのゲートに光が灯ると、川そのものが月へ続く光の道に変わり、花の冠と小舟が夜空へ向かってのぼっていきます。

### 3つの核

- **夢×写実**：本物のような花びら、水の流れ、濡れた石、月光の反射を描きながら、満月に反応するゲートと、夜空へとのぼる川という夢の世界を実現する。
- **高揚感**：ゲートが一つずつ目覚めるたびに月と川が輝きを増し、世界全体が壮大な変化を迎える期待感を育てる。
- **爽快感**：最後に完成した月光の道を、花の冠と小舟が水しぶきと光の粒を伴って一気に駆けのぼる。

単なる風景鑑賞ゲームにしないこと。自分の指で花の冠を動かし、自分の操作によって世界が変わっていくことを、遊びの中心に据えてください。

## 2. 絵から借りる光と色

### 2.1. 美術の基本方針

参考資料B19から借りるものは、満月、花の冠、水面の反射、月光に反応する石造りの建造物というモチーフ、および青・紫・銀白色を基調とした色彩の方向性のみとします。

既存作品の構図、建築形状、花の配置、絵柄は再現せず、独自の世界を構築してください。

自然物は写真のような質感を目指し、光の演出によって現実と想像が溶け合う世界にしてください。大作ファンタジー映画の魔法が発動する瞬間のように、静かな美しさと壮大な驚きを共存させます。

夜の世界ですが、暗闇を楽しむゲームではありません。川岸の草花、石造りのゲート、水面に浮かぶ冠が、常に十分な視認性を保つようにしてください。

### 2.2. 時間経過に伴う色彩設計

ゲーム全体を、深い青の月夜から銀白色と虹色が混ざる幻想的な夜明け前まで、段階的に変化させます。

| 要素 | 序盤 | 中盤 | 終盤 | クライマックス |
|---|---|---|---|---|
| 天頂の空 | `#253C79` | `#344C91` | `#505CA7` | `#637BC1` |
| 地平線 | `#778AC4` | `#9BA6DF` | `#C1B3E8` | `#F1D7EF` |
| 水面 | `#326B9E` | `#418EBB` | `#69B5D7` | `#B1E8F5` |
| 月光 | `#DAEBFF` | `#E3F1FF` | `#F1F7FF` | `#FFF7E5` |
| ゲート発光 | `#9FE7FF` | `#B3D6FF` | `#D3C5FF` | `#FFF1CE` |
| 花びら | 白・桃色 | 白・桃色・紫 | 淡い虹色 | 真珠色・虹色 |

空は時間経過に応じて連続的に補間し、突然色が切り替わらないようにします。段階移行時は約3〜5秒かけて変化させてください。

### 2.3. Three.jsにおける照明設定

以下の数値を初期調整値とし、実際の描画結果に応じて調整してください。

- 月光：DirectionalLight、色温度7500〜9500K相当、強度2.0〜3.5。
- 天空光：HemisphereLight、空側 `#BDD8FF`、地面側 `#697A92`、強度1.2〜1.8。
- 冠の補助照明：色温度5500〜6500K相当、強度0.5〜0.9。
- ゲート内部の発光：Emissive Intensity 1.5〜3.5。
- クライマックスの発光：Emissive Intensity 3.0〜5.0。
- トーンマッピング：ACESFilmicToneMapping。
- Exposure：1.0〜1.35を初期値とする。
- 霧：FogExp2、色 `#788EC3`、density 0.006〜0.012程度。
- ブルーム：Strength 0.4〜0.85、Radius 0.35〜0.55、Threshold 0.85〜1.1程度。

数値はThree.jsのバージョンやシーンのスケールに合わせて最適化してください。

ブルームで輪郭を失わせないこと。花びらや石の質感が残ったまま、発光する箇所の周囲に光が広がる描写を目指します。

## 3. 舞台と登場するもの

すべてのモデル、テクスチャ、アニメーション、音声を手続き的に生成してください。外部の画像、3Dモデル、動画、音声ファイルは使用禁止です。

### 3.1. 川と地形

湖のように穏やかな水面を持つ、幅の広い川を生成してください。

川幅は約12〜18mとし、岸辺には自然な起伏、小石、草地、低木、白い花が点在します。川岸を左右対称にせず、自然な地形の不規則性を持たせてください。

川の中心線は緩やかな曲線で構成します。ただし、急カーブは設けず、カメラが頻繁に回転する状況を避けてください。

地形には低周波ノイズと細かなノイズを組み合わせ、草地・土・砂利の色を頂点カラーやプロシージャルシェーダーで混合します。

草花や小石はInstancedMeshを利用し、描画負荷を抑えながら密度のある景観を作ってください。

### 3.2. 水面

水面は、このゲームの最重要ビジュアルの一つです。単色の透明な平面にしないでください。

専用の水面シェーダーを用い、以下の要素を組み合わせます。

- 異なる方向・波長を持つ3〜4種類の波。
- 波高0.01〜0.07m程度の穏やかな水面変形。
- 法線の細かなゆらぎによる月光のきらめき。
- Fresnel効果による視線角度依存の反射。
- 岸辺の浅瀬と中央部の深い水の色の違い。
- 花の冠の移動に伴うV字形の航跡。
- 花びらの周囲から広がる小さな波紋。
- ゲートが発光した際の水面の光の反射。

満月の反射は、月からプレイヤーへ向かって伸びる銀色の帯として表現してください。波の形に応じて反射が細かく分断され、絶えず形を変えることが重要です。

ゲートを通過するたびに、この反射帯の長さと幅が増していきます。

毎フレームの高解像度ミラー反射は必須とせず、月の位置と水面法線から計算する近似反射を積極的に活用してください。

### 3.3. 花の冠

プレイヤーが直接操作する主役です。最も丁寧に作り込んでください。

直径約0.9〜1.2mの円環状の花冠とし、白い花、桃色の花、小さな紫色の花、瑞々しい緑の葉を組み合わせます。

花冠は単なる円環に花模様を貼ったものではなく、個々の花びら、花芯、葉、茎が実際の立体形状を持つようにしてください。

花びらは曲面メッシュから生成し、中心付近と外縁で色を変化させます。形状、向き、大きさには適度な個体差を設けます。

マテリアルの目安：

| 部位 | Roughness | Metalness | 質感 |
|---|---:|---:|---|
| 花びら | 0.45〜0.65 | 0 | 薄い膜を透過する光 |
| 葉 | 0.30〜0.50 | 0 | 葉脈と水滴の光沢 |
| 茎 | 0.55〜0.75 | 0 | 植物の繊維感 |
| 水滴 | 0.05〜0.15 | 0 | 小さな鏡面反射 |

花びらの逆光部分には、疑似的な透過光を加えてください。花全体を常時発光させるのではなく、花びらの縁や水滴が月光を受けて輝くようにします。

冠は水面の波に合わせて上下し、最大3度程度の傾きを持たせます。指で送り出された際には、わずかに回転しながら滑らかに進みます。

### 3.4. 石造りのゲート

川の両岸から立ち上がり、水路をまたぐ独自形状の石造りのアーチを生成してください。

ゲートは全15基とし、5基ずつ3段階に分けます。同じ形状を単純に複製するのではなく、石の積み方、高さ、装飾、発光する結晶の形状などを変化させます。

石材には以下の質感を与えます。

- 灰白色から青灰色の自然な色むら。
- 細かな凹凸と欠け。
- 石の継ぎ目。
- 水に近い部分の濡れた光沢。
- 部分的な苔や小さな植物。
- 月光に反応する透明な結晶。

石材のRoughnessは0.65〜0.9、濡れた部分は0.25〜0.45程度とします。

未起動時もゲートの形状がはっきり見えるようにしてください。起動済みのゲートとの違いは、黒さではなく、発光量・結晶の輝き・光の流れによって表現します。

### 3.5. 満月、星、雲

満月は画面内で常に存在感を持つ、巨大な球体または天球上の円盤として描画します。

クレーター模様を手続き的なノイズと円形の凹凸パターンから生成し、単なる白い円にしないでください。

視直径は序盤で約5〜7度、終盤で約9〜12度を目安とします。現実より大きい月ですが、風景の中に自然に溶け込ませます。

星は数百個程度の点群で生成し、個々の輝度に差を持たせます。雲は半透明のプロシージャルノイズを用いた層状表現とし、非常にゆっくり移動させてください。

月を雲で完全に隠してはいけません。

### 3.6. 小舟と動物

プレイヤーが乗っていることを想像できる、小さな木製の舟を配置してください。

舟は木目、船縁、金具、水面に接する部分の光沢を持つ写実的な形状とします。船体はカメラの下方に置き、花の冠を遮らないようにしてください。

人間や人体は描画しません。

岸辺には白い水鳥や小さな蝶を少数配置しても構いません。ただし、操作対象と誤認されないようにし、冠とゲートの視認性およびFPSを優先してください。

## 4. 指1本で完結するプレイループ

### 4.1. 開始

ページを開いた直後から、満月と川、花の冠、最初のゲートが見える状態にします。

タイトル画面や開始ボタンは設けません。

水面に浮かぶ冠の周囲に小さな光が集まり、冠の花びらに沿って一周します。この動きによって、冠が触れる対象であることを伝えてください。

冠を最初にタップすると、小さな波紋と透明感のある音が発生し、ゲームが開始します。

### 4.2. 1回の操作の流れ

**課題 → 取り組み → 結果**の関係を毎回明確にしてください。

1. **課題の提示**

   冠が手元の水面に浮かんでおり、その先に未起動のゲートがあります。ゲートの結晶が小さく呼吸するように輝き、次の行き先を示します。

2. **冠に触れる**

   冠に指を置くと、その位置から円形の波紋が広がります。冠が少し沈み、水面が揺れることで、指が触れたことを伝えます。

3. **冠を送り出す**

   指をゲートの方向になぞると、冠が指の動きに追従して前進します。画面上で20〜35 CSS px程度以上の前方への移動を検出したら、送り出しを成立させます。

4. **水面を滑走する**

   指を離した後、冠は慣性を持ってゲートまで自動的に進みます。花びらの周囲に細かな水しぶきが生じ、冠の後方に銀色の航跡が伸びます。

5. **ゲートが目覚める**

   冠がゲートをくぐる瞬間、結晶から青白い光が発生し、アーチの両側から頂点に向かって光が駆け上がります。満月が一段輝きを増し、水面の光の道が伸びます。

6. **次の操作へ**

   小舟とカメラが冠に追いつき、次のゲートが正面に現れます。冠は再び手元に浮かぶ位置まで相対的に近づき、同じ操作を続けられます。

同一の冠が連続して川を進む構造とし、毎回別の冠が出現する表現にはしないでください。

### 4.3. 操作の寛容性

ゲートに向かう正確な軌道を要求してはいけません。

送り出しの方向判定は進行方向を中心とした左右約65度の範囲を許容し、成立後の軌道は自動的に補正してください。

冠から多少外れた位置で触れても操作できるように、見た目より広い当たり判定を用意します。

逆方向への操作、短すぎる操作、途中での指離しによって、冠が沈む、花びらが散る、ゲートに衝突するなどの現象は起こさないでください。

スコア、制限時間、残機、失敗判定、やり直しの要求は一切設けません。

### 4.4. 操作を促す視覚的な誘導

操作可能な状態で約3秒間入力がなければ、冠の縁を月光が一周します。

さらに入力がなければ、冠が進行方向へわずかに動き、元の位置に戻ります。同時にゲートの結晶が輝きます。

この誘導を適度な間隔で繰り返してください。文字、矢印、指や手のアイコンは使用禁止です。

実際の送り出しやゲートの起動は、プレイヤーの操作なしには発生させないでください。

## 5. 盛り上がりと全体の進行

標準プレイ時間は約3〜5分とします。

全15基のゲートを3段階に分け、1回の操作によって生じる変化を段階的に拡大してください。

| 段階 | ゲート数 | 主な体験 | 目安時間 |
|---|---:|---|---:|
| 第1段階 | 5基 | 月光が石のゲートを目覚めさせる | 50〜75秒 |
| 第2段階 | 5基 | 川全体へ光が伝わっていく | 55〜80秒 |
| 第3段階 | 5基 | 月と川がつながり始める | 55〜80秒 |
| クライマックス | — | 月光の川を駆けのぼる | 20〜30秒 |
| 余韻 | — | 月の下で静かに漂う | 10〜15秒 |

時間は目安であり、操作が速い子どもを不必要に待たせないでください。逆に、操作が遅くても急かさないこと。

### 5.1. 第1段階：月光が目覚める川

川幅は比較的狭く、岸辺の花や石の細部が見える距離から始めます。

冠は約2〜3m/sで滑走します。

ゲートが起動すると、小さな結晶が輝き、銀白色の光が石の表面を伝わります。成功音は透明感のある単音と短い余韻です。

5基目の起動時には、川岸に咲く白い花へ光が連鎖し、これまでより広い景色が現れます。

### 5.2. 第2段階：星のきらめく川

川幅が広がり、水面に星のような反射が増えていきます。

冠の滑走速度は約3〜4.5m/sとします。

ゲートの起動に伴い、青、紫、桃色の光が水面を流れ、岸辺の花が次々と輝きます。成功音は2音または3音の和音に変化します。

10基目の起動時には、月光の反射帯が川の奥までつながり、遠くのゲートの輪郭が月光に浮かび上がります。

### 5.3. 第3段階：月へ続く川

川が広い湖面へと変化し、周囲の視界が大きく開けます。

冠の滑走速度は約4.5〜6m/sとし、冠の後ろに残る航跡を長くします。

ゲートが起動するたびに、光の粒がアーチから空へとのぼり、月と水面を結ぶ光が太くなります。

最後のゲートは、前のゲートより約1.5〜2倍の高さを持つ壮大な構造物としてください。ただし、画面外へ見切れないようにカメラをあらかじめ調整します。

最後の冠を送る操作も、それまでと同じ操作方法にします。特別に難しいジェスチャーは要求しません。

### 5.4. クライマックス：月光の川を駆けのぼる

15基目のゲートを通過した瞬間から、以下の演出を連続的に実行してください。

- 0〜2秒：最後のゲートの結晶が順番に輝き、光がアーチの頂点へ集まる。
- 2〜5秒：水面に蓄積された月光が一つにつながり、川の先端がゆっくりと空へ持ち上がる。
- 5〜9秒：空中に向かって続く銀白色の水の道が形成され、冠がその上を進み始める。
- 9〜20秒：小舟が冠に追従し、滑らかに加速して空へとのぼる。速度は最大12〜16m/s程度とする。
- 20〜25秒：満月の手前に到達し、冠の周囲から真珠色と虹色の光の粒が大きく広がる。

空中の川は、単なる光の線ではなく、水の表面と波、反射、流れを持つ立体的な水路として生成します。

光の粒が左右へ流れ、水面の細かな模様が後方へ通過することで、速度感を表現してください。

急落下、急旋回、カメラの揺れ、画面全体の白い閃光は使用しません。

### 5.5. 静かな余韻と再プレイ

クライマックス後は速度を落とし、満月を正面に見ながら、冠と小舟が静かな水面を漂う場面へ移行します。

花の冠はゆっくり回転し、周囲の光の粒が少しずつ水面へ降りていきます。音楽も余韻を残しながら静まります。

約10〜15秒後、淡い月光の霧を利用した自然な場面転換によって、最初の川へ戻ります。

再び冠に触れるだけで遊び始められる状態にしてください。ページの再読み込みやリスタートボタンは不要です。

## 6. カメラと画面構成

### 6.1. 基本カメラ

花の冠の少し後方かつ上方から眺める追従カメラを使用してください。

カメラは冠と次のゲートの中間付近を注視し、両者を画面中央の領域に収めます。

画面上の配置の目安：

| 対象 | 画面の横方向 | 画面の縦方向 |
|---|---|---|
| 満月 | 中央 | 上から15〜23% |
| 次のゲート | 中央 | 上から40〜50% |
| 花の冠 | 中央 | 上から58〜68% |
| 小舟の先端 | 中央 | 上から85〜95% |

冠、ゲート、満月が視線の流れに沿って縦方向に並ぶ構成を基本とします。

### 6.2. 自動フレーミング

冠、ゲート、満月の境界領域を画面座標へ投影し、すべてが安全領域内に入るよう、カメラ距離と画角を自動調整してください。

- 安全領域：画面の上下左右から約8〜12%内側。
- PerspectiveCameraの垂直FOV：40〜65度程度。
- カメラ位置の補間時間：0.5〜1.2秒程度。
- 注視点の補間時間：0.4〜0.8秒程度。
- ロール角：原則0度。

操作対象を画面端に置かないこと。装飾よりも目標の視認性を優先してください。

クライマックスでは、カメラの注視点を徐々に月へ移しながら、冠と月の両方が画面に収まる構図を維持します。

### 6.3. 縦横画面への対応

iPhoneの縦画面、iPadの縦・横画面、PCの横画面すべてに対応してください。

縦画面では必要に応じてカメラを後方へ移動させ、ゲートの左右が切れないようにします。

横画面では画面の横幅を利用して岸辺の景観を見せますが、冠やゲートの配置は中央を維持してください。

端末の回転によってゲームを初期化してはいけません。

## 7. 操作と入力処理

Pointer Eventsを使用し、タッチとマウスを共通の仕組みで処理します。

- `pointerdown`で冠の操作を開始する。
- `pointermove`で指の移動方向と距離を取得する。
- `pointerup`で送り出しを確定する。
- `pointercancel`では操作状態を安全に解除する。
- Pointer Captureを利用し、指が当たり判定の外へ出ても操作を継続できるようにする。
- 最初のポインターのみを使用し、追加の指による入力は無視する。
- 冠の当たり判定には、最低直径72 CSS px程度を確保する。
- 送り出し中の連続入力による二重起動を防止する。

ゲーム領域では、ピンチズーム、ダブルタップズーム、スクロール、長押しメニュー、テキスト選択、画像のドラッグを抑止してください。

`touch-action: none`、`overscroll-behavior: none`、`user-select: none`などを適切に設定し、iPad Safari固有の挙動にも配慮します。

画面サイズの変化にはResizeObserverおよび必要に応じてVisual Viewport APIを利用してください。

## 8. 音響設計

すべての音をWebAudio APIによって手続き的に合成してください。

最初のユーザー操作時にAudioContextを作成またはresumeし、それ以前は無音でも正常に動作するようにします。

### 8.1. 操作音と成功音

| 場面 | 音の設計 |
|---|---|
| 冠に触れる | 小さな水滴音と短い正弦波 |
| 冠を送り出す | 帯域制限したノイズによる水の滑走音 |
| 第1段階の成功 | C5・E5・G5などの透明な単音 |
| 第2段階の成功 | 2〜3音の分散和音 |
| 第3段階の成功 | 高音域を加えた3〜4音の和音 |
| 最後のゲート | 広い音域を使った上昇音 |
| クライマックス | 水音、風音、長い和音の重なり |
| 余韻 | 減衰していく鐘のような音 |

成功音は毎回同じ音程にせず、段階内でも少しずつ上昇させます。音の変化によって、世界が完成へ向かっていることを伝えてください。

サイン波、三角波、倍音成分、短いノイズを組み合わせ、電子的な警告音やゲームセンターのような騒音にならないようにします。

### 8.2. 環境音

穏やかな水の流れ、岸辺に吹く風、遠くから響く音色を、ごく控えめな音量で再生します。

主音量を1.0とした場合のGainの目安は、環境音0.05〜0.10、操作音0.12〜0.20、成功音0.15〜0.25としてください。

DynamicsCompressorNodeなどを用いて急激な音量上昇を防止します。

AudioContextが起動できない場合も、ゲーム進行を妨げないでください。

## 9. 画面の文字と禁止事項

ゲーム画面には文字、数字、説明文、ボタンのラベル、スコア、進捗バーを一切表示しないでください。

開始、操作、成功、段階移行、再プレイのすべてを、物体の動き、光、音、景色の変化だけで伝えます。

不気味な生物、おばけ、怪物、不穏な風景、お姫様、人間のキャラクター、既存のキャラクター、実在のブランド、既存作品固有の建造物や意匠は使用禁止です。

夜の風景であっても、操作対象や進行方向を見失うような照明にしてはいけません。

また、別紙の禁止語を、HTML、CSS、JavaScript、コード内のコメント、ログ、画面表示などに使用しないでください。

## 10. 画質の自動調整とパフォーマンス

iPad Safariで50fps以上を維持することを目標としてください。可能な限り60fpsを目指します。

画質はhigh / mid / lowの3段階を用意します。

| 項目 | high | mid | low |
|---|---:|---:|---:|
| 最大ピクセル比 | 1.75 | 1.25 | 1.0 |
| シャドウマップ | 1024〜2048 | 512〜1024 | 簡易影 |
| 水面の波成分 | 4 | 3 | 2 |
| 光のパーティクル上限 | 1000 | 500 | 200 |
| ブルーム | 高品質 | 低解像度 | 疑似発光 |
| 草花・小石の密度 | 100% | 65% | 40% |
| 水面メッシュ密度 | 高 | 中 | 低 |

初期状態はmidを基本とし、起動後のフレーム時間から適切な品質を選択してください。

実行中も直近2〜3秒程度のフレーム時間を監視します。

- 50fps未満が約2秒継続した場合は1段階下げる。
- 58fps以上が約10秒継続した場合は1段階上げることを検討する。
- 画質切り替え後は約10秒のクールダウンを設ける。
- バックグラウンド移行中のFPS低下を判定に含めない。

`?q=low`、`?q=mid`、`?q=high`による強制設定にも対応してください。強制設定時は自動画質変更を停止します。

低画質でも、冠の立体形状、月光の反射、ゲートの起動、クライマックスの水の道は必ず維持してください。遊びの核を削って高速化することは禁止です。

ジオメトリやマテリアルの再利用、InstancedMesh、パーティクルのオブジェクトプール、視錐台カリングを活用します。

毎フレームのオブジェクト生成や不要な再計算を避け、描画ループ中のメモリ確保を最小限にしてください。

## 11. 技術構成

### 11.1. ファイル構成

実装対象は以下の1ファイルです。

`site/games/d10/index.html`

HTML、CSS、JavaScriptをすべてこのファイルにまとめてください。

Three.jsはリポジトリに同梱済みのものを使用します。

- Three.js本体：`site/vendor/three/build/three.module.min.js`
- Three.js追加モジュール：`site/vendor/three/examples/jsm/`

importmapを使用し、ゲームファイルからの相対パスとして以下を設定してください。

| モジュール名 | 相対パス |
|---|---|
| `three` | `../../vendor/three/build/three.module.min.js` |
| `three/addons/` | `../../vendor/three/examples/jsm/` |

CDN、外部API、外部素材、追加ライブラリのネットワーク経由での取得は禁止です。

`<head>`内に以下を入れてください。

```html
<meta name="robots" content="noindex">
```

`</body>`の直前に以下を入れてください。

```html
<script src="../../gf-playlog.js" defer></script>
```

### 11.2. ゲーム状態の管理

ゲームの進行は明示的な状態管理によって実装してください。

以下の状態を基本とします。

| 状態 | 内容 |
|---|---|
| `IDLE` | 開始操作を待つ |
| `AIM` | 冠の送り出しを待つ |
| `DRAG` | 冠を操作中 |
| `GLIDE` | 冠がゲートへ滑走する |
| `ACTIVATE` | ゲート起動演出 |
| `ADVANCE` | 次のゲートへ移動 |
| `STAGE_TRANSITION` | 段階移行 |
| `CLIMAX` | 月光の川をのぼる |
| `AFTERGLOW` | 静かな余韻 |
| `RESET` | 初期状態への復帰 |

状態遷移とアニメーションの完了条件を明確にし、入力の連打やアニメーションの重複による進行停止を防止します。

段階番号、起動済みゲート数、各ゲートの発光状態、冠の位置、カメラ位置を一元管理してください。

### 11.3. 準備完了とエラー記録

`window.__ready`を用意してください。

初期値をfalseとし、シーン構築、入力イベント登録、初回描画が正常に完了した時点でtrueに設定します。

`window.__errors`を配列として用意し、JavaScriptの実行時エラー、未処理のPromise拒否、初期化エラーを記録してください。

エラー監視は可能な限り早い段階で開始します。

WebGLコンテキストの消失や復帰、ブラウザのバックグラウンド移行も考慮し、復帰時の異常な時間経過や物体の瞬間移動を防止してください。

### 11.4. 自動プレイモード

URLに`?autotest`が指定された場合、自動的にゲームを開始し、通常の操作と共通する処理を通じて15基すべてのゲートを起動してください。

自動プレイ専用の疑似的な成功画面を表示するのではなく、実際の冠の移動、ゲートの発光、段階移行、クライマックスを実行します。

テスト時間短縮のため、入力待機時間と演出時間を短縮することは許容します。

AudioContextの起動にはブラウザのユーザー操作制限があるため、自動テスト時の音声再生は必須としません。

自動テスト用の進行情報はJavaScriptから取得できるようにしても構いませんが、ゲーム画面には表示しないでください。

## 13. 最終的な品質基準

実装上の優先順位は、以下の順序としてください。

1. 子どもが迷わず、自分の指で遊べること。
2. 一つの操作が、世界の大きな変化につながること。
3. 花の冠、水面、月光が写真のような質感を持つこと。
4. 最初から最後まで段階的な高揚感があること。
5. 最後の空中滑走に十分な爽快感があること。
6. iPad Safariで安定して動作すること。

特に、最後の演出だけを豪華にして、途中の15回の操作が単調になることを避けてください。各ゲートの起動そのものが、小さなクライマックスであるように設計します。

完成したゲームを遊んだ子どもが、「もう一回、あの花を流したい」「もう一回、お月さままで行きたい」と自然に思える作品を目指してください。
