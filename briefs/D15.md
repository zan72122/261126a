# D15 実装指示文：海から宇宙へ泳ぎ出すイルカ

## 1. ゲームの狙い

5歳の女の子が、イルカと一緒に夜の海を跳び、水面から月のそばへ、さらに惑星の間を抜けて宇宙へ旅立つ、写真のような写実3Dウェブゲームを制作すること。

- **夢×写実：** イルカが宇宙を泳ぐという夢のような体験を、濡れたイルカの肌、水しぶき、月面の凹凸、惑星の大気、地球を覆う雲などの写実的な描写によって、本当に起きているかのように感じさせる。
- **高揚感：** 海面から月へ、月から巨大な惑星へ、さらに宇宙から地球全体を眺める場所へと、指で触れるたびに世界のスケールが拡大していく喜びを生み出す。
- **爽快感：** イルカが光の輪を突き抜ける瞬間の加速、水しぶきの飛散、そして水滴が星くずへと変化する連続的な演出によって、何度でも跳びたくなる感覚を生み出す。

本作で最も重要なのは、単なる宇宙の鑑賞ではなく、**自分の指でイルカを跳ばせた結果、海から宇宙まで到達できたという主体的な体験**である。

映像の美しさだけで満足せず、タップするたびに気持ちのよい変化が起き、次の輪に触れたくなるゲームにすること。

## 2. 絵から借りる光と色

### 2.1 アートディレクション

参考資料B2・B3・B17から、以下の視覚的な要素だけを借りる。

- 珊瑚の海と宇宙の色彩が自然につながる世界観。
- 紫色や青色の海と、月光を受けて輝く水しぶき。
- 巨大な天体を背景にしたイルカの存在感。
- 宇宙から眺める青い地球の美しさと神秘性。
- 現実の自然現象と想像上の現象が、同じ光の法則の中で共存する感覚。

参考作品の構図、絵柄、天体の配置、イルカのポーズを直接再現してはならない。

目指すのは、自然写真のような質感を持ちながら、長編ファンタジー映画のように光が魔法を起こす、独自の3D空間である。

### 2.2 段階ごとの色彩設計

ゲーム中は夜から宇宙へ連続的に移行する。夜であっても視認性を犠牲にしてはならない。

| 要素 | 第1段階：夜の海 | 第2段階：月への飛翔 | 第3段階：惑星の宇宙 | 第4段階：地球光 |
|---|---|---|---|---|
| 背景上部 | `#172858` | `#161D49` | `#111D40` | `#142B50` |
| 背景下部 | `#946CB9` | `#5555A0` | `#343B76` | `#345C91` |
| 主光源 | `#DAE9FF` | `#FFF2DC` | `#D8E9FF` | `#BDEEFF` |
| 補助光 | `#947FFF` | `#B7A3F5` | `#BB9AFF` | `#69C8FF` |
| 光の輪 | `#AAEEFF` | `#FFF0BB` | `#E4C3FF` | `#E2FAFF` |
| 粒子の主色 | 水色・銀色 | 銀色・金色 | 紫・水色・金色 | 青白色・金色 |

背景を完全な黒一色にしない。宇宙でも青や紫の星間光を薄く残し、イルカの輪郭と進行方向が常に確認できるようにする。

### 2.3 Three.jsの照明設定

以下は初期値の目安とし、実際のレンダリング結果に応じて調整する。

| 設定 | 推奨値 |
|---|---|
| 月光の色温度 | 約7,500〜9,000K |
| 太陽光の色温度 | 約5,200〜5,800K |
| 地球から届く演出的な反射光 | 約8,000〜10,000K |
| DirectionalLight intensity | 2.0〜3.5 |
| HemisphereLight intensity | 1.2〜1.8 |
| HemisphereLight skyColor | `#C5DEFF` |
| HemisphereLight groundColor | `#514D88` |
| Tone Mapping | ACESFilmicToneMapping |
| Exposure | 1.15〜1.40 |
| Bloom strength | 0.35〜0.65 |
| Bloom radius | 0.4〜0.7 |
| Bloom threshold | 0.85〜1.0 |

海上ではFogを使用し、ゲーム内の単位をイルカの全長約3とした場合、nearを35〜50、farを180〜240程度に設定する。

上空へ進むにつれて霧を薄くし、宇宙では通常の距離霧を原則として無効化する。星雲は霧ではなく、背景シェーダーや低負荷な半透明レイヤーで表現する。

ブルームは光の輪、水滴、星くず、大気の縁に重点的に適用する。イルカや惑星の表面全体を白く発光させないこと。

## 3. 舞台と登場するもの

外部の画像、テクスチャ、3Dモデル、音声ファイルは一切使用しない。すべてプロシージャル生成、Three.jsのジオメトリ、CanvasTexture、シェーダー、WebAudioによって制作する。

### 3.1 夜の海

最初の舞台は、月光が降り注ぐ透明度の高い海とする。

- 海面は200×200〜300×300程度のPlaneGeometryを基本とする。
- 複数方向の波を合成し、Gerstner Waveに近い頂点変位を実装する。
- 波長は2〜18、振幅は0.05〜0.35程度とする。
- 波の細部は頂点数を増やすのではなく、シェーダー上の法線のゆらぎで表現する。
- Fresnel効果によって、浅い角度では空の色が強く反射するようにする。
- 月光の反射が海面に縦長の光の道となって伸び、波の動きに合わせて細かく分裂するようにする。
- 海水の基本色は`#075B8B`、深部は`#092A56`、波頭は`#BCEEFF`を目安とする。

浅い場所には、珊瑚礁や白い砂地を配置する。珊瑚は分岐する曲線と細いジオメトリを組み合わせ、InstancedMeshで描画する。

水面下の珊瑚礁は序盤の景観を豊かにするための要素であり、操作対象にはしない。

海面はイルカの移動に合わせて描画範囲を循環させ、無限に続くように見せる。島や海底を含む巨大な地形を生成する必要はない。

### 3.2 主役のイルカ

本作の写実性を最も左右するモデルである。制作時間を優先的に割り当てること。

単純な球体の集合や玩具のような造形にはせず、バンドウイルカを想起させる流線形の体を作る。

- 全長：約3。
- 胴体：断面の大きさが連続的に変化する曲線ベースのメッシュ。
- 頭部：額から吻部にかけて自然に連続する形状。
- 胸びれ：左右に1枚ずつ。
- 背びれ：後方へ緩やかに湾曲する形状。
- 尾びれ：魚類と異なり、水平方向に広がる形状。
- 目：小さな黒褐色の眼球と微細な光の反射。
- 腹部：背面から自然に移行する銀白色。

背面を`#627F9A`、側面を`#91AFC2`、腹部を`#DAE8ED`程度とし、頂点カラーまたはプロシージャルシェーダーで滑らかに色を変化させる。

MeshPhysicalMaterialまたはMeshStandardMaterialを使用する。roughnessは0.20〜0.32、metalnessは0〜0.05、clearcoatは0.3〜0.5を目安とする。濡れた肌に月光が映り込むように、手続き的に生成した環境マップを利用する。

泳ぎのアニメーションは胴体後半から尾びれへ伝わる周期的な上下運動を中心とする。尾びれを左右に振る魚の泳ぎ方にしない。

通常時は約1.2〜1.6Hz、加速時は約1.8〜2.2Hzで尾びれを動かす。跳躍時には胴体全体が弧を描き、空中では胸びれをわずかに広げる。

人間のプレイヤーモデル、手、鞍、手綱などは描画しない。イルカの斜め後方から追従するカメラによって、一緒に乗って旅をしている感覚を作る。

### 3.3 水しぶきと星くず

水しぶきから星くずへの変化は、本作を象徴する演出として特に丁寧に作り込む。

海上では以下の3種類を組み合わせる。

- 大きな水滴：透明感と月光の反射を持つ小粒子。
- 細かなしぶき：加速方向と反対側へ扇状に広がる粒子。
- 水面の波紋：イルカが海面を離れた地点から広がる円形の波。

宇宙への移行時には、同じ粒子群の重力、透明度、発光量、色、寿命を徐々に変更する。

水滴が途中で消えて別の星が出現するのではなく、飛び散った一粒一粒の水滴そのものが発光する星くずへ変化したように見せること。

### 3.4 月・惑星・地球

すべて球体ジオメトリとプロシージャルテクスチャで生成する。

**月**

直径18〜30程度の球体に、複数のノイズと大小のクレーターを組み合わせる。クレーターには中心部のくぼみと外縁の隆起を付け、法線マップによって立体感を出す。

基本色は`#D0D5DD`。陰影を持たせながらも、暗部の形状が見えるようにする。

**惑星**

最低3種類を登場させる。

- 黄褐色と白色の縞模様を持つ巨大ガス惑星。
- 青緑色の雲と薄い大気を持つ惑星。
- 金色や乳白色の環を持つ惑星。

ガス惑星の縞模様には緯度方向のノイズと渦を使用する。環にはRingGeometryを使用し、半径方向の透明度と色彩を変化させて多数の細い環が重なって見えるようにする。

**地球**

最後の主役として、イルカと同等以上に描写品質を重視する。

海洋、大陸、雲、大気を別々のレイヤーで構成する。大陸は球面上に複数の輪郭を手続き的に生成し、ノイズで海岸線を変形させる。厳密な地理的再現は不要だが、地球と認識できる青い海と緑・褐色の大陸を作る。

雲は地表より約1〜2%大きい球体に配置し、透明度を持たせたノイズで渦状の雲や雲帯を表現する。

大気は地表より約3〜5%大きい球体とFresnel系シェーダーによって表現し、外縁に青白い光を生じさせる。

### 3.5 空・雲・星空

海上では、紫から群青へ変化する空のグラデーションと、月光を受けた雲を描く。

雲は多数の白い球体を並べるのではなく、ノイズによる密度の変化を持つ半透明のレイヤーとする。

宇宙では、星の大きさと輝度に差を付け、遠景には微細な星、近景にはまばらな発光粒子を配置する。流星群のような演出は成功時に限定し、常時大量の星を高速移動させない。

## 4. 指1本のゲームループ

### 4.1 基本ループ

すべての段階で、以下の共通操作を繰り返す。宇宙へ進んでも操作方法を変更しない。

**① 課題：前方に光の輪が現れる**

イルカの進行方向、画面中央に光の泡で構成された輪が出現する。

輪は最初から認識できる大きさで表示し、イルカの接近とともに大きく見えるようにする。輪の直径はイルカの全長の1.5〜2.5倍を目安とする。

**② 取り組み：指でタップする**

輪がイルカの正面に近づくと、輪の光が強まり、輪を構成する粒子が中心へ向かって収束する。

この変化によって、今タップすると何かが起こることを直感的に伝える。

プレイヤーがタップすると、イルカが尾びれを力強く動かし、輪の中心へ向かって跳躍する。

**③ 結果：輪を突き抜ける**

イルカが光の輪を通過した瞬間に、以下を同期させる。

- イルカが前方へ加速する。
- 輪が放射状に弾ける。
- 水しぶき、または星くずが画面周辺へ飛散する。
- 心地よい上昇音と透き通った成功音が鳴る。
- 周囲の景色が一段階先へ進む。
- 次の光の輪が進行方向に現れる。

入力からイルカの反応までは原則100ms以内とする。輪の通過まで多少時間が必要な場合でも、尾びれの動きや発光によって即座に反応を返す。

### 4.2 失敗のないタイミング操作

厳密なタイミングゲームにしてはならない。

輪がイルカに十分接近した瞬間を理想的なタップ位置とするが、その前後には広い受付範囲を設ける。

早めにタップした場合は入力を保持し、イルカが自然に輪へ到達できるタイミングで跳躍する。

タップが遅れた場合は、イルカが輪の手前をゆっくり泳ぎ続けるように速度を調整する。輪が背後へ流れて消えることはない。

画面中央付近へのタップも有効とし、輪そのものに正確に指を合わせる必要はない。

失敗音、赤色の警告、減点、制限時間、衝突、墜落、ゲームオーバーは実装しない。

### 4.3 操作しない場合の誘導

約2.5秒間操作がなければ、輪の発光をゆっくり増減させる。

約5秒間操作がなければ、輪の内側に光の粒子が集まり、短い予告音が鳴る。イルカも輪へ向かって小さく体を持ち上げる。

以後は約4〜6秒間隔で誘導を繰り返す。

文字、矢印、手のアイコンは使用しない。また、放置しただけで輪を通過してゲームが進んでしまうことも避ける。

## 5. 盛り上がりの設計

標準的なプレイ時間は約3〜5分とする。

全4段階、各6回、合計24回の輪の通過を基本構成とする。1回の操作から次の操作まで約7〜9秒を目安とし、プレイヤーを待たせすぎない。

| 段階 | 成功回数 | 主な景色 | 体験 |
|---|---:|---|---|
| 第1段階 | 1〜6 | 月光の海・珊瑚礁 | 水面を跳ぶ |
| 第2段階 | 7〜12 | 上空・月 | 水滴が星へ変わる |
| 第3段階 | 13〜18 | 巨大な惑星・惑星の環 | 宇宙を泳ぐ |
| 第4段階 | 19〜24 | 星の海・青い地球 | 地球光に包まれる |

### 5.1 第1段階：月光の海を跳ぶ

開始時、イルカは月光の反射する海面をゆっくり泳いでいる。

最初の輪は画面中央にあり、タップすると小さな跳躍が起こる。イルカが海面から飛び出し、再び水面へ滑り込む。

輪を通過するたびに跳躍の高さを増加させる。

- 1回目：海面から約1.5の高さ。
- 2回目：約2.5の高さ。
- 3回目：約4の高さ。
- 4回目：約6の高さ。
- 5回目：約10の高さ。
- 6回目：約16の高さから上昇を継続。

跳躍ごとに水しぶきの量、月光の反射、海面の波紋が豊かになる。

6回目では海へ戻らず、イルカが空中を泳ぎ続ける。雲の向こうに次の光の輪が出現し、その先に月が見える。

### 5.2 第2段階：水しぶきが星に変わる

ここは本作の中で最も重要な変化の場面である。

イルカが雲の間を通過すると、水面から飛び出したときの水滴がイルカの後方を追いかけてくる。

輪をくぐる瞬間、約1.5〜2.5秒かけて以下の変化を同時に起こす。

- 水滴の落下運動が止まり、無重力のように漂い始める。
- 水滴の内部から青白い光が生まれる。
- 水滴の色が銀色、水色、金色へ分かれる。
- 水しぶきの音が、鈴やガラスを思わせる音へ移行する。
- 空のグラデーションに星が増え、海面が遠ざかる。

イルカの泳ぎ方はそのまま維持する。ロケットに変形したり、翼が生えたりする演出は不要である。

月のクレーターが見える距離まで接近し、月面の縁に沿って滑空する。月に衝突したり、着陸したりする操作は設けない。

最後の輪を通過すると、月の向こうに複数の巨大な惑星が現れる。

### 5.3 第3段階：惑星の間を泳ぐ

輪をくぐるたびに、宇宙ならではの異なる景色を体験させる。

1. 黄褐色の巨大ガス惑星のそばを通る。
2. 惑星の渦模様が近くに見える。
3. 青緑色の惑星の大気に沿って泳ぐ。
4. 金色に輝く惑星の環の上を通過する。
5. 環を構成する小さな光の粒がイルカの後方へ流れる。
6. 惑星の間を抜け、広大な星空へ到達する。

惑星は操作対象ではなく、イルカが進むことで景観が変わる舞台装置とする。

惑星の巨大さは、ゆっくりとした相対移動、表面模様の細かさ、遠近感によって表現する。急激な接近や衝突を想起させる映像にはしない。

### 5.4 第4段階：青い地球を振り返る

最後の6回は、青白色と金色の光の輪を中心とする。

イルカの進行経路が大きな弧を描き、これまで泳いできた方向を徐々に振り返るようにする。

カメラを突然180度回転させるのではなく、複数の輪を通過する間に少しずつ進行方向を変化させる。

遠方に小さな青い光が見え始め、輪を通過するたびに、その光が青い地球であることが分かるようになる。

最後の輪は地球の手前、画面中央に配置する。

### 5.5 クライマックス：地球光の解放

24回目の成功は、通常の成功演出とは明確に区別する。

- 最後の輪が金色と青白色の光へ分解される。
- イルカの周囲から多数の星くずが広がる。
- 星くずが地球の外縁に沿って流れていく。
- 地球の大気が青白く輝き、海と雲が月光のような光を反射する。
- カメラがゆっくり引き、地球全体と手前を泳ぐイルカが見える。
- 成功音が豊かな和音へ発展し、約3〜4秒間響く。

画面全体を白一色にするフラッシュは使用しない。地球の輪郭と表面模様を最後まで視認できるようにする。

クライマックス後は約10〜15秒間、地球の前をイルカがゆっくり泳ぐ余韻を設ける。

その後、星くずから形成された光の輪を出現させる。この輪に触れると、青い光に包まれながら最初の海へ戻り、再び遊べるようにする。

得点画面や終了画面は作らない。

## 6. カメラ

### 6.1 基本位置

PerspectiveCameraを使用し、イルカの斜め後方、やや上方から追従する。

初期設定の目安は以下とする。

- イルカから後方へ7〜10。
- 上方へ2〜4。
- 左右方向へ1〜2。
- FOV：48〜55度。
- near：0.1。
- far：描画範囲に応じて約500〜2,000。

イルカの全身、次の輪、進行先の景色を同時に確認できる構図とする。

### 6.2 操作対象を常に中央に置く

カメラの注視点は原則として次の光の輪の中心とする。

イルカを画面下部の中央寄り、光の輪を画面中央に配置し、プレイヤーが自然に次の操作対象へ視線を向けられるようにする。

輪の中心を画面幅・高さの中央付近、原則として各±5%以内に維持する。

輪を通過した後は、現在の輪の消滅と次の輪への注視点の移行を滑らかに連動させる。次の輪が画面中央に入ってから操作可能な状態にする。

### 6.3 縦画面・横画面への対応

画面比率に応じてカメラ距離を自動調整する。

縦画面では横方向の視野が狭くなるため、横画面と同じカメラ距離を固定使用してはならない。

対象物の境界球を利用して、縦方向と横方向の両方に収まる距離を求める。

最終場面では地球の発光する大気まで含め、画面の短辺に対して直径70〜80%程度に収める。地球全体の外側に十分な余白を残すこと。

### 6.4 酔いを防ぐ

- カメラのロール角は原則0度。
- カメラ位置と注視点は時間差を考慮した補間で追従させる。
- 旋回速度は最大でも毎秒10〜15度程度。
- 加速感は主に粒子、景色の相対移動、音で表現する。
- FOVの急変、画面振動、急降下、強いモーションブラーは使用しない。
- イルカが上下しても、カメラを完全に同じ振幅で上下させない。

## 7. 操作

iPad Safari、iPhone Safari、PCのマウス操作に対応する。

Pointer Eventsに統一し、タッチとマウスで同じゲームロジックを使用する。

操作はタップまたはクリックのみとする。ドラッグ、長押し、複数の指、端末の傾きによる操作は必要としない。

輪の当たり判定は見た目の約1.3〜1.6倍に拡大する。小さく見える遠方の輪でも、最低64CSSピクセル程度の判定範囲を確保する。

連打で複数の成功処理が同時に発生しないよう、輪ごとに入力の受付状態を管理する。2本目以降の指からの入力は無視する。

ゲーム領域では以下を抑止する。

- スクロールとオーバースクロール。
- ピンチズームとダブルタップズーム。
- 長押しによるコンテキストメニュー。
- テキスト選択。
- ドラッグによるブラウザの標準動作。

`touch-action`、`overscroll-behavior`、`user-select`、viewport設定などを適切に組み合わせ、Safari固有の挙動も確認する。

## 8. 音

すべてWebAudioで手続き的に合成する。外部音声ファイルは禁止する。

AudioContextは最初のユーザー操作で起動またはresumeする。

### 8.1 効果音

| 場面 | 音の設計 |
|---|---|
| 輪への接近 | 小さな鈴のような予告音 |
| 跳躍開始 | 水や空気を切る短い上昇音 |
| 海上の輪の通過 | 水しぶきと澄んだ単音 |
| 水滴から星への変化 | 水音からガラス質の音への連続的変化 |
| 宇宙の輪の通過 | 透明感のある複数の音 |
| 地球の出現 | 広がりのある長い和音 |

水音はフィルターを通したホワイトノイズやピンクノイズと、短い音量エンベロープを組み合わせる。

成功音はサイン波、三角波、高次倍音をわずかに持つ音を中心とする。

### 8.2 段階ごとの音楽的発展

- 第1段階：C5、E5、G5などの単音を中心とする。
- 第2段階：2音の協和音を加える。
- 第3段階：長三和音、分散和音を加える。
- 第4段階：付加音やオクターブを重ね、世界の広がりを表現する。
- クライマックス：Cmaj9などの透明感のある和音をゆっくり響かせる。

BGMは控えめな波音、風音、持続音を基本とする。既存楽曲を模倣せず、成功音が環境音に埋もれないようにする。

マスターゲインは0.25〜0.40程度を初期値とし、音の重複による急激な音量増加を防止する。

## 9. 画面の文字

ゲーム画面には文字、数字、得点、ステージ名、説明文、ボタンラベルを一切表示しない。

開始画面も夜の海とイルカ、呼吸するように発光する輪だけで構成する。光の輪に触れるとゲームが始まる。

ロード中に表示が必要な場合は、光の粒子が集まるアニメーションなどを利用する。

操作方法は、対象物の発光、動き、音、位置関係だけで伝える。

## 10. 画質の自動調整

iPad Safariで50fps以上、可能であれば安定した60fpsを目標とする。

起動時および実行中のフレーム時間を計測し、high、mid、lowの3段階を自動選択する。

| 項目 | high | mid | low |
|---|---:|---:|---:|
| 最大ピクセル比 | 1.75 | 1.25 | 1.0 |
| 海面分割数 | 128×128 | 80×80 | 48×48 |
| 天体の球体分割数の目安 | 64×48 | 48×32 | 32×24 |
| 同時表示エフェクト粒子数 | 1,200 | 600 | 250 |
| シャドウマップ | 最大1024 | 最大512 | 無効 |
| ブルーム | 有効 | 低解像度 | 疑似発光 |
| 背景の雲・星雲 | 高品質 | 簡略化 | 最小限 |

実行中は直近約2〜3秒間の平均フレーム時間を用いて判定する。50fps未満の状態が継続した場合は画質を1段階下げる。

58fps以上の状態が約10秒間継続した場合に限り、画質を上げることを検討する。頻繁な切り替えを防止するため、切り替え後にはクールダウン時間を設ける。

`?q=low`、`?q=mid`、`?q=high`で画質を強制指定できるようにする。強制指定中は自動変更しない。

lowでも光の輪、水滴から星への変化、地球の大気、イルカの泳ぎは維持する。ゲームの核となる表現を削除してはならない。

粒子のオブジェクトプール、InstancedMesh、ジオメトリの再利用、不要な描画の停止を積極的に利用する。

## 11. 技術構成

### 11.1 ファイル構成

実装対象は以下の1ファイルとする。

`site/games/d15/index.html`

HTML、CSS、JavaScript、シェーダー、プロシージャル生成処理をすべてこのファイルに含める。

Three.jsはリポジトリに同梱されている以下を使用する。

- `site/vendor/three/build/three.module.min.js`
- `site/vendor/three/examples/jsm/`

importmapでは、`three`を`../../vendor/three/build/three.module.min.js`へ、`three/addons/`を`../../vendor/three/examples/jsm/`へ対応させる。

CDN、外部API、外部アセット、追加のパッケージ取得は不要とする。

`<head>`内に以下を必ず含める。

`<meta name="robots" content="noindex">`

`</body>`の直前には以下を必ず含める。

`<script src="../../gf-playlog.js" defer></script>`

### 11.2 状態管理

以下の状態を明確に分離して管理する。

- `LOADING`：初期化。
- `READY`：開始操作待ち。
- `APPROACH`：輪への接近。
- `WAIT_INPUT`：操作受付。
- `BOOST`：跳躍・加速・成功演出。
- `TRANSITION`：段階間の景観変化。
- `CLIMAX`：地球光の解放。
- `AFTERGLOW`：余韻。
- `RESTART`：初期状態への復帰。

ゲーム進行、入力、カメラ、音、粒子、画質管理の責務を分離する。

フレームレートに依存してイルカの速度や進行時間が変わらないよう、経過時間を利用して更新する。バックグラウンドから復帰した直後の過大な時間差も制限する。

### 11.3 準備完了とエラー監視

`window.__ready`を初期状態でfalseとし、必要なシーンの生成、入力受付、初回描画が完了した時点でtrueにする。

`window.__errors`を空の配列として初期化し、実行時エラー、初期化エラー、未処理のPromise拒否などを記録する。

エラー監視は可能な限りモジュール読み込み前から有効にしておく。

### 11.4 自動プレイ

URLに`?autotest`が存在する場合は、自動プレイモードを有効にする。

開始から24回の輪の通過、全4段階、クライマックス、余韻まで到達させる。

自動プレイ専用の簡略化されたシーンを作らず、通常プレイと同じ入力処理、成功処理、状態遷移を使用する。

テスト時間短縮のため待機時間を短縮してもよいが、各段階の景観生成や成功演出を省略しない。

ユーザー操作なしでAudioContextを起動できない環境では、無音のままテストを継続する。

到達段階、成功回数、クライマックス到達の有無、完了状態を開発者がコンソールから確認できるようにする。

## 14. 実装時の優先順位

制作上の制約が生じた場合は、次の優先順位に従うこと。

1. 指1本で迷わず操作できること。
2. 輪を突き抜ける瞬間が気持ちよいこと。
3. 水しぶきが星くずへ変化する瞬間に驚きがあること。
4. イルカと地球が写実的で美しいこと。
5. 海から宇宙へ進むにつれて高揚感が増すこと。
6. iPadで滑らかに動作すること。
7. 背景の細部や追加の装飾が充実していること。

本指示文では、段階数、成功回数、各種描画設定を具体的な初期設計値として定めた。実際の映像品質と操作感に応じた微調整は許容するが、ゲームの基本ループや主要な景観変化を省略してはならない。

目指す完成形は、5歳の子どもが、自分の指でイルカを跳ばせることに夢中になり、いつの間にか海を離れて宇宙まで泳ぎ出し、最後に青く輝く地球を見て思わず声を上げるような体験である。
