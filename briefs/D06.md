# D06 実装指示文：深い海で光るイルカと泳ぐ

## 1. ゲームの狙い

あなたは、写実的な3Dグラフィックス、海洋生物のアニメーション、光の演出、幼児向けのインタラクション設計に精通したゲーム開発者です。

5歳の女の子が、文字を一切読むことなく、指1本で遊べる3Dウェブゲームを完成させてください。

このゲームでは、夜の海の中で光をまとったイルカたちと出会い、離れているイルカを仲間のもとへ導き、群れと一緒に光の輪をくぐりながら、最後には満月が浮かぶ水面へと泳ぎ上がります。

- **夢×写実**：イルカの体を幻想的な白い光が縁取る非現実的な光景を、実際の海中の光学現象、イルカの生態に即した泳ぎ、水や気泡の質感によって、本当に体験しているかのように表現する。
- **高揚感**：イルカを仲間のもとへ導くたびに海の透明度が増し、光の粒が広がり、群れの動きが次第に壮大になっていくことで、期待感を積み重ねる。
- **爽快感**：イルカたちが作る巨大な光の渦に乗って海中を上昇し、水面を突き抜け、満月と星空が広がる瞬間に、蓄積してきたエネルギーを一気に解放する。

最も重要なのは、美しい海中映像を鑑賞することではなく、**自分が指を動かすことでイルカが動き、群れが完成し、海そのものが変わっていく体験**である。

プレイヤーを観客にせず、海の変化を引き起こす存在にすること。

## 2. 絵から借りる光と色

### 2.1. アートディレクション

参考となる2作品からは、深い藍色の海、白い光で縁取られたイルカ、鮮やかな珊瑚礁、水中における発光感と空間の奥行きという要素だけを借りる。

既存作品の構図、イルカの配置、ポーズ、絵柄を模倣してはならない。独自の3D空間として構築すること。

現実と想像が溶け合う海洋世界を目指す。イルカの皮膚や水の質感は自然科学系の映像作品に近づけながら、発光現象や光の輪には、上質なファンタジー映画のような驚きと魔法の感覚を持たせる。

夜の海であっても、恐怖や孤独を感じさせないこと。常にイルカの姿、周囲の水、進むべき方向が認識できる照度を確保する。

### 2.2. 段階ごとの色彩設計

Three.jsのワールド単位は、原則として1 unit＝1 m相当とする。

以下の値は初期調整の目安であり、実際のレンダリング結果を確認して最適化すること。

| 要素 | 第1段階：出会い | 第2段階：光の珊瑚礁 | 第3段階：月への上昇 |
|---|---|---|---|
| 海の基調色 | `#12365F` | `#104E78` | `#247EB0` |
| 遠方の水 | `#102746` | `#195B84` | `#63B8DB` |
| 環境光 | `#8EBBFF` | `#A3E7FF` | `#D1F3FF` |
| イルカの発光 | `#D8F5FF` | `#C2FFFF` | `#FFF6DD` |
| 光の粒 | 青白・水色 | 水色・薄紫・真珠色 | 白・金・淡い虹色 |
| Fog開始距離 | 8 m | 12 m | 18 m |
| Fog終了距離 | 55 m | 75 m | 110 m |
| Bloom strength | 0.35 | 0.50 | 0.65 |

ゲームの時間経過に伴って夜が明ける必要はない。一貫して満月の夜とし、深度、透明度、発光体の増加によって光景を変化させる。

### 2.3. 光源とレンダリング

- 月光は約7,500〜9,000 K相当の青白い光とし、`#C5DEFF`を基準色とする。
- イルカの縁の発光は約6,500〜8,000 K相当の白から水色を基本とする。
- 珊瑚礁には青緑、薄紫、真珠色の局所的な発光を加える。
- クライマックスでは約4,500〜5,500 K相当の淡い金白色を加え、達成感を表現する。
- `HemisphereLight`の強さは0.8〜1.4、月光を表現する`DirectionalLight`は1.2〜2.2程度を初期値とする。
- トーンマッピングは`ACESFilmicToneMapping`、露出は1.0〜1.25程度を目安とする。
- 出力色空間はsRGBとし、PBRマテリアルを使用する。
- Bloomのthresholdは0.8〜1.1、radiusは0.35〜0.55程度とする。

発光は輪郭や光の粒を際立たせるために使う。画面全体が白くかすんだり、イルカの形状や皮膚の質感が失われたりしないようにする。

急激な点滅、強烈な白色フラッシュ、ストロボ状の演出は禁止する。

### 2.4. 海上の空

クライマックスで水面に到達した際には、以下の色彩による満月の夜空を展開する。

- 天頂：`#142B60`
- 中間の空：`#345F9A`
- 水平線付近：`#829DC9`
- 月の中心：`#FFF5D9`
- 月の周囲の光輪：`#BFDFFF`

満月の光が海面に長く反射し、波の動きに応じて細かく分裂する様子を表現する。

水中の藍色から、開放的な水平線と星空へ変化すること自体を、最後の大きなご褒美とする。

## 3. 舞台と登場するもの

### 3.1. 海中空間

完全な3D空間として構築する。平面的な背景の上にイルカを動かすだけの実装にしてはならない。

海中には以下の空間的な層を作る。

| 空間 | 描画するもの |
|---|---|
| 近景 | 気泡、水中を漂う微粒子、イルカの背中 |
| 中景 | イルカの群れ、光の輪、珊瑚礁 |
| 遠景 | 海底の岩、遠方の珊瑚、水面から届く月光 |
| 上方 | 波打つ水面、屈折した月光、上昇する気泡 |

近景・中景・遠景で移動速度、色、コントラストを変え、視差による立体感を生み出す。

海底には滑らかな起伏のある砂地と丸みのある岩を配置する。海底の暗い穴、洞窟、沈没船、骨などは出さない。

珊瑚は分岐する枝状、扇状、半球状の形を組み合わせ、プロシージャルに生成する。色は青緑、淡いピンク、紫、橙色を中心とする。

海底や珊瑚はあくまで舞台であり、プレイヤーの視線をイルカから奪わないようにする。

### 3.2. イルカの造形

イルカは、このゲームにおいて最も制作コストをかけるべき対象である。

バンドウイルカを基本とした、現実のイルカに近い形状をプロシージャルに生成する。

- 全長：2.5〜3.2 m程度
- 流線型の胴体
- 自然な曲面を持つ額と吻
- 背中の鎌形の背びれ
- 左右の胸びれ
- 水平に広がる尾びれ
- 頭部に自然に収まる小さな黒い目
- 背側の青灰色から腹側の真珠色への連続的な色の変化

単純な球体やカプセル形状を重ねただけのモデルにしないこと。体軸に沿った断面形状を補間して連続したメッシュを生成し、頭部から尾部まで自然な曲面を作る。

背びれ、胸びれ、尾びれにも厚みを持たせる。

皮膚には`MeshPhysicalMaterial`または`MeshStandardMaterial`を使用する。

| マテリアル項目 | 初期値の目安 |
|---|---:|
| 背側の色 | `#688AA0` |
| 腹側の色 | `#D1DEE5` |
| Roughness | 0.25〜0.38 |
| Metalness | 0.0 |
| Clearcoat | 0.20〜0.35 |
| Clearcoat roughness | 0.22 |
| 法線の微細な変化 | 0.03〜0.08相当 |

皮膚の法線には、ごく細かなプロシージャルノイズを加える。ただし、魚の鱗、ゴム製玩具、金属製ロボットのような質感にしない。

目を極端に大きくしたり、人間のように笑わせたり、擬人化した表情を付けたりしない。実在のイルカそのものの魅力を生かす。

### 3.3. イルカの泳ぎ

イルカの移動は、位置と回転だけを変更する硬直したアニメーションにしてはならない。

体軸を複数の変形区間に分け、胴体から尾びれにかけて上下方向の波が伝わるように変形させる。

- 通常の尾びれの周期：0.9〜1.4秒
- 加速時の周期：0.55〜0.85秒
- 通常の遊泳速度：1.2〜2.5 m/s
- 光の輪へ向かう速度：2.5〜4.0 m/s
- 胸びれの角度変化：上下左右に5〜15度程度
- 進行方向への回転は補間し、瞬間的に向きを変えない。

魚のように胴体全体を左右にくねらせるのではなく、イルカ特有の上下方向の尾びれ運動を再現する。

各個体の泳ぎの位相、速度、胸びれの角度を少しずつ変える。すべてのイルカが完全に同期した機械的な動きにならないようにする。

群れには個体間の最低距離を設け、体やひれが互いに貫通しないようにする。

### 3.4. イルカを縁取る光

イルカの発光は、体全体を発光マテリアルに置き換える方法ではなく、Fresnel項を利用したリムライトを基本とする。

視線に対して接線に近い表面ほど発光が強くなるようにし、背中、吻、胸びれ、尾びれの輪郭に細い光が現れるようにする。

- Fresnel power：2.5〜4.0
- 通常個体の発光強度：0.4〜0.8相当
- 操作対象の発光強度：1.0〜1.8相当
- 誘導時の発光周期：1.4〜2.0秒

発光の変化は正弦波などで連続的に行う。対象を完全に消灯させない。

泳いだ軌跡には短い光の粒の尾を残す。光の尾は0.8〜2.0秒で自然に消える。

輪郭の光が夢の要素、皮膚の質感と泳ぎが写実の要素である。両者を同時に認識できる状態を維持する。

### 3.5. 水、月光、気泡

海水の表現には、距離による色の吸収、深度による色の変化、微細な浮遊物、水面から届く光の筋を組み合わせる。

海中で赤系統の光が弱くなり、青緑系統の光が残る現象を簡略化して再現する。

水面には複数の方向を持つ波を合成したシェーダーを使用する。

- 波長：0.8〜8 m
- 波高：0.03〜0.18 m
- 法線の微細なゆらぎを重ねる。
- Fresnel反射により、浅い視線角度ほど反射を強くする。
- 海面を突き抜ける瞬間には、水中から海上へ描画設定を連続的に移行する。

月光の筋は半透明の形状や軽量なシェーダーで表現する。負荷の大きい本格的なボリュームレンダリングは必須としない。

気泡には球状の透明感、細い反射光、上昇に伴う緩やかな横方向のゆらぎを持たせる。

光の粒と気泡は明確に区別する。光の粒は幻想的な発光体、気泡は現実の水中現象として表現する。

### 3.6. 空、雲、満月

星空はプロシージャルに生成する。満月には多層ノイズによる月面模様を加え、単純な白い円盤にしない。

雲は少数の薄い雲の層として、低速で移動させる。満月を覆い隠さないこと。

満月の見かけの大きさは、海上到達時に画面短辺の15〜22％程度を目安とする。

実際の月より大きく見える幻想的な演出とするが、海や空の写実性は保つ。

### 3.7. プレイヤーの存在

人体、顔、アバター、潜水服などは描画しない。

カメラの少し前方に、子どもが泳いでいると仮定した不可視のプレイヤー座標を設ける。カメラはその斜め後方から、イルカたちと一緒に移動する。

乗りものは登場させず、イルカたちの群れと光の流れそのものが、プレイヤーを運んでくれる感覚を作る。

すべての形状、テクスチャ、環境光用データ、音は手続き的に生成する。外部の画像・3Dモデル・音声ファイルを使用しない。

## 4. 指1本で遊ぶ基本ループ

### 4.1. 開始画面

起動直後から、海中の3D空間を表示する。

画面中央に1頭のイルカが現れ、ゆったりと泳ぎながら白い輪郭光を周期的に強める。周囲には仲間のイルカが数頭いる。

タイトル、説明文、開始ボタンは表示しない。

中央のイルカに触れると、イルカが小さく旋回し、歓迎するように光の粒を放出する。同時に音が有効になり、最初の遊びが始まる。

### 4.2. 1回分の操作と結果

1回の基本ループを約8〜12秒とする。

<escape>**① 課題：仲間から離れたイルカを見つける**</escape>

群れの1頭が少し離れた位置を泳ぐ。その1頭を画面中央に配置し、輪郭光を周期的に強める。

仲間の群れは、その後方で円弧を描きながら泳いでいる。1頭が戻れば輪が完成することを、イルカの配置から視覚的に理解できるようにする。

<escape>**② 取り組み：イルカへ向かって指をなぞる**</escape>

プレイヤーが画面に触れ、中央のイルカへ向かって指を滑らせる。

指の移動に伴い、水中に細い水色の光の流れが生まれる。イルカがそれに気づいたように顔の向きを変え、指の動きに呼応して泳ぎ始める。

指を正確な経路に沿わせる必要はない。移動方向が大まかにイルカへ向いていれば受理する。

直接イルカをタップした場合にも、短い誘導動作として受理する。指を滑らせる操作を基本としながら、5歳児の自然なタップを拒絶しない。

<escape>**③ 結果：イルカが仲間のもとへ戻る**</escape>

入力成立後、イルカは約1.2〜1.8秒かけて自然な曲線を描きながら仲間のもとへ泳ぐ。

群れが円形に整列し、各個体の輪郭光がつながることで、空間に1つの大きな光の輪が完成する。

完成の瞬間には以下を同時に起こす。

- 輪の接続部分から光が一周する。
- 透明感のある成功音が鳴る。
- イルカが尾びれを一度大きく動かす。
- 光の粒が輪の外側へ広がる。
- 周囲の海の透明度が少し増す。

<escape>**④ ご褒美：光の輪をくぐる**</escape>

カメラと不可視のプレイヤー座標が、完成した輪の中心へ向かって自動的に進む。

輪をくぐった瞬間には、数十〜数百個の光の粒が左右へ流れ、奥行きのある空間が開ける。

通過後には、次の1頭が群れから離れ、再び画面中央に現れる。

### 4.3. 入力の許容範囲と誘導

操作対象の画面上の当たり判定は、イルカの表示範囲の1.3〜1.6倍程度とする。短辺が小さい端末でも、最小直径88 CSS px程度の操作領域を確保する。

指の移動方向は目標への方向から±60度程度まで許容し、20〜30 CSS px程度の移動でも誘導が成立するようにする。

操作経路を採点したり、線の形の正確さを判定したりしない。指で道を描くこと自体を課題にしてはならない。

操作対象から外れた位置に触れても、悪いことは一切起きない。イルカは逃げず、光も失われず、進行状況も戻らない。

約3秒間入力がなければ、対象のイルカの輪郭光を強める。約6秒間入力がなければ、イルカがゆっくりと顔をこちらへ向け、胸びれを動かす。

文字、矢印、手のアイコン、画面に描かれた操作経路は使用しない。

1回の入力で複数回成功することは防ぐが、次の操作対象が現れた後は、すぐに次の入力を受け付ける。

## 5. 盛り上がりの設計

全体を3段階、各6回、合計18回の基本ループで構成する。

通常のプレイ時間は約3〜5分を想定する。ただし、時間制限は設けず、子どもが何も操作しない時間は自由に延長できるものとする。

| 要素 | 第1段階 | 第2段階 | 第3段階 |
|---|---|---|---|
| テーマ | イルカとの出会い | 光の珊瑚礁 | 満月への上昇 |
| 群れの頭数 | 4頭 | 6頭 | 8頭 |
| 操作回数 | 6回 | 6回 | 6回 |
| 光の輪の直径 | 約5〜6 m | 約7〜8 m | 約9〜10 m |
| 光の粒 | 少なめ | 多彩で増量 | 空間全体に広がる |
| 音楽的な変化 | 単音 | 2〜3音の和音 | 広がりのある和音 |

### 5.1. 第1段階：イルカとの出会い

ゲーム開始時は、水深約35 mを想定した藍色の海にいる。

最初の4頭のイルカは、プレイヤーから近い場所をゆっくり泳ぐ。

1回成功するたびに、光の粒が少しずつ増え、遠くまで見通せるようになる。

最初の成功は、開始後数秒以内に体験できるようにする。説明や長い導入映像で待たせない。

6回目の輪を通過すると、遠方に鮮やかな珊瑚礁が現れ、そこから2頭のイルカが群れへ加わる。

### 5.2. 第2段階：光の珊瑚礁

水深約20〜30 mの海中を、イルカたちと珊瑚礁の上方に沿って移動する。

基本操作は変更しない。ただし、イルカが戻って光の輪を完成させるたびに、周囲の珊瑚へ光が伝わり、青緑、薄紫、真珠色の発光が広がる。

光の粒がイルカの軌跡から海底へ流れ、珊瑚礁の奥にまで波及する様子を見せる。

背景の変化は、成功によって引き起こされたことが明確に伝わるタイミングで開始する。

6回目の輪を通過すると、さらに2頭のイルカが合流する。上方に水面の月光が現れ、群れは次第に上向きに泳ぎ始める。

### 5.3. 第3段階：満月への上昇

8頭のイルカとともに、月光の届く海中を泳ぎ上がる。

光の輪はそれまでより大きくなり、輪の面が少しずつ上方へ傾いていく。

成功するたびに気泡が増え、光の粒の流れが上方へ向き、イルカたちの泳ぎにも勢いが増す。

水面までの距離は、成功に応じて段階的に縮まっていく。最後の操作対象が群れに戻ると、全員の輪郭光が金白色を帯びる。

ここでは「もうすぐ何か大きなことが起こる」という期待感を最大限に高める。

### 5.4. クライマックス：光の渦と満月

最後の操作が成立したら、約15〜20秒間の特別な演出へ移行する。

**0〜4秒：群れが集まる**

8頭のイルカが大きな円を作る。各個体の光の軌跡が連結し、空間に巨大な光の輪が完成する。

**4〜10秒：上昇する光の渦**

群れが上向きの螺旋状の軌道へ移行する。

イルカの光の尾と気泡によって、巨大な光の渦が形成される。プレイヤーはその中心を通り、イルカたちとともに水面へ近づく。

渦はイルカと光が作るものであり、危険な海流や竜巻には見せない。

カメラ自体は回転させない。周囲が穏やかに旋回することで、渦に乗っている感覚を作る。

**10〜13秒：水面を突破する**

水面が画面中央の上昇目標として迫る。

細かな気泡、水の反射、屈折が画面を通過し、月光を映した海面を滑らかに突き抜ける。

イルカのうち数頭が水面から優雅に跳び出し、水滴が月光を反射する。

画面の白飛びや急激なカメラの上下動を使わず、水中から海上へ視界が開けることで爽快感を生む。

**13〜20秒：光の解放**

満月を画面中央に置く。

イルカの光の軌跡から数多くの光の粒が広がり、海面と星空を彩る。最も豊かな和音と水面の音を重ねる。

その後、光の粒はゆっくり減少し、静かな波と満月の光だけが残っていく。

### 5.5. 余韻とフリープレイ

クライマックス後は約8〜12秒の余韻を設ける。

満月の下でイルカが泳ぎ、月光の道が海面に広がる様子を楽しめるようにする。

その後は、満月の下で1頭のイルカが光を強め、再び触れられる状態になる。

そのイルカに触れると、滑らかな潜水演出を経て最初の海中空間へ戻り、もう一度遊べるようにする。

リザルト画面、点数、評価、終了メッセージは設けない。

## 6. カメラと画面構成

### 6.1. 基本方針

**その瞬間にプレイヤーが最も注目すべき対象を、常に画面の中央に置くこと。**

カメラの制御対象を、ゲームの状態に応じて切り替える。

| 状態 | 画面中央の対象 |
|---|---|
| 開始時 | 最初のイルカ |
| 操作待ち | 仲間から離れたイルカ |
| イルカの合流中 | 仲間へ戻るイルカ |
| 輪の完成時 | 光の輪の中心 |
| 輪の通過時 | 輪の中心と進行方向 |
| 渦による上昇時 | 光の渦の中心軸 |
| 水面到達時 | 月光が差し込む水面 |
| クライマックス | 満月 |

操作対象のイルカを画面中央から外さず、後方にいる仲間の群れも画面内に収まるように、イルカ側の配置とカメラの両方を制御する。

次の操作対象を出現させる際には、カメラを大きく振り回すのではなく、イルカを中央へ泳がせる。

カメラは目標の移動を滑らかに追跡する。目標の画面座標は原則としてX＝50％、Y＝50％とし、操作待ちの間は中央から±5％以内を目安とする。

### 6.2. 縦画面と横画面

iPadの横画面とiPhoneの縦画面の両方に対応する。

カメラの引きの距離を固定せず、アスペクト比と対象群の境界範囲から必要な距離を求める。

- 垂直FOV：45〜55度を基本とする。
- 操作対象のイルカ：画面短辺の25〜40％程度。
- 光の輪：画面短辺の65〜80％程度。
- クライマックスの渦：画面短辺の80〜85％以内。
- 主要対象の周囲には8〜12％以上の余白を確保する。

縦画面では横方向の視野が狭くなるため、必要に応じてカメラを後退させる。カメラだけでは収まりきらない場合は、群れの奥行き方向の配置も調整する。

イルカの吻、尾びれ、光の輪の外周などが画面外に出ないことを、投影座標に基づいて確認する。

輪をくぐる瞬間に限り、輪が視野の周囲へ流れることは自然な通過表現として許容する。ただし、輪の完成時には必ず全体を見せる。

### 6.3. 酔いを防ぐ制御

- カメラのロール角は原則0度。
- 回転速度は通常時10〜20度/秒以内を目安とする。
- 注視点の切り替えは0.6〜1.2秒程度で補間する。
- 急加速、急停止、画面の振動、急激なズームは禁止する。
- 上昇の勢いは光の流れ、気泡、視差、イルカの泳ぎによって表現する。

視野を狭める高速移動演出や、カメラを螺旋状に回転させる演出は使用しない。

## 7. 操作とタッチインタラクション

iPad Safari、iPhone Safari、PCブラウザで同じ操作が成立するようにする。

`pointerdown`、`pointermove`、`pointerup`、`pointercancel`を使用し、タッチとマウスの処理を統一する。

最初に入力したポインターのみを操作対象として管理し、2本目以降の指は無視する。

必要に応じてPointer Captureを利用し、指が操作対象の外側へ移動しても入力を追跡できるようにする。

以下のブラウザ標準動作は抑制する。

- ピンチズーム
- ダブルタップズーム
- ページスクロール
- オーバースクロール
- 長押しによるコンテキストメニュー
- テキスト選択
- 画像のドラッグ

CSSの`touch-action: none`、`user-select: none`などを適切に設定する。

画面回転、リサイズ、バックグラウンドからの復帰、`pointercancel`が発生しても操作不能にならないようにする。

タッチした瞬間から光の粒やイルカの反応を開始し、入力への視覚的な応答は100 ms以内を目標とする。

## 8. 音の設計

### 8.1. 基本構成

すべての音をWebAudio APIで手続き的に合成する。外部音声ファイルは使用しない。

最初のユーザー操作のイベント内でAudioContextを生成または再開する。

音響の基本は以下の5種類とする。

| 場面 | 音のイメージ | 合成方法 |
|---|---|---|
| 海中の環境音 | 遠くの水の流れ | フィルター付きノイズ |
| 指での誘導 | 水中を光が流れる音 | サイン波と周波数変化 |
| イルカの合流 | 澄んだガラスの響き | 減衰する複数のサイン波 |
| 輪の通過 | 水と光が広がる音 | ノイズと上昇する和音 |
| 水面への到達 | 水しぶきと開放的な響き | フィルター付きノイズと長い和音 |

イルカの鳴き声は短い周波数変調によって表現してもよい。ただし、甲高い警報音や不自然な電子音にならないようにする。

### 8.2. 成功音の成長

第1段階はC5、E5、G5などの短い単音を中心とする。

第2段階はCメジャーやFメジャーを基調とした2〜3音の和音を使い、第3段階は高音域やオクターブを加える。

最後のクライマックスではCメジャーadd9などの広がりのある和音を、2〜4秒程度の余韻とともに鳴らす。

常に協和性を重視し、成功回数に応じて際限なく音程や音量を上げない。

BGMは主張の少ない環境音と持続音を基本とする。成功音を妨げる連続的なメロディーは避ける。

マスターゲインは0.25〜0.40程度を目安に調整し、音が重なってもクリッピングしない構成とする。

失敗音、警告音、カウントダウン音は実装しない。

## 9. 画面の文字とUI

ゲーム画面に文字、数字、タイトル、説明、スコア、進行ゲージ、ボタンのラベルを一切表示しない。

次の操作対象はイルカ自身の光と動きによって伝える。進行状況は群れの頭数、海の透明度、光の量、水面までの距離によって伝える。

読み込み画面が必要な場合も、文字を使用せず、中央に小さな光の輪を表示する程度にとどめる。

## 10. 画質の自動調整

iPad Safariにおける50fps以上の安定した描画を目標とする。

起動時は中画質から開始し、初期フレームと実行中の描画速度を測定して、3段階の画質を自動調整する。

| 項目 | high | mid | low |
|---|---:|---:|---:|
| ピクセル比の上限 | 1.75 | 1.25 | 1.0 |
| リアルタイム影 | 必要な場合のみ | 原則なし | なし |
| Bloom | 有効 | 低解像度 | 無効 |
| 光の粒の最大数 | 1,200 | 600 | 250 |
| 気泡の最大数 | 180 | 90 | 40 |
| 月光の筋 | 8本 | 4本 | 2本 |
| 水面シェーダー | 高品質 | 標準 | 簡略化 |
| 珊瑚の描画密度 | 100％ | 65％ | 35％ |

FPSは約2〜3秒の移動平均によって評価する。

48fps未満が約3秒続く場合は1段階下げ、57fps以上が約10秒続く場合は1段階上げる。切り替え後にはクールダウン時間を設け、頻繁な画質変更を防ぐ。

バックグラウンド移行中や復帰直後のFPSは判定から除外する。

光の粒は`Points`や`InstancedMesh`、オブジェクトプールを利用して描画する。毎フレーム大量のオブジェクトを生成・破棄しない。

イルカの形状と泳ぎ、操作対象の発光、光の輪、クライマックスの主要演出はlowでも維持する。

Bloomを無効化した場合は、加算合成やシェーダーによる簡易発光で補う。

URLの`?q=low`、`?q=mid`、`?q=high`によって画質を強制指定できるようにする。強制指定時は自動画質変更を停止する。

画質調整によって遊びの内容、操作回数、成功判定を変えてはならない。

## 11. 技術構成と実装上の必須事項

### 11.1. ファイル構成

実装先は以下の1ファイルとする。

`site/games/d06/index.html`

HTML、CSS、JavaScriptをこのファイルにまとめる。

Three.jsはリポジトリに同梱されている以下のものを使用する。

- `site/vendor/three/build/three.module.min.js`
- `site/vendor/three/examples/jsm/`

importmapにより、`three`を`../../vendor/three/build/three.module.min.js`へ、`three/addons/`を`../../vendor/three/examples/jsm/`へ対応付ける。

CDNおよび外部サービスへの依存は禁止する。

`<head>`内には、必ず以下のメタタグを設置する。

`<meta name="robots" content="noindex">`

`</body>`の直前には、必ず以下を設置する。

`<script src="../../gf-playlog.js" defer></script>`

### 11.2. 状態管理

以下の状態を明確に区別して管理する。

`START → WAIT_INPUT → GUIDING → FORM_RING → PASS_RING → WAIT_INPUT`

各段階の規定回数に達した場合には`STAGE_TRANSITION`へ、最終段階を達成した場合には`CLIMAX → AFTERGLOW → REPLAY_WAIT`へ移行する。

描画、入力、カメラ、イルカのアニメーション、効果音、進行状態を適切に分離する。

フレームレートによって遊泳速度や演出時間が変化しないよう、経過時間に基づいて制御する。

再プレイ時に、イルカ、パーティクル、音源、イベントリスナーなどが重複して増加しないようにする。

### 11.3. テスト用インターフェース

- `window.__ready`：初期値はfalse。描画、入力、状態管理の準備が完了し、遊べる状態になった時点でtrueとする。
- `window.__errors`：初期値は空配列。未処理のエラー、Promiseの拒否、重大な初期化エラーを記録する。
- `?autotest`：開始から18回の操作、全段階の移行、クライマックス、余韻まで自動進行するテストモードとする。

自動プレイは、通常の入力処理と共通の成功処理を通るようにする。単に進行回数を書き換えて終了させるだけのテストは禁止する。

自動プレイ時にブラウザの音声自動再生制限が働いた場合は、無音でテストを継続できるようにする。

### 11.4. 禁止事項

気持ち悪い生き物、おばけ、怪物、シュールな造形、不穏な世界、人物、お姫様、既存のキャラクター・作品・ブランドを想起させる固有の意匠を登場させない。

別紙の禁止語については、ひらがな・カタカナ表記も含め、コード、コメント、実装時の文書に使用しないこと。

## 12. 完成の確認項目

実装後は、実装者自身が以下のすべてを確認すること。

### ゲーム体験

- [ ] 最初の画面で、触るべきイルカが説明なしで分かる。
- [ ] 開始後数秒以内に最初の達成感を得られる。
- [ ] 指を動かすとイルカが即座に反応する。
- [ ] イルカの合流によって光の輪が完成する。
- [ ] 輪をくぐることで海中の光景が変化する。
- [ ] 全3段階で景色、光、音、群れの動きが発展する。
- [ ] 最後の渦、水面突破、満月の演出が十分に壮大である。
- [ ] 何もしなくても、次に触るべき対象が自然に合図する。
- [ ] 操作を外しても不利益が生じない。
- [ ] 余韻の後、再プレイできる。

### グラフィックスとカメラ

- [ ] イルカの形状、皮膚、尾びれの動きが写実的である。
- [ ] 水中の奥行き、気泡、水面反射が自然に見える。
- [ ] 夜の海でも主要対象が明瞭に見える。
- [ ] 操作対象が画面中央に配置される。
- [ ] 完成した光の輪が見切れていない。
- [ ] クライマックスの満月が画面中央に配置される。
- [ ] 急激な回転、激しい点滅、画面の振動がない。
- [ ] 文字や数字がゲーム画面に表示されない。

### 技術と端末対応

- [ ] 768×1024、1024×768 CSS px相当で正常に動作する。
- [ ] 390×844 CSS px相当の縦画面でも正常に動作する。
- [ ] PCのマウスでも遊べる。
- [ ] 複数の指で触れても動作が破綻しない。
- [ ] 画面回転後も目標が適切に収まる。
- [ ] コンソールエラーがなく、`window.__errors`が空である。
- [ ] `window.__ready`が正しくtrueになる。
- [ ] `?autotest`でクライマックスまで到達する。
- [ ] 3段階の画質指定と自動画質調整が機能する。
- [ ] iPad実機で50fps以上を目標とした動作確認を行う。
- [ ] 外部アセットやCDNに依存していない。
- [ ] 連続して再プレイしても負荷が増大しない。

各種数値は実装前の設計上の初期値であり、実機で検証済みの値ではない。実機確認ができない場合は、ブラウザで確認できた範囲と未確認事項を区別して報告すること。

## 13. 実装時の優先順位

実装の際は、次の順序で品質を優先すること。

1. イルカの写実的な造形と生命感のある泳ぎ。
2. 指1本の操作と、操作によって生じる確かな変化。
3. 目標が常に中央にある、分かりやすい画面構成。
4. 光の輪の完成と通過の気持ちよさ。
5. 海全体が段階的に変化する高揚感。
6. 水面を突き抜けるクライマックスの爽快感。
7. 安定したフレームレートと端末対応。

処理負荷のために何かを削減する必要がある場合は、背景の装飾から削減する。イルカの造形、泳ぎ、入力への反応、主要な光の演出は妥協しない。

最終的に目指すのは、子どもが自分の指でイルカたちを集め、夢のような海を作り上げ、満月へ向かって一緒に泳いだという記憶が残るゲームである。
