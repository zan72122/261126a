# D03 実装指示文：動物が集まる平原の、輝く空

## 0. 実装の目的と基本方針

5歳の女の子が、キリンの背に乗って広大なサバンナを進み、野生動物を次々と呼び集め、最後に丘の頂上で壮大な光の祝福を体験する、写実3Dウェブゲームを実装してください。

単なる風景鑑賞や動物の観察ではなく、「自分が動物を呼ぶことで、仲間が増え、世界が変わっていく」という能動的な体験を中心に据えてください。

最も重要なのは、次の3点です。

- 指1本の小さな操作によって、目の前で大きな変化が起きる。
- 動物が集まるたびに、次はもっとすてきなことが起こりそうだと感じられる。
- 最後の光景が、それまでの積み重ねに対する十分な報酬になっている。

ゲームの対象年齢は5歳。文字を読む能力、ゲーム経験、正確な指の操作を一切要求しないこと。

## 1. ゲームの狙い

- **夢×写実：** 本物の野生動物と見分けがつかないような毛並み、皮膚、歩行、砂ぼこり、夕日の逆光の中で、動物が呼びかけに応えて集まり、空までもが呼応する幻想的な世界を体験する。
- **高揚感：** 最初は一頭のキリンだけだった旅が、次第に大きな動物の行進へと成長し、期待感とともに丘の頂上へ向かう。
- **爽快感：** 全員が集まった瞬間、空いっぱいに巨大な光の輪が開き、それまで蓄積してきた光と音が一気に解放される。

写実性は世界に存在する物体の質感と動きに持たせ、幻想性は光、色、音、自然現象の変化に持たせること。この二つを混同しない。

## 2. 絵から借りる光と色

参考となる絵から借りる要素は「緑豊かなアフリカの平原」「無数の動物が集まる光景」「期待感に満ちた輝く空」の3つに限定する。

既存作品の構図、動物の配置、特徴的な岩山、キャラクターデザイン、絵柄は再現しない。独自の地形、独自の光学演出、独自のカメラ構成を作ること。

世界全体は、自然写真のような写実性と、魔法を題材にした長編アニメーション映画のクライマックスに見られるような光の演出を融合させる。

### 2.1 時間帯とカラーパレット

ゲームの進行に伴い、夕方の空が金色、桃色、紫色へと変化していく。ただし、時間経過によって視認性が低下することは禁止する。

| 項目 | 第1段階：出発 | 第2段階：行進 | 第3段階：丘への道 | クライマックス |
|---|---|---|---|---|
| 天頂の空 | `#69BCE8` | `#81B5E9` | `#9CA4E9` | `#B1A7F1` |
| 地平線 | `#FFE2A2` | `#FFCE82` | `#FFB7AD` | `#FFF1B8` |
| 雲の光彩 | `#FFF1CF` | `#FFD39B` | `#FFD0DB` | `#FFF7E0` |
| 遠景の霞 | `#D6D9BA` | `#E6CCA2` | `#E8B8B4` | `#F6D9C4` |
| 草原 | `#829B45` | `#8DA34B` | `#98A650` | `#ACB969` |
| 太陽光の色温度 | 約4800K | 約4100K | 約3400K | 約3800K |
| 太陽の仰角 | 22度 | 16度 | 10度 | 7度 |

色は段階が変わるたびに瞬時に切り替えず、4〜8秒かけて連続的に補間する。動物を1組呼ぶごとにも、現在の段階の色から次の段階の色へ少しずつ移行させる。

### 2.2 ライティング

Three.jsのライティングは以下を初期値とし、実際の描画結果に合わせて調整する。

- `DirectionalLight`：太陽光。intensity 2.0〜3.2。
- `HemisphereLight`：空と地面からの環境光。intensity 1.3〜2.0。
- 補助光：動物の影側に空の反射光を与える。intensity 0.3〜0.6。
- 太陽は進行方向の斜め前方、方位角30〜45度程度に配置する。
- 動物の耳、首、背中、尾の輪郭に金色のリムライトを作る。
- `ACESFilmicToneMapping` を使用し、exposureは1.0〜1.2を目安とする。
- 出力色空間は `SRGBColorSpace` とする。

逆光によって動物が黒いシルエットになることを避ける。ゾウの皮膚、シマウマの縞、キリンの模様が、全段階で明瞭に識別できるようにする。

### 2.3 大気と発光

世界の単位は1 unit = 1mを基本とする。

- `Fog` のnearは45〜70m、farは180〜260m程度。
- 遠景ほど彩度とコントラストを下げ、空気遠近法を表現する。
- 光る花粉は白金色 `#FFF4BC` を基本に、桃色 `#FFD1DD` と淡い青色 `#C9F3FF` を混ぜる。
- 通常時のブルームはstrength 0.2〜0.35、radius 0.4〜0.6、threshold 0.85〜1.0。
- クライマックスではstrengthを0.65〜0.9まで一時的に増加させる。
- ブルームは発光体を中心に適用し、動物の質感を損なわない。

光は画面全体を白く塗りつぶすものではなく、空気中に実際に存在するような奥行きのある現象として表現する。

高速点滅、強いフラッシュ、過剰なレンズフレアは禁止する。

## 3. 舞台と登場するもの

### 3.1 サバンナの地形

開放的で起伏のある草原をプロシージャル生成する。広さは約400m四方を初期値とする。

地形には複数の周波数のノイズを重ね、なだらかな丘、浅い谷、土の小道、岩場、背の低い草むらを作る。

進行経路はあらかじめスプラインで定義する。開始地点は低い平原とし、最終地点には草原全体と広大な空を見渡せる丘を配置する。

- 草丈は0.15〜0.65m程度。
- 草は `InstancedMesh` を使用し、風によって穂先が揺れる。
- 土の小道には砂、細かな石、踏み固められた部分の色の違いを持たせる。
- アカシアに似た樹木を疎らに配置し、枝の分岐と樹冠を生成する。
- 遠景の丘は低ポリゴン化し、霞によって距離感を作る。

画面内の草木の量を増やすこと自体を目的としない。動物の姿と次の操作対象が見えやすいことを優先する。

### 3.2 水辺

進行経路の側方に、浅い水場を1〜2か所設ける。水場を通過する操作や課題は追加しない。

水面は平面メッシュと手続き的なシェーダーで表現する。

- 2〜3方向の正弦波による細かな波紋。
- 法線の時間変化による夕日の反射。
- フレネル効果による視線角度に応じた反射率の変化。
- 水面の色は `#769FA6`、浅瀬は `#A8C2AF` を基準とする。
- 水面に金色の光が細長く揺れるようにする。

リアルタイム反射のためにシーン全体を毎フレーム再描画する必要はない。空の色と太陽の位置を利用した近似反射で十分な質感を目指す。

### 3.3 空と雲

空は巨大なドームまたはシェーダーベースの背景として生成する。

天頂と地平線のグラデーションに加え、太陽の周辺に大気散乱を近似した光彩を作る。雲はノイズを利用した半透明の層、または軽量なメッシュで生成する。

雲の太陽側は金色に輝き、影側には桃色や紫色が現れる。

クライマックスでは、雲の切れ間から複数の光の筋が広がるようにする。重いボリュームレンダリングは必須としない。

### 3.4 主役となるキリン

プレイヤーはキリンの背に乗っているという設定とする。ただし、プレイヤー自身の身体、手、顔、衣服は描画しない。

キリンはゲーム全体を通して行進の先頭にいる。

- 全高4.5〜5m程度。
- 長い首、細長い四肢、特徴的な頭部と角状突起を再現する。
- 首、胴体、脚を滑らかにつながった立体として生成する。
- キリン特有の不規則な多角形模様をVoronoiノイズ等で生成する。
- 耳の動き、瞬き、尾の揺れ、首のわずかな上下動を実装する。
- 四肢の接地を考慮した歩行アニメーションを実装する。

動物を球体と円柱の組み合わせに見せないこと。断面形状の補間、頂点法線の調整、関節の変形によって、解剖学的に自然な輪郭を作る。

鞍や装飾品は不要。動物本来の美しさを優先する。

### 3.5 仲間になる動物

登場する動物はゾウ、シマウマ、鳥の群れの3種類とする。

| 動物 | 写実性の重点 | 仲間になる際の動き |
|---|---|---|
| ゾウ | 大きな耳、鼻の関節、皮膚の皺、重量感 | 耳を動かし、鼻を持ち上げ、力強く近づく |
| シマウマ | 体表の縞模様、たてがみ、蹄、筋肉 | 軽快に駆け寄り、自然に減速する |
| 鳥 | 翼の形、羽毛の色、羽ばたきと滑空 | 草地から飛び立ち、行進の上空に合流する |

動物の表情を人間風に誇張しない。大きすぎる目、笑顔、人間のような手振りなどは使用しない。

ゾウの鼻は複数の関節を持つ曲線状メッシュ、シマウマの縞は体表に沿った手続き的なパターン、鳥の翼は複数の羽根を持つ関節構造で生成する。

毛並みや皮膚の質感は、PBRマテリアル、手続き的なテクスチャ、微細な法線のゆらぎを用いる。動物1頭ごとに個別の毛を大量生成する必要はない。

roughnessの目安は、皮膚0.75〜0.95、毛並み0.65〜0.85、目0.15〜0.25とする。

動物同士で体格、模様、歩行周期、耳や尾の動きに少しずつ個体差を持たせる。

### 3.6 行進の管理

仲間になった動物は消滅させず、キリンの後方に合流させる。

行進の経路に沿って動物ごとの目標位置を管理し、前後左右に適切な間隔を取らせる。全員が完全に同じタイミングで歩くことを避ける。

ゾウは重厚に、シマウマは軽快に、鳥は自由に滑空する。種類ごとの動きの違いが、行進そのものの魅力になるようにする。

重い汎用物理エンジンは使用せず、経路追従、速度補間、地面への接地補正、簡易的な間隔調整で実現する。

## 4. 指1本のゲームループ

基本ループは「動物を見つける→光を触る→動物が駆け寄る→世界が輝く」とする。

### 4.1 開始画面

読み込み完了時には、すでにサバンナとキリンが画面に描画されている状態にする。

キリンは穏やかに首を動かし、背の上方に小さな金色の光が浮かんでいる。

この光が開始ボタンを兼ねる。文字、再生マーク、矢印、説明画面は不要。

光またはキリンをタップすると、短い澄んだ音が鳴り、カメラが移動し、キリンが歩き始める。

### 4.2 1回の基本ループ

**課題：動物を見つける**

進行方向の少し先に、まだ仲間になっていない動物がいる。

動物は草むらの近くで立ち止まり、耳や首を動かしてこちらの存在に気づく。頭上に直径0.3〜0.6m程度の金色の発光体が現れる。

光は動物の身体に追従し、約1.5秒周期で強弱を繰り返す。

次に触る対象は必ず1つに限定する。

**取り組み：光をタップする**

発光体または対象の動物本体をタップすると、呼びかけが成立する。

入力から100ms以内を目標に、光が弾け、短い成功音が鳴る。

タップした光は数本の光の粒となって動物の周囲に広がる。動物は耳を動かす、首を持ち上げる、翼を広げるなど、種類に応じた反応を示す。

**結果：動物が行進に加わる**

動物は約3〜5秒かけて自然に近づき、キリンの後方へ合流する。

シマウマの駆け寄る速度は4〜6m/s、ゾウは2.5〜3.5m/sを目安とする。合流直前に徐々に減速させる。

足元から小さな砂ぼこりが立ち、その直後に金色の花粉が地面から舞い上がる。

花粉は動物の移動に沿って波状に広がり、一部が上空まで上昇する。それに呼応して空と雲の色が少し変化する。

成功のたびに、次の4つの結果が必ず目で確認できるようにする。

- 動物が自分の操作に反応した。
- 動物が実際に移動した。
- 行進の仲間が増えた。
- 草原と空の光景が変化した。

### 4.3 何もしなかった場合

2.5秒間操作がなければ、発光体の光彩を少し強める。

さらに数秒間操作がなければ、対象動物が顔を上げ、発光体がゆっくり上下する。地面にも同系色の光が短時間広がる。

文字、矢印、手のアイコンは使用しない。

プレイヤーが操作しない限り、対象動物はその場から立ち去らない。進行速度を落とし、必要に応じてキリンを穏やかに待機させる。

### 4.4 外れた場所を触った場合

何も悪いことは起こらない。

失敗音、警告、振動、減点、時間制限、仲間の消失は一切実装しない。

対象の光はそのまま残り、数秒後に再び操作を促す。

## 5. 盛り上がりの設計

全3段階、各6回、合計18回の呼びかけを基本構成として採用する。鳥の場合は1回の操作で4〜5羽が仲間になる。

通常のプレイ時間は約3〜5分とする。

| 段階 | 新しく集まる仲間 | 景色・演出 |
|---|---|---|
| 第1段階 | シマウマ3頭、ゾウ1頭、鳥2群 | 青空と緑の草原、金色の花粉 |
| 第2段階 | シマウマ2頭、ゾウ2頭、鳥2群 | 金色の平原、長くなる行進 |
| 第3段階 | シマウマ1頭、ゾウ3頭、鳥2群 | 丘への上り道、桃色と金色の空 |
| 最終演出 | 全員集合 | 巨大な光の輪と光の解放 |

### 5.1 第1段階：小さな旅の始まり

キリンの歩行速度は1.3〜1.6m/s程度。

最初の動物は近い場所に配置し、ゲームの仕組みを一度の操作で理解できるようにする。

成功時の光は局所的なものとし、草むらの周辺から金色の花粉が舞う。鳥が加わると、空にも動きが生まれる。

6回目の成功後、キリンの進行方向に広大な平原が開ける。

### 5.2 第2段階：動物たちの大行進

キリンの速度を1.6〜1.9m/s程度まで増加させる。

動物が増えることで、蹄の音、草の揺れ、砂ぼこり、鳥の羽ばたきが重なっていく。

各成功時には花粉が地面を円状に広がり、近くの草木にも金色の反射が現れる。

行進の存在感を強めるため、合流後にカメラをわずかに引き、これまでに集まった動物たちを見せる短い時間を設ける。

### 5.3 第3段階：輝く丘への道

キリンの速度は1.8〜2.2m/s程度を上限とする。

丘の頂上が見え始め、空には桃色と金色の雲が増える。

成功時の光は草原だけでなく、空の雲にも伝わるようにする。花粉が上昇すると、その延長上に光の筋が現れる。

最後の動物が合流したら、キリンと仲間たちは自然に丘の頂上へ向かう。

### 5.4 時間配分

1回のループは、操作から合流、光の変化、次の対象の出現までを含めて8〜11秒程度とする。

次の操作ができない時間にも、動物の移動や景色の変化など、意味のある出来事を継続させる。単なる待ち時間を作らない。

段階間の演出は各4〜6秒程度。クライマックスと余韻を合わせて20〜30秒程度とする。

プレイヤーの操作が遅い場合は、5分を超えても構わない。時間による強制終了は禁止する。

## 6. クライマックス：空いっぱいに開く光の輪

本ゲームで最も重要な演出である。

通常の成功演出を単純に拡大するだけではなく、以下の順序で段階的に期待を高め、最後に解放する。

**0〜3秒：全員集合**

キリンが丘の頂上に到達する。動物たちは後方と側方に集まり、自然に歩みを止める。

鳥は上空を大きく旋回する。足音が次第に静まり、風と鳥の音が残る。

**3〜6秒：光の蓄積**

全ての動物の足元から金色の花粉が舞い上がる。

花粉は複数の流れを作り、空の中央へ集まっていく。

雲の切れ間に小さな金色の光が生まれ、ゆっくりと強くなる。

**6〜10秒：光の解放**

空の中央に巨大な光の輪が出現し、滑らかに広がる。

光の輪は複数の半透明リング、細かな発光粒子、大気中の光の筋によって立体的に構成する。

主輪は金白色 `#FFF2AE`、内側は `#FFFBE8`、外縁は `#FFD4C9` を基準とする。

輪の拡大に合わせて、雲、草原、動物の背中に金色の光が伝播する。

WebAudioによる豊かな和音と鐘の音を重ね、これまでで最大の達成感を作る。

リングの全体像は必ず画面内に収める。輪郭を画面外に見切れさせない。

**10〜25秒：静かな余韻**

光の輪は空に残り、細かな粒子がゆっくり降り注ぐ。

キリンが首を持ち上げ、ゾウが鼻を伸ばし、鳥が光の周辺を滑空する。

音楽は徐々に静まり、穏やかな環境音に戻る。

余韻の後、キリンの近くに小さな金色の光を出現させる。この光に触れると最初から遊べる状態に戻す。触れなければ、そのまま動物と空の光景を楽しめるようにする。

強制的な画面切り替えは行わない。

## 7. カメラと画面構成

### 7.1 基本カメラ

カメラはキリンの斜め後方上部に置く。

- キリンとの距離：8〜14m程度。
- 地面からの高さ：6〜10m程度。
- 横方向の角度：進行軸から15〜25度程度。
- 垂直FOV：45〜55度程度。

キリンの頭部、首、背中の一部を画面内に残し、キリンと一緒に旅をしている感覚を作る。

キリンの歩行に合わせてカメラを直接上下させない。カメラのロール角は原則0度とし、地平線の傾斜を防ぐ。

### 7.2 操作対象を常に中央に置く

現在操作できる発光体をカメラの注視点とし、画面中央に配置する。

発光体の投影座標は、画面幅・高さともに中央から原則5%以内に収める。対象動物の身体と、行進の先頭となるキリンの頭部・首が同時に画面内に入るようにする。

これを実現するため、カメラ制御だけでなく、対象動物の出現位置も設計する。

進行方向から大きく外れた場所には操作対象を配置しない。カメラの視野から外れている動物を次の対象に指定することは禁止する。

対象の切り替え時は、カメラが次の対象へ滑らかに移動し、中央に収まった時点で発光体を出現させる。

### 7.3 縦横画面への対応

固定のカメラ距離だけで実装しない。

縦向き・横向きそれぞれのアスペクト比から、キリン、操作対象、クライマックスの光の輪など、必要な物体の投影範囲を計算する。

画面の四辺に6〜10%程度の余白を確保できるよう、カメラの距離と高さを自動調整する。

縦向きでは横方向の視野が狭くなるため、必要に応じてカメラを引くとともに、動物の隊列の幅を抑える。

光の輪の演出では、輪の中心と外周がすべて収まるよう、専用のカメラ位置を計算する。

### 7.4 カメラの動き

位置と注視点を時間ベースの補間で制御する。追従時定数は0.4〜0.9秒程度を目安とする。

急旋回、急接近、急なズーム、手持ちカメラ風の揺れは禁止する。

カメラを自由に回転させる操作も実装しない。

## 8. 操作と入力

iPad Safari、iPhone Safari、PCブラウザで動作すること。

入力処理はPointer Eventsに統一する。

- `pointerdown`、`pointerup`、`pointercancel` を適切に処理する。
- 最初の有効なポインターのみを追跡する。
- 2本目以降の指は無視する。
- Raycasterまたはスクリーン座標による当たり判定を使用する。
- 発光体だけでなく、対象動物の身体全体を有効なタップ領域にする。
- 最小タップ領域は直径72 CSS px程度を目標とする。
- 見た目より1.5〜2倍程度広い当たり判定を設ける。
- 同じ対象への連打によって動物が重複生成されないようにする。

ゲーム領域には `touch-action: none`、`user-select: none`、`overscroll-behavior: none` などを適用する。

Safari固有のジェスチャーイベントも必要に応じて処理し、ピンチ、ダブルタップによるズーム、スクロール、長押しメニュー、テキスト選択を抑制する。

画面の回転後もゲームの進行状態を維持し、正しい当たり判定を再計算する。

## 9. 音の設計

音はすべてWebAudioによって手続き的に合成する。外部音声ファイルは使用しない。

最初のユーザー操作で `AudioContext` を生成またはresumeする。

### 9.1 環境音

- フィルターを通したノイズによる草原の風。
- 短い減衰音による草の擦れる音。
- 低周波成分を含むゾウの足音。
- 短く硬質なシマウマの蹄の音。
- 周波数変調による小鳥のさえずり。
- 羽ばたきに同期した微細な風切り音。

動物の種類と動きに応じて発音し、同じ音を機械的な間隔で繰り返さない。

### 9.2 成功音

長調のペンタトニックスケールを基本に、成功音の音程と和音を段階的に豊かにする。

| 段階 | 音の構成例 |
|---|---|
| 第1段階 | C5、E5、G5を中心とした短い音 |
| 第2段階 | C5、E5、G5、A5による小さなアルペジオ |
| 第3段階 | C5、E5、G5、C6に倍音を追加 |
| クライマックス | C3〜C6に広がる長調の和音と鐘の残響 |

オシレーター、GainNode、BiquadFilterNode、短いディレイなどを組み合わせる。

BGMは旋律を強く主張させず、風景を支える持続音を中心とする。

マスターゲインは0.2〜0.35程度を初期値とし、音の重なりによるクリッピングを防ぐ。突然の大音量や威圧的な動物の鳴き声は禁止する。

## 10. 画面の文字と表現上の禁止事項

ゲーム画面には以下を一切表示しない。

- タイトル、説明文、会話文。
- 数字、スコア、カウントダウン。
- 進捗バー、ステージ番号。
- ボタンのラベル。
- 矢印、手のアイコン。
- FPSなどのデバッグ情報。
- 人物、既存キャラクター、ブランドを想起させる造形。

不穏な生物、怪物、おばけ、恐怖演出、捕食、襲撃、転落、動物が傷つく描写は禁止する。

別紙の禁止語については、実装コード、変数名、コメント、文字列、デバッグメッセージを含め、使用しないこと。表記を変更した使用も禁止する。

## 11. 画質の自動調整とパフォーマンス

2020年モデルのiPad ProのSafariで50fps以上を目標とする。

写実性のために処理負荷を無制限に増やしてはならない。安定したフレームレートを優先する。

### 11.1 画質プリセット

| 項目 | high | mid | low |
|---|---:|---:|---:|
| ピクセル比上限 | 1.75 | 1.25 | 1.0 |
| シャドウマップ | 2048 | 1024 | 512または簡易接地影 |
| 草のインスタンス数 | 18000 | 8000 | 3000 |
| 同時発光粒子数 | 1000 | 450 | 160 |
| ブルーム | 通常 | 低解像度 | 簡易発光表現 |
| 遠景の動物 | 中詳細 | 低詳細 | 低詳細 |
| 水面 | 詳細シェーダー | 簡略シェーダー | 近似反射 |

数値は初期設定の目安であり、実測に基づいて変更してよい。

lowでも動物の種類、操作対象、動物が集まる演出、巨大な光の輪は削除しない。

### 11.2 自動判定

起動時はmidを基本とし、最初の数秒間の描画負荷から適切な品質を選択する。

実行中は `requestAnimationFrame` の時間差を利用してFPSの移動平均を測定する。

- 50fps未満が約3秒継続したら1段階下げる。
- 58fps以上が約10秒継続したら1段階上げることを検討する。
- 品質切り替え後は10〜15秒程度のクールダウンを設ける。

タブが非表示の時間、画面回転直後、初期ロード中はFPS評価の対象外とする。

`?q=low`、`?q=mid`、`?q=high` が指定されている場合は、指定された画質を固定し、自動変更しない。

### 11.3 最適化

草、岩、花粉、鳥など、共有可能な形状にはインスタンシングを活用する。

動物のジオメトリとマテリアルを可能な範囲で共有し、距離に応じてLODを切り替える。

パーティクルにはオブジェクトプールを使用する。毎フレームの大量の配列生成、ジオメトリ生成、マテリアル生成は禁止する。

地形、テクスチャ、動物の基本形状は初期化時に生成する。

リプレイを繰り返しても、GPUメモリ、イベントリスナー、AudioNode、描画オブジェクトが増え続けないようにする。

## 12. 技術構成

### 12.1 ファイルと依存関係

ゲーム本体は以下の1ファイルにまとめる。

`site/games/d03/index.html`

HTML、CSS、JavaScriptを同一ファイルに記述する。

Three.jsはリポジトリに同梱されているものを使用する。

- `site/vendor/three/build/three.module.min.js`
- `site/vendor/three/examples/jsm/`

importmapにおいて、`three` を `../../vendor/three/build/three.module.min.js` に、`three/addons/` を `../../vendor/three/examples/jsm/` に対応させる。

CDN、外部画像、外部3Dモデル、外部フォント、外部音声、外部APIは禁止する。

`<head>` 内に以下を必ず含める。

`<meta name="robots" content="noindex">`

`</body>` の直前には以下を必ず配置する。

`<script src="../../gf-playlog.js" defer></script>`

既存のThree.jsと共通ログスクリプトを除き、新規の依存ファイルは作らない。

### 12.2 状態管理

ゲームの進行は明示的なステートマシンで管理する。

- `INIT`：初期化。
- `TITLE_IDLE`：開始操作待ち。
- `TRAVEL`：移動。
- `TARGET_READY`：呼びかけ対象の操作待ち。
- `ANIMAL_JOIN`：動物の合流演出。
- `STAGE_TRANSITION`：段階の移行。
- `CLIMAX`：最終演出。
- `AFTERGLOW`：余韻と再プレイ待ち。

対象動物の識別子、現在の段階、呼びかけ済みの回数、合流済みの動物一覧、進行経路上の位置を独立して管理する。

アニメーションはフレーム数ではなく、経過時間を基準として更新する。

### 12.3 準備完了とエラー管理

`window.__ready` を初期状態でfalseとする。

シーン、カメラ、動物、操作処理、初期描画が正常に準備できた段階でtrueにする。音声のアンロックは準備完了条件に含めない。

`window.__errors` は空配列として初期化する。

未処理例外、Promise rejection、WebGLの初期化エラーなどを記録できるようにする。既存の共通ログ機構との競合を避ける。

### 12.4 自動プレイ

`?autotest` が指定された場合、自動で開始操作から全18回の呼びかけ、全段階、クライマックス、余韻まで進行させる。

自動プレイ専用に結果だけを書き換えることは禁止する。

通常プレイと同一の成功処理、合流処理、段階移行、光の演出を通過させる。演出時間はテスト用に短縮してもよい。

ブラウザの自動再生制限によって音声を開始できない場合でも、自動プレイが停止しないようにする。

画面に文字やテスト用UIを表示することなく、開発者ツールからテスト結果を確認できるようにする。

## 13. 実装時の優先順位

実装は以下の優先順位で進める。

1. キリン、ゾウ、シマウマ、鳥の写実的な造形と自然な動き。
2. 光を触ると動物が駆け寄ってくる、因果関係の明確な遊び。
3. 操作対象を常に画面中央に置くカメラ。
4. 仲間が増えることによる行進の成長。
5. 夕方の草原、雲、逆光、空の色の変化。
6. クライマックスにおける光の輪と音の解放。
7. 描画負荷の最適化と細部の仕上げ。

特に動物の造形について、簡易的な仮モデルをそのまま完成品としないこと。

一方、背景の細かな草の本数や水面反射の精密さは、フレームレートを犠牲にしてまで追求する必要はない。

## 14. 完成の確認項目

実装者は完成報告前に、以下の全項目を自ら確認すること。

### ゲーム性

- [ ] 文字を読まなくても開始方法が理解できる。
- [ ] 開始後、次に触る対象が自然に分かる。
- [ ] 1回のタップで動物が反応し、行進に加わる。

- [ ] 外れた場所を触っても不利益がない。
- [ ] クライマックスが通常の成功演出より十分に壮大である。
- [ ] 余韻から再プレイできる。

- [ ] 動物が玩具や単純な幾何学立体に見えない。
- [ ] 動物の歩行時に不自然な滑りや地面への埋没がない。
- [ ] キリン、ゾウ、シマウマ、鳥が容易に識別できる。
- [ ] 空の色が段階的かつ連続的に変化する。
- [ ] 夕方の場面でも動物と地形が明瞭に見える。
- [ ] 操作対象が常に画面中央に配置される。
- [ ] キリンの頭部と首が見切れない。
- [ ] クライマックスの光の輪全体が画面内に収まる。
- [ ] 急激なカメラ移動や画面の揺れがない。

### 技術品質

- [ ] コンソールエラーがない。
- [ ] `window.__ready === true` になる。
- [ ] `window.__errors` が空配列である。
- [ ] `?autotest` で最後まで進行できる。
- [ ] 3種類の画質指定が正常に機能する。
- [ ] 自動画質調整が機能する。
- [ ] iPad相当の1194×834および834×1194 CSS pxの画面で正常に動作する。
- [ ] iPhone相当の390×844 CSS pxでも正常に動作する。
- [ ] タッチとマウスの双方で操作できる。
- [ ] 複数の指によって操作や画面表示が壊れない。
- [ ] リプレイを3回以上繰り返しても正常に動作する。
- [ ] ゲーム画面に文字や数字が表示されない。
- [ ] 外部リソースへのネットワークアクセスがない。
- [ ] 指定のファイルパス、metaタグ、共通ログスクリプトを満たす。
- [ ] 可能な限り50fps以上を維持する。

最終的な完成基準は、写実的な動物が存在することだけではない。子どもが自分の指で仲間を集め、世界が次第に輝き、最後に空いっぱいの光を生み出したと感じられることである。
