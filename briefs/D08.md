# D08 実装指示文：月面から青い地球へ跳ぶ

## 0. 実装の目的と最優先事項

5歳の女の子が、文字を読むことなく、指1本で直感的に遊べる、写真のような写実性を持つ3D Webゲームを実装してください。

舞台は、青く輝く地球を空に望む月面です。小さな宇宙服を着た子どもが白いウサギと一緒に、クレーターのふちから次々と大きくジャンプします。ジャンプするたびに地球が近づき、最後には地球の青い光の中へ飛び込む、現実には体験できない宇宙旅行を描きます。

本作品は宇宙の景色を鑑賞するだけのコンテンツではありません。自分の指で跳ぶきっかけを作り、跳ぶたびに世界が変化し、自分の力で地球に近づいていると感じられるゲームにしてください。

実装の優先順位は以下のとおりです。

1. 説明なしで次に何をすればよいか分かること。
2. ジャンプそのものが何度でも繰り返したくなるほど気持ちよいこと。
3. 地球に近づいていることが視覚的に伝わること。
4. 写実的な月面と幻想的な宇宙の光が共存すること。
5. 最後のジャンプが、それまでのすべてのジャンプを上回る感動的な体験になること。
6. iPad Safariで安定して滑らかに動作すること。

## 1. ゲームの狙い

- **夢×写実：** 月面の細かな砂粒、クレーターの陰影、地球の海と雲を写実的に描きながら、低重力のジャンプを繰り返すことで月から地球まで届いてしまう夢の体験を実現する。
- **高揚感：** ジャンプの高さと滞空時間、地球の見かけの大きさ、青い光の輝きが段階的に増し、最後には視界全体が地球の光に包まれる。
- **爽快感：** 地面を蹴った瞬間の心地よい反応から、低重力による長い浮遊、眼下を流れる月面、光の粉が舞う着地までを一連の気持ちよい動きとして表現する。

特に重要なのは「自分が跳んだから、あんなに遠かった地球が近くなった」という因果関係です。時間経過だけで景色を変えず、子どもの操作と世界の変化を必ず結び付けてください。

## 2. 絵から借りる光と色

### 2.1. 美術の方向性

提示されたB17からは、月面から見上げる青い地球、地球から届く光、静かな宇宙の壮大さを借りてください。

B2からは、惑星の浮かぶ宇宙、現実の自然と想像上の風景が溶け合う感覚、青・紫・金色が共存する光の美しさを借りてください。

いずれも作品固有の構図、絵柄、惑星の配置、地形などを再現しないこと。既存のキャラクター、建築物、ブランド要素も使用しないこと。

目指すのは、宇宙探査機が撮影した月面写真のような質感と、劇場用ファンタジー映画のような魔法の光が共存する、独自の写実3D世界です。

### 2.3. 光源と時間帯に相当する演出

月面では地球上のような短時間の昼夜変化は起こさず、太陽の位置をほぼ固定してください。その代わり、地球に近づく各段階に応じて光の比率と色彩を変化させます。

| 項目 | 序盤 | 中盤 | 終盤 | 最終演出 |
|---|---:|---:|---:|---:|
| 太陽光の強さ | 2.6 | 2.5 | 2.3 | 1.8 |
| 太陽光の色温度 | 5400K | 5800K | 6000K | 6200K |
| 半球光の強さ | 0.9 | 1.0 | 1.15 | 1.3 |
| 地球由来の補助光 | 0.25 | 0.55 | 0.95 | 1.6 |
| 地球由来の光の色温度目安 | 8000K | 9000K | 11000K | 12000K |
| ブルーム強度 | 0.25 | 0.4 | 0.65 | 0.95 |

上記はThree.jsで調整を始めるための目安であり、使用するレンダラーやトーンマッピングに応じて最適化してください。色温度は対応するRGB色に変換して指定し、地球からの青色光は物理的な色温度の厳密な再現よりも視覚的な効果を優先します。

太陽光にはDirectionalLightを使用し、地表に対する高度を25〜40度程度に設定します。クレーターの凹凸に長い影を落とし、立体感を強調してください。

地球から届く青色光は、別のDirectionalLightなどを用いて近似します。ジャンプするたびに、宇宙服やウサギの白い毛、月面の石に青色の反射光が増えていくようにします。

### 2.4. 霧・ブルーム・反射

月には大気がほとんど存在しないため、地球のような濃い大気霧は使用しません。

- 月面の遠景のみに、描画負荷と奥行きの調整を兼ねた非常に薄い距離減衰を与える。開始距離160m、終了距離450m程度を目安とする。
- 地球と星には月面用の霧を適用しない。
- 着地時の砂煙は地表付近の局所的なパーティクルで表現する。
- ブルームのthresholdは0.85〜1.1、radiusは0.3〜0.55程度から調整する。
- ブルームによって地球の海や雲の模様が失われないようにする。
- 水面反射は主に地球の海の表現に使用する。太陽の位置と海面の法線に応じて、海の一部に白金色の光沢が現れるようにする。
- ACESFilmicToneMapping、露出1.0〜1.2程度を初期値とし、白飛びと黒つぶれを防ぐ。

月面全体を発光させるのではなく、地球の大気圏、ジャンプ地点、着地の砂粒など、意味のある対象だけを選択的に発光させてください。

## 3. 舞台と登場するもの

### 3.1. 月面の地形

月面はプロシージャル生成による立体的な地形としてください。単純な平面に丸い模様を描くだけの表現は禁止します。

- 高さマップを用いて、緩やかな丘、小さな窪み、大小のクレーターを生成する。
- クレーターは半径3〜25m程度とし、中心の窪み、盛り上がったふち、外側の斜面を連続的な曲面で作る。
- 複数の周波数のノイズを重ね、地形に自然な不均一性を加える。
- 大小の月の石をInstancedMeshで配置する。形状、回転、大きさ、色を少しずつ変える。
- 進行経路には極端な段差や障害物を置かない。
- 前方には複数のクレーターと月の地平線が見え、進む先への期待が生まれるようにする。

月面にはMeshStandardMaterialを基本として使用します。roughnessは0.85〜0.98、metalnessは0〜0.05程度とします。

手続き的に生成したノイズを法線やバンプに利用し、細かな砂粒、岩石のざらつき、色のむらを表現してください。ただしノイズが強すぎて、地面が汚れているように見えないよう注意します。

カメラ近傍は高密度の地形メッシュ、遠景は低密度のメッシュとし、地平線までの広がりを低負荷で実現してください。

### 3.2. 地球

地球は本ゲームで最も重要な視覚的対象です。単色の青い球体や、抽象的な光の球体で代用してはいけません。

以下の層を重ねて生成してください。

**第1層：海と陸地**

- 球体表面にプロシージャルな海と陸地を生成する。
- 大陸のおおよその輪郭を緯度・経度上の形状として定義し、ノイズで海岸線に細部を加える。
- 実際の地球を連想できる大陸配置とする。
- 海には深海の濃い青、沿岸部の青緑、太陽光による反射を加える。
- 陸地には森林、乾燥地帯、山岳地帯、極地の色の違いを設ける。
- 海のroughnessは0.15〜0.3、陸地は0.65〜0.9程度とする。

**第2層：雲**

- 地表の球体より半径を0.5〜1.2％大きくした球体に、手続き的な半透明の雲を生成する。
- 大きな渦を巻く雲、細長い雲帯、小さな雲の集合を混在させる。
- 雲の模様には多層ノイズと座標のゆがみを用いる。
- 地球本体とはわずかに異なる速度で回転させる。

**第3層：大気圏**

- フレネル効果を用いた青色の大気圏シェーダーを実装する。
- 球体の輪郭ほど青白く輝くようにする。
- 太陽側では光を強め、反対側では減衰させる。
- 薄い大気圏と、その外側の広がりを持つ光を分けて表現する。

地球は太陽光を受けた球体として立体感を保ち、海と雲の詳細が常に認識できるようにしてください。

地球が大きくなるのは、本作品の夢の演出です。実際の天体間距離をそのまま再現する必要はありません。地球の方向は大きく変えず、見かけの直径を成功回数に応じて滑らかに増加させます。

### 3.3. 星空と遠方の惑星

星はPointsまたはInstancedMeshを使って生成します。high設定で1000〜2000個程度を目安とします。

白色を中心に、ごく一部を青白色、淡い金色とし、大きさや輝度を変えて自然な星空を作ってください。すべての星を同時に点滅させる表現は避けます。

遠方には小さな惑星を1〜2個配置しても構いません。ただし、地球と見間違えるような色や大きさにはせず、ゲームの目標を分かりにくくしないこと。

地球の手前に星が透けて見える描画上の不具合も防いでください。

### 3.4. 子どもの宇宙服

カメラの手前側に、小さな宇宙服を着た子どもの後ろ姿を配置します。

- 人間の顔や表情は描画しない。
- 白色の宇宙服、関節部分の布のひだ、銀色の接合部、小型の生命維持装置を立体形状で作る。
- ヘルメットは球体を基礎とし、バイザーには宇宙と地球の反射を近似して映す。
- 身体の各部を階層構造とし、膝、腰、腕などを自然に動かす。
- ジャンプ前には膝を曲げ、空中では腕をわずかに広げ、着地時には膝で衝撃を吸収する。

人物の精密な造形に処理能力を費やしすぎず、宇宙服の材質と自然な動きによって写実性を確保してください。

子どもの姿が地球や次のジャンプ地点を覆い隠さないよう、画面下方に小さめに配置します。

### 3.5. 白いウサギ

子どもと一緒に進む白いウサギを1匹登場させます。

月面でウサギが自由に跳ねること自体は夢の要素として扱い、不必要な説明は行いません。

- 実際の白いウサギの体型を参考に、胴体、頭部、後ろ脚、前脚、耳、尾を立体的に作る。
- 毛並みは白色と淡い灰色の濃淡、微細な法線ノイズ、輪郭の光で表現する。
- 全身を大量の毛のメッシュで覆う方法は採用しない。
- 耳の内側は淡い桜色、瞳は自然な黒褐色とする。
- ジャンプ前には身体を縮め、跳躍中は後ろ脚を伸ばし、着地後に耳が少し揺れる。
- 待機中は耳を動かす、鼻を小さく動かす、地球を見上げるなどの仕草を行う。

ウサギは少し先に跳ぶことで、子どもに次の操作を自然に教える案内役にもなります。ただし、プレイヤーより遠くへ行ってしまったり、追いかけなければならない状況を作ったりしないでください。

本作品では乗りものを使用しません。ロケットなどに乗り換える展開も追加せず、低重力によるジャンプを最後まで遊びの中心に据えます。

## 4. 指1本のゲームループ

### 4.1. 開始画面

最初から月面、白いウサギ、子どもの後ろ姿、青い地球が見える状態にします。

すぐ前にあるクレーターのふちの一部が金色に輝き、ウサギがそこを見ながら小さく跳ねます。

タイトル画面、開始ボタン、説明文は設けません。光っているふちを触るとゲームが始まり、そのまま最初のジャンプへ移行します。

### 4.2. 1回のジャンプの流れ

| 状態 | 画面で起きること |
|---|---|
| 課題 | 前方のクレーターのふちが金色に輝く |
| 接近 | 子どもとウサギが自動でふちに近づく |
| 誘導 | ふちに光の波紋が広がり、ウサギが跳ぶ準備をする |
| 操作 | プレイヤーが指1本でタップする |
| 踏み切り | 膝を曲げて地面を蹴り、足元から光の粉が飛び出す |
| 浮遊 | 低重力によって大きく弧を描いて跳ぶ |
| 景色の変化 | 地球が一回り大きくなり、月面が眼下を流れる |
| 着地 | 月の砂が青白い光の粉となって舞い上がる |
| 次の課題 | 前方の新しいクレーターのふちが輝く |

操作後、100ms以内に光や音などの反応を開始してください。子どもが自分の操作でジャンプしたことを即座に理解できる必要があります。

### 4.3. タップの許容と失敗のない設計

原案の「ふちに着いた瞬間にタップする」という気持ちよさは残しますが、正確なタイミングを要求するゲームにはしません。

接近開始後からタップを受け付け、早めに触った場合は入力を予約し、ふちに到達した時点で自動的にジャンプします。

ふちに到達してからタップしなかった場合は、その場で待機します。勝手に落下したり、踏み切りの機会を失ったりすることはありません。

- 光るふちの当たり判定を実際の表示より広く設定する。
- 目標の周辺を触った場合もジャンプを受け付ける。
- 何もない場所を触っても悪い反応を返さない。
- ジャンプ中の連打で二重ジャンプや進行状態の破綻を起こさない。
- 失敗音、減点、制限時間、ゲームオーバーを設けない。

2.5秒間操作がなければ、光るふちの輝度をゆっくり上下させます。5秒間操作がなければ、ウサギが小さな見本のジャンプを行います。

文字、矢印、手のアイコンを使わず、実物の光と動きだけで誘導してください。

### 4.4. ジャンプの気持ちよさ

低重力の感覚は本ゲームの核です。通常のアクションゲームのように短時間で跳んで落ちる動きにしないでください。

月面の重力加速度1.62m/s²を基準とした放物線運動を採用し、演出上必要な場合のみ調整します。

踏み切りには適度な加速を与え、最高点付近では上下方向の速度が自然に小さくなるようにします。浮遊中には、足元を月面が流れ、ウサギの耳が動き、地球の青色光が宇宙服の表面を照らします。

着地は穏やかに減速させ、強い画面振動や衝突感を与えないこと。地面に触れる瞬間には円形に光が広がり、砂粒が弾道を描いて飛び散るようにします。

ジャンプの高さだけでなく、前方へ進む距離、滞空時間、地球の変化量も段階的に増加させてください。

## 5. 盛り上がりの設計

全体を4段階、合計24回のジャンプで構成します。通常のプレイ時間は約3〜5分としますが、操作を急かすことはありません。

段階ごとに異なる操作を要求するのではなく、同じジャンプが次第に壮大になっていく構成としてください。

以下の数値は、原案で指定されていない部分を具体化した初期設計値です。実際の画面と操作感を確認しながら調整してください。

### 5.1. 全体の進行

| 項目 | 第1段階 | 第2段階 | 第3段階 | 第4段階 |
|---|---:|---:|---:|---:|
| ジャンプ回数 | 6回 | 6回 | 6回 | 6回 |
| 跳躍高度 | 約2.3m | 約4.1m | 約6.3m | 約8.6m |
| 滞空時間 | 3.4秒 | 4.5秒 | 5.6秒 | 6.5秒 |
| 水平移動距離 | 7〜10m | 12〜16m | 18〜24m | 26〜35m |
| 地球の見かけの直径※ | 14〜24％ | 24〜38％ | 38〜55％ | 55〜80％ |
| 着地の光の粉 | 少量 | 中量 | 多量 | 最大 |

※画面の短辺に対する割合。最後のジャンプは通常の跳躍高度・滞空時間の制限から除外します。

### 5.2. 第1段階：はじめての月面ジャンプ

月面の砂や岩、クレーターの質感を十分に見せる段階です。

地球はまだ遠く、小さく見えています。金色に光るクレーターのふちから跳ぶと、普段の地球上では体験できない長さの浮遊を味わえます。

着地するたびに地球が少しずつ大きくなり、青白い光の粉が足元に広がります。

最初のジャンプから、操作に対する大きな反応を与えてください。序盤を長いチュートリアルにしないこと。

### 5.3. 第2段階：地球の光が届く丘

地形の起伏が少し大きくなり、ジャンプの高さと移動距離が増します。

地球の海と大陸をはっきり認識できるようになります。月面の岩の輪郭や宇宙服に青い反射光が加わります。

着地時には光の粉が円形に広がるだけでなく、近くにある小さな月の石も青白い光を一瞬反射します。

### 5.4. 第3段階：青い地球を見渡す高原

ジャンプすると眼下に複数のクレーターが見えるほどの高さになります。

地球の雲の渦や海の反射、大気圏の青い輪郭が存在感を増します。空中では、子どもとウサギの周囲を淡い青色の光の粒が流れていきます。

地球が近くなったことを、単に球体の大きさだけでなく、表面の細部が見えるようになることでも伝えてください。

着地するたびに月面を伝う光の輪が大きくなり、成功音には豊かな和音が加わります。

### 5.5. 第4段階：地球へ届く最後の丘

最後の丘の頂上に向かって、より長いジャンプを繰り返します。

地球は空の主役となり、月面には地球から届く青い光が広がっています。クレーターのふちも、金色から金色と水色が重なった光へ変化します。

第4段階の6回目のジャンプ地点は、特別に大きな光の輪を持つクレーターのふちとします。

ウサギがそこに立って地球を見上げ、耳を動かしながらプレイヤーの操作を待ちます。

通常のジャンプ地点と同じ操作で、クライマックスが始まります。

### 5.6. クライマックス：青い地球の光へ

### 5.7. しずかな余韻と再プレイ

クライマックスの後、約12〜15秒間の余韻を設けます。

青い光が徐々に落ち着き、子どもとウサギが星空の中で穏やかに浮かびます。地球は正面に美しい姿を保ち、光の粒がゆっくり漂います。

最後は滑らかなクロスフェードによって再び月面に戻ります。ウサギが耳を動かし、最初のクレーターのふちが金色に輝き始めます。

再スタートのための文字やボタンは設けず、そのふちを触るだけで再び遊べるようにしてください。自動で状態を初期化する際も、突然場面が切り替わらないようにします。

## 6. カメラ設計

### 6.1. 基本構図

子どもの斜め後ろから追従する三人称視点を採用します。

初期値として、カメラの高さを3〜4m、子どもからの後方距離を5〜8m、垂直FOVを45〜55度程度とします。

画面内では、以下の配置を維持してください。

- 画面中央上部：青い地球。
- 画面中央付近：次に触るクレーターのふち。
- 画面中央下部：子どもと白いウサギ。

地球とジャンプ地点の水平位置は、画面幅の中央50％の位置を基準に、±5〜8％程度に収めます。

操作対象は画面の上下方向にも極端に偏らず、通常は画面上端から45〜65％の範囲に配置してください。

地球の位置を不自然に動かすことで構図を維持するのではなく、進行経路、注視点、カメラ位置を設計して両者を整列させます。

### 6.2. ジャンプ中のカメラ

カメラは子どもの動きに遅れて滑らかに追従します。

- 踏み切り時に急な上下移動を行わない。
- 滞空中は月面の広がりと地球を同時に見せる。
- 着地時に画面を振動させない。
- ロール角は原則0度とする。
- カメラ回転速度は通常15度/秒以下を目安とする。
- 追従の補間時定数は0.25〜0.6秒程度とする。

カメラの手動操作は設けません。プレイヤーはジャンプすることだけに集中できるようにしてください。

### 6.3. 縦画面と横画面への対応

単純に画面を切り抜くだけのレスポンシブ対応は禁止します。

Three.jsのカメラの水平・垂直FOVと、地球や操作対象の投影サイズを用いて、自動的にカメラ距離や注視点を調整してください。

地球については球体の外周と大気圏まで含めた境界を計算し、画面の四辺から原則7％以上の余白を確保します。

クライマックスで画面全体を光が覆う場合も、地球本体の円形を画面外へ押し出さず、光の広がりによって包み込まれる感覚を表現します。

画面回転中に進行状態をリセットしてはいけません。画面サイズに対応する再計算を行い、現在のジャンプをそのまま継続してください。

## 7. 操作と入力処理

iPad Safari、iPhone Safari、PCブラウザーで同じゲームを遊べるようにします。

入力はPointer Eventsに統一し、タッチとマウスの双方に対応してください。

- 最初のpointerdownを主要な入力とする。
- 複数のポインターが検出された場合は、最初の1本だけを処理する。
- pointercancel時には入力状態を適切に解除する。
- 光るふちの当たり判定は、投影された見た目の大きさの1.3〜1.6倍程度とする。
- 最小タップ領域は96×96 CSS px程度を目安とする。
- touch-action、overscroll-behavior、user-selectなどを適切に設定する。
- スクロール、ピンチズーム、ダブルタップズーム、長押しメニュー、テキスト選択をゲーム領域で抑制する。
- マウスホイールや右クリックによるカメラ操作は設けない。

状態管理は、待機、接近、踏み切り、浮遊、着地、段階移行、最終跳躍、余韻に分けます。

1回の入力から複数回の成功判定が発生しないようにし、成功回数と演出の進行を一元管理してください。

## 8. 音の設計

外部音源を使用せず、Web Audio APIによってすべての音を手続き的に合成してください。

AudioContextは最初のユーザー操作時に生成またはresumeします。

### 8.1. 操作に対応する効果音

| 場面 | 音の方向性 |
|---|---|
| タップ | 小さく澄んだ鈴のような音 |
| 踏み切り | 上昇する短い音程 |
| 浮遊 | 透明感のある持続音 |
| 最高点 | 小さな倍音の輝き |
| 着地 | 砂の感触を伴う穏やかな音と短い和音 |
| 次の地点の点灯 | 遠くから響くような澄んだ音 |
| クライマックス | 複数の音が重なる壮大な和音 |

踏み切り音は正弦波と三角波を組み合わせ、250Hz前後から600Hz前後へ滑らかに上昇させる方法などを採用してください。

着地音はフィルターを通したノイズと、短い減衰を持つ音程成分を組み合わせます。

月面での音は現実の大気を伝わる音ではなく、ゲーム内の心地よい演出音として扱います。

### 8.2. 段階による変化

- 第1段階：単音を中心とする。
- 第2段階：2音の協和音を加える。
- 第3段階：長三和音を中心とする。
- 第4段階：オクターブや高域の倍音を加える。
- クライマックス：複数の音が時間差で重なり、ゆっくり減衰する。

例えばC、E、G、上のCを基本とした音の組み合わせを使用できます。

環境音は低音量のアンビエント音とし、効果音を妨げないようにしてください。既存の楽曲や旋律は使用しません。

音割れ、突然の大音量、鋭い高音を防ぎ、マスターゲインとDynamicsCompressorNodeなどで出力を管理します。バックグラウンド移行時には音を停止または減衰させ、復帰時に正常に再開できるようにします。

## 9. 画面の文字と表現上の禁止事項

ゲーム画面には文字、数字、タイトル、スコア、段階表示、ボタンラベルを一切表示しません。

進行度は地球の大きさ、ジャンプの高さ、光の変化、音の豊かさだけで伝えてください。

不気味な生き物、怪物、おばけ、不穏な風景、お姫様、既存のキャラクター、ブランド要素、既存作品を識別できる意匠は使用禁止です。

宇宙の背景が暗色であっても、地形、ウサギ、宇宙服、操作対象は十分な視認性を保ってください。

また、実装するHTML、CSS、JavaScript、変数名、コメント、付随するテキストに、別紙の禁止語を使用しないでください。ひらがな・カタカナへの置き換えも禁止です。

## 10. 画質の自動調整とパフォーマンス

2020年モデルのiPad Pro相当のSafariで、通常プレイ時50fps以上を目標とします。

写実性を高めることよりも、安定したフレームレートと気持ちよい操作感を優先する場面があることを理解してください。

### 10.1. 画質プリセット

| 項目 | high | mid | low |
|---|---:|---:|---:|
| デバイスピクセル比の上限 | 1.5 | 1.15 | 0.85 |
| シャドウマップ | 2048² | 1024² | 512²または簡易影 |
| ブルーム | 有効 | 低解像度 | 簡易発光 |
| 星の数 | 1600 | 800 | 400 |
| 着地パーティクル上限 | 360 | 180 | 80 |
| 地球の生成テクスチャ | 2048×1024 | 1024×512 | 1024×512 |
| 地形メッシュ密度 | 100％ | 約65％ | 約40％ |

low設定でも、地球の海と雲、クレーターの立体感、ジャンプの動き、着地時の光、操作対象の視認性は維持してください。

### 10.2. 自動画質調整

起動時にはmidを基本とし、描画開始後のFPSを測定して適切な品質を選択します。

実行中も継続して測定し、例えば以下の基準で制御してください。

- 平均FPSが48未満の状態が3秒以上続いた場合、画質を1段階下げる。
- 平均FPSが58以上の状態が12秒以上続いた場合、画質を1段階上げる候補とする。
- 画質変更後は一定の待機時間を設け、頻繁な切り替えを防止する。
- 可能な限り着地後などの安定したタイミングで画質を変更する。

URLパラメータ `?q=low`、`?q=mid`、`?q=high` が指定されている場合は、その画質に固定し、自動変更を停止します。

### 10.3. 最適化

InstancedMesh、オブジェクトプール、ジオメトリ共有、マテリアル共有、距離に応じたLODを活用してください。

描画フレームごとに多数のオブジェクトを生成・破棄したり、地球のテクスチャを再生成したりしないこと。

アニメーション時間はフレーム数ではなく経過時間に基づいて計算します。タブ復帰時などの異常に大きなdelta timeは制限し、突然ジャンプが終了する現象を防いでください。

再プレイを繰り返しても、GPUメモリ、イベントリスナー、オーディオノード、パーティクル数が増加し続けないようにします。
