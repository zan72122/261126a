# D01 実装指示文：月夜の港町から、一番輝く星へ

## 0. 実装の基本方針

あなたは、写実的な3D空間の構築、自然現象の表現、幼児向けのインタラクション設計、WebGLのパフォーマンス最適化に精通したゲーム開発者です。

5歳の女の子が、白い大きな鳥の背に乗り、月夜の港町の上空を飛びながら、雲から動物の仲間を生み出し、空で一番輝く星へ向かう3Dウェブゲームを制作してください。

単に美しい景色を眺める作品ではなく、**自分が雲に触れるたびに、仲間が増え、町に光がともり、世界全体が変化していく遊び**にしてください。

プレイヤーに飛行操縦や正確な照準合わせを要求しません。鳥は自動で飛行し、子どもは指1本で魔法を起こすことに集中できます。

最優先事項は、操作の直感性、操作直後の大きな変化、写実的な空間表現、段階的な高揚感、最後の圧倒的な爽快感です。

## 1. ゲームの狙い

- **夢×写実：** 雲がクジラや馬になって一緒に飛ぶ夢のような出来事を、月光を受けた雲の立体感、鳥の羽毛、川面に揺れる光など、現実の自然現象に基づく写実表現で成立させる。
- **高揚感：** タップするたびに空の仲間が増え、眼下の港町が次々と輝き始め、目的地の星が大きくなっていくことで、自分の力で壮大な世界を変えている感覚を生み出す。
- **爽快感：** 仲間たちと最後の星へ飛び込み、それまで蓄積された光が夜空全体へ解き放たれる、解放感に満ちたクライマックスを体験させる。

ゲーム全体を通じて、「触ったから、この素晴らしい変化が起きた」という因果関係を明確にすること。

## 2. 絵から借りる光と色

### 2.1 芸術的な方向性

参考資料B11から借りる要素は、満月に照らされた川沿いの町、銀色の月光、動物の形へ変化する雲、遠方に輝く目的地の星である。

参考資料B22からは、同じ景色の中で多数の灯りが一斉にともることによる、世界全体の変貌という発想を借りる。

元の作品の構図、建物の配置、絵柄、固有の意匠は再現しない。舞台は独自に設計した架空の港町とする。

現実の自然風景と幻想的な現象が違和感なく溶け合う、映画品質を志向した写実3D空間を目指す。魔法は装飾的な記号ではなく、光の拡散、反射、発光、雲の変形といった空間内の現象として表現する。

### 2.2 時間帯とカラーパレット

物語の時間帯は満月の夜で統一する。ただし、飛行高度と魔法の進行に応じて、空の色彩と光の密度を変化させる。

| 項目 | 第1段階：月夜の港 | 第2段階：銀色の雲海 | 第3段階：星への飛翔 |
|---|---|---|---|
| 天頂の空 | `#193866` | `#243F80` | `#334C91` |
| 地平線の空 | `#6489B8` | `#82A8D0` | `#A7BCED` |
| 月光を受けた雲 | `#DCEBFA` | `#E5F2FF` | `#F1F5FF` |
| 雲の陰影 | `#607BA3` | `#7892BD` | `#8796C7` |
| 川・港の水 | `#244B70` | `#305B80` | `#41668C` |
| 建物の窓の光 | `#FFD28A` | `#FFE0A0` | `#FFE7B8` |
| 魔法の光 | `#A9E5FF` | `#D2E8FF` | `#FFF2C9` |
| 目的地の星 | `#FFF1C2` | `#FFF4D8` | `#FFFAEB` |

真っ黒な空や黒く潰れた地形を避ける。夜景であっても、羽毛、雲の陰影、建物、水面の輪郭を容易に識別できる露出を維持する。

月光の青白さと、町の灯りの暖色との対比を、全編の美術的な中心に据える。

### 2.3 Three.jsでの照明設定

以下は初期実装時の目安であり、実際の描画結果を見ながら調整してよい。距離の単位はおおむね1単位＝1mとする。

| 光源・効果 | 設定の目安 |
|---|---|
| 月光 | DirectionalLight、約7000～8500K相当、`#D0E5FF`、intensity 2.0～3.0 |
| 空からの環境光 | HemisphereLight、sky `#B5D5FF`、ground `#56647D`、intensity 1.5～2.2 |
| 補助光 | AmbientLight、`#D7E5FF`、intensity 0.2～0.45 |
| 建物の窓 | 約2400～3000K相当、emissive `#FFD18A`、intensity 1.5～3.5 |
| 雲の変身時 | 約8500K相当、`#C7E9FF`、発光強度2.0～4.0 |
| 星の光 | 約4800～5500K相当、`#FFF1CD`、発光強度3.0～7.0 |
| 大気遠近法 | Fog、near 180、far 1400～2200 |
| ブルーム | threshold 0.85～1.1、strength 0.35～0.75、radius 0.3～0.55 |
| トーンマッピング | ACESFilmicToneMapping |
| 露出 | toneMappingExposure 1.05～1.35 |

色温度は演出上の目安とし、Three.jsへの入力には対応する色を使用する。出力色空間はsRGBとし、照明とマテリアルの色管理を統一する。

月は光源としてだけでなく、空に見える球体としても配置する。月の位置とDirectionalLightの方向を一致させ、雲の縁、羽毛、水面の反射に一貫性を持たせる。

ブルームを画面全体に過剰に適用しない。羽毛や雲の細部は残しながら、星、窓、魔法の粒子などの高輝度部分を選択的に輝かせる。

## 3. 舞台と登場するもの

### 3.1 川沿いの港町

舞台は、幅広い川が海へ注ぐ、緩やかな丘陵に囲まれた架空の港町とする。

以下の要素をすべてプロシージャル生成する。

- 石造りや木造の低層住宅、三角屋根、煙突、窓、バルコニー。
- 川沿いの遊歩道、街灯、石橋、桟橋、小型の帆船。
- 丘陵、草地、針葉樹、川岸の岩。
- 川から港へ連続する広大な水面。

建物を単純な直方体の集合で終わらせない。屋根の傾斜、窓の奥行き、庇、壁面の微細な凹凸などを加え、空から見ても実在感のある町を構築する。

建物の色、屋根の角度、高さ、窓の配置を一定範囲で変化させる。建物は120～200棟程度を目安とし、InstancedMeshやジオメトリの結合によって描画負荷を抑える。

町を18区画に分割する。開始時は一部の街灯と窓だけが点灯しているが、プレイヤーが雲を動物に変えるたびに、未点灯の1区画に光がともる。

点灯した区画は最後まで点灯状態を維持する。

### 3.2 川と港の水面

単色の平面で水を表現することは禁止する。

ShaderMaterialなどを使用し、以下を組み合わせて写実的な水面を構築する。

- 波長0.3～8m程度の複数の波を合成した水面の法線変化。
- 視線角度に応じて反射率が変化するフレネル効果。
- 月光による銀色の反射の帯。
- 建物や街灯の光が縦方向に伸び、水面の揺れによって細かく分断される反射。
- 川の中央と川岸で異なる色と波の強さ。

反射は単純な鏡像ではなく、細かな波によって絶えず形状が変化するようにする。

町の一区画が点灯した際には、その区画に対応する水面の反射も同時に出現させる。これによって、子どもの操作が建物だけでなく川にも影響したことを実感させる。

高画質設定でも高負荷なリアルタイム反射を必須としない。解析的な反射表現や、発光体を参照した疑似反射を優先してよい。

### 3.3 白い大きな鳥

プレイヤーが乗っている鳥は、白鳥の優美さと大型の海鳥の飛行能力を組み合わせた、架空の白い鳥とする。

人間や乗客の身体は表示しない。カメラ位置によって、鳥の背に乗って飛んでいる感覚を成立させる。

鳥の造形では以下を重視する。

- 全長約6～8m、翼幅約14～18m。
- 胴体から首、頭部へ連続する自然な曲面。
- 翼の初列風切羽と次列風切羽の重なり。
- 翼端の羽が風圧によって個別にわずかにしなる動き。
- 飛行方向に沿った羽毛の流れ。
- 月光を受ける羽毛の細かな陰影と、翼の縁の反射光。

胴体と翼を単純な球体や板だけで構成しない。曲面メッシュと複数の羽毛形状を組み合わせる。

羽毛の基調色は `#E6EDF4`、陰影は `#91A8C0`、月光を受ける部分は `#F5FAFF` を目安とする。

MeshStandardMaterialを基本とし、roughness 0.65～0.85、metalness 0.0とする。

羽ばたきは3～5秒に1回程度とし、その間は気流に乗って滑空する。カメラを羽ばたきと同期して上下に揺らさないこと。

### 3.4 空と雲

空は大型の球体または専用シェーダーによって生成する。天頂から地平線へ連続する色の変化、大気による光の散乱、遠方の霞を表現する。

背景には大小の星を配置するが、目的地の星だけが明確に際立つようにする。背景の星は控えめな輝度とし、操作対象と誤認させない。

通常の雲には以下の特徴を持たせる。

- 複数の密度の異なる雲塊が重なった立体構造。
- ノイズを用いた自然な輪郭の変化。
- 月側の縁に生じる銀色の光。
- 内部の密度差による陰影。
- 風によってゆっくりと変化する表面。

球体を並べただけの雲や、常にカメラに正対する単純な白い板は避ける。

高負荷な完全体積レンダリングは必須としない。低ポリゴンの雲塊、InstancedMesh、フラグメントシェーダーによる密度表現などを組み合わせ、立体感と処理速度を両立する。

### 3.5 雲から生まれる動物

変身する動物は、以下の6種類を基本とする。

| 動物 | 特徴的なシルエット | 飛行中の動き |
|---|---|---|
| クジラ | 大きな胴体、胸びれ、尾びれ | 尾びれを上下させて空を泳ぐ |
| 馬 | 長い首、たてがみ、四肢 | 空中をゆっくり駆ける |
| 白鳥 | 長い首と広い翼 | 優雅に羽ばたく |
| イルカ | 流線形の胴体と背びれ | 緩やかな弧を描いて泳ぐ |
| ウサギ | 長い耳と丸みのある胴体 | 空中を軽やかに跳ねる |
| シカ | 分岐する角と細長い脚 | ゆったりと空を駆ける |

動物は雲で構成されているが、実際の動物に近い骨格、身体の比率、関節の動きを採用する。

目や口を過度に強調しない。人間のような表情を与えず、動物として自然な仕草にする。角や牙などが脅威に見える造形も避ける。

雲の輪郭には細かな粒子を残し、動物の実体が水蒸気から成り立っていることを表現する。

変身前後で雲の構成要素を共有し、各要素が目標となる動物形状へ補間移動する方式を推奨する。動物の形状は、楕円体、曲線に沿った立体、関節付きメッシュなどから生成する。

同じ動物が再登場する場合は、大きさ、銀色の濃淡、動作を変化させる。

### 3.6 目的地の星

目的地の星は、空の向こうに浮かぶ独立した発光体とする。

五芒星のような記号的形状ではなく、恒星を思わせる白金色の中心核、青白い光輪、微細な光の粒子から構成する。

ゲームの進行に応じて、見かけの大きさを段階的に増加させる。

星の周辺には、到達が近づくほど繊細な光の筋や、ゆっくり回転する粒子の流れが出現する。

## 4. 指1本のプレイループ

### 4.1 開始

ページを開くと、すでに白い鳥が月夜の港町の上空を滑空している。

画面中央には、まだ何の形にもなっていない銀色の雲が浮かんでいる。その雲の縁がゆっくりと脈動し、最初の操作を誘う。

開始ボタン、説明文、タイトル画面、カウントダウンは設けない。

中央の雲を初めてタップした瞬間から、最初の変身と音の演出が始まる。

### 4.2 1回の操作と結果

以下の流れを、1回の基本ループとする。

1. **課題の出現：** 飛行方向の正面に、形のない雲が現れる。鳥は雲との距離を保ちながら滑空する。
2. **取り組み：** 子どもが雲をタップする。
3. **即時反応（0～0.15秒）：** タップ位置から銀色の光が広がり、澄んだ成功音が鳴る。
4. **変身（0.15～1.8秒）：** 雲の構成要素が集まり、クジラや馬などの身体を形成する。
5. **仲間入り（1.8～3.5秒）：** 動物が身体を動かし始め、白い鳥の隣へ移動する。
6. **町の点灯（2.0～4.0秒）：** 眼下の町の一区画に光が連鎖的に広がり、川面にも反射が現れる。
7. **前進（3.5～7.0秒）：** 飛行する仲間たちが一緒に進み、目的地の星が一段近づく。
8. **次の課題：** 新しい雲が前方に現れ、次のタップを誘う。

1回の操作によって、手前の雲、眼下の町、遠方の星という3つの距離の異なる対象が連動して変化することが、このゲームの最も重要な特徴である。

### 4.3 操作を促す演出

最後の操作から3秒経過した場合は、現在の対象の縁に銀色の光を走らせる。

さらに3秒経過した場合は、対象の雲が緩やかに膨張と収縮を繰り返し、小さな光の粒子が雲の中心に集まるようにする。

文字、矢印、指や手のアイコンは使用しない。

何も操作しなくても鳥は滑空を続けるが、対象の雲を通り過ぎないようにする。

### 4.4 失敗のない設計

- 雲以外の場所をタップしても、不快な音や警告を出さない。
- 制限時間、ライフ、得点、減点、失格を設けない。
- 操作しないことによる進行度の減少を禁止する。
- 雲への衝突や鳥の墜落は発生させない。
- 連打してもゲーム状態が破綻しないようにする。
- 変身演出中に再度タップしても、二重に成功処理を実行しない。

プレイヤーがどれだけ長く操作しなくても、次の成功を待っている世界であり続けること。

## 5. 盛り上がりの設計

全3段階、各6回、合計18回の成功でクライマックスに到達する構成とする。

標準的なプレイ時間は約3～5分とする。ただし、時間による強制終了は行わない。

### 第1段階：月夜の港町（1～6回目）

- 飛行高度：約60～110m。
- 飛行速度の演出：約6～9m/s。
- 仲間の動物：0体から6体へ。
- 町の点灯：全18区画のうち6区画。
- 主な色彩：月光の青白さと窓の琥珀色。

港町に近い高さを飛行することで、建物や川面の細部を楽しめる段階とする。

最初の雲は、変身前後の形状の違いが分かりやすいクジラにする。巨大なクジラが雲から誕生することで、最初の数秒からこのゲーム固有の魅力を伝える。

6回目の成功では、石橋と川沿いの街灯が連鎖的に点灯する。通常の成功よりも規模の大きな演出を与える。

### 第2段階：銀色の雲海（7～12回目）

- 飛行高度：約110～220m。
- 飛行速度の演出：約9～14m/s。
- 仲間の動物：6体から12体へ。
- 町の点灯：累計12区画。
- 主な色彩：銀色、青紫、淡い金色。

白い鳥は徐々に高度を上げ、厚みのある雲の間を飛ぶ。

雲の隙間から眼下の港町が見えるようにし、町と水面の点灯演出が引き続き確認できること。

仲間たちは単に横に並ぶだけでなく、ゆっくりと隊列を組み替える。クジラが空を泳ぎ、馬が駆け、鳥が翼を広げる光景を同時に楽しめるようにする。

12回目の成功では、点灯済みの区画を結ぶように、川沿いの光が大きな波となって伝わる。

### 第3段階：星への飛翔（13～18回目）

- 飛行高度：約220～350m。
- 飛行速度の演出：約14～20m/s。
- 仲間の動物：12体から18体へ。
- 町の点灯：全18区画。
- 主な色彩：白金色、銀色、淡い虹色。

目的地の星が、遠くの小さな点から立体的な発光体へ変化する。

仲間たちの身体の縁にも星の光が反射し、編隊全体が輝き始める。

速度の増加は、遠方の景色や光の粒子の移動によって伝える。画面を激しく揺らしたり、カメラの回転速度を増加させたりしない。

18回目の成功で町の最後の区画が点灯し、川沿いの港町全体が光に包まれる。

## 6. クライマックスと余韻

### 6.1 星への最後のタップ

18回目の雲の変身が完了すると、新しい雲は出現せず、目的地の星そのものが画面中央の操作対象となる。

星の周囲を銀色と金色の粒子が巡り、中心核がゆっくりと脈動する。

プレイヤーが星をタップすると、最後の飛翔が始まる。

### 6.2 光の解放

クライマックスは約12～18秒とする。

| 経過時間 | 演出 |
|---|---|
| 0～2秒 | 星がタップに反応し、金色の光輪が拡大する |
| 2～6秒 | 白い鳥が翼を大きく広げ、18体の仲間が星へ向かう編隊を形成する |
| 6～9秒 | 星の中心へ接近し、光の粒子が画面の奥から周囲へ流れる |
| 9～11秒 | 星へ飛び込む瞬間、白金色の光が球状に広がる |
| 11～14秒 | 光の波が夜空と眼下の港町へ伝播し、水面が銀色と金色に輝く |
| 14～18秒 | 光の粒子がゆっくりと空に散り、静かな飛行へ戻る |

星へ接近する際には、その全体が画面内に収まる最大サイズまで拡大する。最後の飛び込みは、中央から広がる光による連続的な場面遷移で表現し、星そのものを見切れさせない。

光の解放は一度だけの壮大な演出とする。高速点滅、ストロボ、急激な白画面への切り替えは避け、露出と発光強度を連続的に変化させる。

### 6.3 静かな余韻とフリープレイ

クライマックス後は、すべての灯りがともった港町の上空を約10～15秒間滑空する。

18体の仲間たちは消滅せず、一緒に飛行を続ける。

その後は自動的にフリープレイへ移行する。新しい雲に触れることで、仲間の一部が別の動物へ変身したり、町に光の波を送ったりできる。

フリープレイ中は仲間の数を最大18体に維持し、無制限にオブジェクトを増やさない。

終了画面やリザルト画面は表示しない。

## 7. カメラと画面構成

### 7.1 基本カメラ

PerspectiveCameraを使用する。

- 基本位置：白い鳥の斜め後ろ上。
- 鳥との距離：24～40mを初期値とする。
- 鳥からの高さ：7～13m。
- FOV：縦方向42～55度程度。
- near：0.5～1.0。
- far：2500～4000。

鳥の背と広げた翼、前方の雲、眼下の町が同時に見える構成を基本とする。

### 7.2 中央配置の絶対条件

現在の操作対象を常にカメラの注視点とする。

雲のタップ待機中は雲の中心、変身中は変身する動物の中心、クライマックスでは星の中心を画面中央に配置する。

変身完了後は、動物が隊列へ移る動きと次の雲の出現を連携させ、注視点を滑らかに切り替える。

操作対象の画面上の中心座標は、原則として画面中央から上下左右5％以内とする。

対象を画面端へ移動させることによって構図を成立させてはならない。

### 7.3 縦向き・横向きへの対応

端末の画面比に応じて、カメラ距離、FOV、仲間の編隊を調整する。

横向きでは仲間を左右に広く配置する。縦向きでは奥行きを利用し、仲間を複数列に配置する。

現在の対象、白い鳥の翼端、すべての仲間、クライマックスの星について、画面への投影座標と境界を確認する。画面端から8～12％程度の余白を確保することを目標とする。

対象の見かけの大きさは、画面の短辺の18～30％程度を基本とする。隊列が広がりすぎて対象が小さくなる場合は、カメラを過度に引くのではなく隊列そのものを再配置する。

18体の仲間が存在する最終段階でも、各動物の主要な輪郭が識別でき、画面外へ切れないようにする。

### 7.4 酔いを防ぐ設計

カメラの移動と回転には、時間差を用いた滑らかな補間を使用する。

- 水平線の傾きは原則0度とする。
- カメラのロール回転は行わない。
- カメラの角速度はおおむね毎秒10度以下。
- 急加速、急降下、急旋回を禁止する。
- 羽ばたきによるカメラの上下動を発生させない。
- モーションブラーや強い放射状ブラーを使用しない。

## 8. 操作と入力処理

iPad SafariおよびPCブラウザで、同一のゲームを遊べるようにする。

入力にはPointer Eventsを使用する。タッチ操作とマウスクリックを共通の処理経路へ接続する。

タップ判定には、実際の雲や星のメッシュとは別に、見た目より1.3～1.6倍程度大きな不可視の判定領域を用意する。画面上の判定領域は短辺64～80 CSS px以上を目安とする。

レイキャストに加え、対象の画面座標との距離による補助判定を採用してよい。

CSSおよびイベント処理によって、ゲーム領域で以下のブラウザ標準動作を抑制する。

- ピンチズーム。
- ダブルタップズーム。
- スクロールとオーバースクロール。
- 長押しによるコンテキストメニュー。
- テキスト選択。
- 画像や要素のドラッグ。

`touch-action: none`、`user-select: none`、`overscroll-behavior: none`などを適切に設定する。

複数の指が画面に触れた場合は、最初の有効なPointerのみを処理し、残りは無視する。`pointercancel`や画面の回転が発生した場合にも、入力状態を正常に復帰させる。

指を画面から離した後に次の操作ができなくなる不具合を防止すること。

## 9. 音響設計

音はすべてWebAudio APIによって手続き的に合成する。外部音声ファイルや既存の楽曲を使用しない。

最初の実際のタップイベント内でAudioContextの生成またはresumeを実行する。

### 9.1 操作音と成功音

| 場面 | 音の設計 |
|---|---|
| 雲へのタップ | 短く澄んだベル音、約0.2秒 |
| 雲の変身 | 上昇する複数の音と繊細なきらめき |
| 動物の誕生 | 透明感のある和音、約0.8～1.5秒 |
| 町の点灯 | 光の伝播に同期した連続音 |
| 星への接近 | 高音域の粒子音と持続する和音 |
| クライマックス | 広がりのある和音と穏やかな低音 |
| 余韻 | 長い減衰を伴う静かな響き |

音階にはDメジャー・ペンタトニックなど、音が重なっても不協和になりにくい構成を採用する。

第1段階では単音と2音、第2段階では3～4音、第3段階では4～6音を組み合わせ、成功音の豊かさを段階的に増加させる。

### 9.2 環境音

フィルターを通したノイズから、上空を流れる風の音を生成する。

低高度では川のせせらぎや遠い水音を加え、高高度では風と静かな持続音を中心にする。

BGMは操作音を邪魔しない音量とする。Master GainとDynamicsCompressorNodeを用い、連打や音の重複によって突然大音量にならないようにする。

## 10. 画面の文字と禁止事項

ゲーム画面に文字、数字、タイトル、得点、進行度、操作説明、ボタンのラベルを一切表示しない。

ロード中も、必要であれば静止した空や脈動する光などを表示し、文章による案内は出さない。

不快な生物、おばけ、怪物、不穏な現象、お姫様、既存のキャラクター、作品固有の意匠、ブランド要素を使用しない。

**別紙の禁止語は、実装指示、ソースコード、コードコメント、変数名、ログ、画面表示のいずれにも使用しないこと。**

別紙が実装環境に提供されている場合は、表記違いを含めて実装完了前に確認する。

## 11. 画質の自動調整

iPad Safariで50fps以上の安定した動作を目標とする。

画質はhigh、mid、lowの3段階を用意する。

| 項目 | high | mid | low |
|---|---:|---:|---:|
| ピクセル比上限 | 1.5 | 1.15 | 0.85 |
| 影マップ | 1024² | 512² | 無効 |
| ブルーム | 有効 | 低解像度 | シェーダーによる疑似発光 |
| 同時表示粒子数 | 1500 | 650 | 250 |
| 雲の構成要素数／近景1体 | 100～160 | 50～80 | 25～40 |
| 背景の星 | 600 | 350 | 180 |
| 水面の波の合成数 | 5 | 3 | 2 |
| 反射表現 | 高精細疑似反射 | 簡略化 | 基本的な光の帯 |

起動時はmidを基本とし、描画開始後のFPSを計測して初期画質を決定する。

実行中も移動平均FPSを監視する。45fps未満が3秒程度続いた場合は1段階下げ、58fps以上が12秒程度続いた場合は1段階上げる。

切り替え後は10秒程度の猶予を設け、頻繁に画質が変化しないようにする。ページが非表示になった際の計測値は除外する。

`?q=low`、`?q=mid`、`?q=high`による画質の強制指定に対応し、その場合は自動切り替えを停止する。

どの画質でも18体の仲間、町の点灯、変身、星への飛び込みというゲームの核を削除してはならない。

ジオメトリとマテリアルの共有、InstancedMesh、LOD、オブジェクトプール、不要な毎フレームのメモリ確保の削減を徹底する。

## 12. 技術構成と実装要件

### 12.1 ファイル構成

ゲーム本体は以下の1ファイルにまとめる。

`site/games/d01/index.html`

HTML、CSS、JavaScriptを同一ファイルに記述する。

Three.jsはリポジトリに同梱されている以下を使用する。

- `site/vendor/three/build/three.module.min.js`
- `site/vendor/three/examples/jsm/`

importmapにて、`three`を`../../vendor/three/build/three.module.min.js`へ、`three/addons/`を`../../vendor/three/examples/jsm/`へ対応させる。

CDN、外部API、外部画像、外部3Dモデル、外部テクスチャ、外部音声ファイルは禁止する。

必要なテクスチャはCanvasTexture、DataTexture、シェーダーなどによって生成する。

`<head>`内に以下を必ず追加する。

```html
<meta name="robots" content="noindex">
```

`</body>`の直前に以下を必ず追加する。

```html
<script src="../../gf-playlog.js" defer></script>
```

既存の共有ライブラリや他のゲームのファイルを改変しないこと。

### 12.2 状態管理

ゲームの進行を明示的な状態として管理する。

以下の状態名は実装上の例である。

- `WAITING`：雲へのタップ待機。
- `TRANSFORMING`：雲の変身。
- `JOINING`：仲間入りと町の点灯。
- `ADVANCING`：前進と次の雲の出現。
- `STAR_WAITING`：最後の星へのタップ待機。
- `CLIMAX`：星への飛翔と光の解放。
- `AFTERGLOW`：余韻。
- `FREE_PLAY`：継続プレイ。

成功回数と段階の情報を一元管理し、入力、点灯、仲間の生成、音、カメラが互いに矛盾しないようにする。

画面回転、ページの一時停止と復帰、画質変更によって進行度を失わないようにする。

### 12.3 準備完了とエラー管理

初期化の開始前に`window.__ready = false`と`window.__errors = []`を定義する。

シーン、カメラ、レンダラー、入力処理、最初の操作対象が正常に準備され、最初のフレームを描画した段階で`window.__ready = true`とする。

実行時エラー、未処理のPromise rejection、初期化時の例外などを`window.__errors`へ記録する。

エラーを握り潰して、正常に動作したように見せる実装は禁止する。

### 12.4 自動プレイ

`?autotest`を付与した場合は、入力操作なしで全18回の成功処理を実行し、最後の星へのタップ、クライマックス、余韻、フリープレイへの移行まで確認できるようにする。

自動プレイでも通常プレイと同じ状態遷移、変身、点灯、描画処理を使用する。

成功回数を直接書き換えてクライマックスへ移動するだけの実装は禁止する。

テスト時は待機時間や演出時間を短縮してよいが、各段階の描画を実際に通過させること。

ブラウザによる自動音声再生の制約は尊重し、ユーザー操作がない場合は無音で自動テストを続行できるようにする。
