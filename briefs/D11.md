# D11 実装指示文：オーロラの譜面で舟をのぼらせる

## 1. ゲームの狙い

5歳の女の子が、氷の湖に浮かぶ小舟からオーロラに触れ、空に音楽を奏でながら、最後には自分の舟でオーロラの帯をのぼっていく、写実的な3Dウェブゲームを制作する。

- **夢×写実**：薄氷の質感、湖面の反射、夜空に揺らめくオーロラを写真のような写実3Dで表現しながら、音楽に応えてオーロラが湖まで降りてくる幻想的な現象を体験させる。
- **高揚感**：光の点に触れるたびに美しい音が鳴り、空に新しい色と光の波が広がり、静かだった北の夜が壮大な光の交響曲へと変化していく。
- **爽快感**：完成したオーロラの帯に小舟が乗り、眼下に湖や雪山を見渡しながら、広大な天空へと滑らかに加速して上昇する。

このゲームの本質は、オーロラを鑑賞することではなく、**自分の指で空に音楽を奏で、その音楽によって世界を変え、最後には自分が空へ飛び立つこと**にある。

単なるタップと発光の繰り返しにせず、触れるたびにオーロラの形状、湖面の状態、舟と空の位置関係が物理的に変化するようにする。

## 2. 絵から借りる光と色

### 2.1 アートディレクション

元資料B20から借りるのは、氷の湖、小舟、北の夜空、オーロラ、天空の音楽というモチーフと、光や色の方向性のみとする。

元作品の構図、山や舟の配置、オーロラの形状、絵柄は再現しない。独自の地形、カメラ構成、光の演出を設計すること。

現実と想像が溶け合う幻想的な写実3Dを目指し、長編ファンタジー映画のような魔法の光、空間の奥行き、世界が変貌する瞬間の驚きを重視する。

夜の場面であっても、黒く沈んだ画面にはしない。月光、星、雪面の反射、オーロラの環境光によって、舟や氷の形状が常にはっきり見えるようにする。

### 2.2 時間経過と色彩設計

実際の時刻ではなく、ゲームの進行段階に応じて空と環境光を変化させる。

| 要素 | 序盤：月光の湖 | 中盤：天空の音楽 | 終盤：光の上昇 |
|---|---|---|---|
| 天頂の空 | `#172D61` | `#233A77` | `#364E92` |
| 地平線 | `#759BC6` | `#759ACF` | `#B4A6E8` |
| 湖面 | `#244C72` | `#326D8E` | `#558DB2` |
| オーロラ・緑 | `#54F5B5` | `#60FFD1` | `#9CFFDB` |
| オーロラ・青 | `#50BFFF` | `#57D9FF` | `#85DDFF` |
| オーロラ・紫 | `#A08CFF` | `#BD8DFF` | `#D8B2FF` |
| オーロラ・桃色 | ごく少量 | `#FF99D9` | `#FFC3E8` |
| 月光 | `#D6E8FF` | `#DEEEFF` | `#ECF3FF` |

終盤では緑、シアン、青、紫、桃色が連続的に混ざり合う。ただし、原色の帯を機械的に並べた虹にはせず、オーロラ内部に自然な色の勾配を持たせる。

### 2.3 Three.jsの照明・レンダリング設定

以下は初期調整値とし、実際の画面を確認して最適化する。

- ワールドスケール：1 unit＝約1m。
- 月光：DirectionalLight、色温度の目安7500〜9000K、intensity 1.2〜1.8。
- 月の反対側からの補助光：intensity 0.3〜0.5。
- HemisphereLight：空色 `#C2D9FF`、地面色 `#6785AB`、intensity 0.9〜1.4。
- オーロラの環境光：進行に応じて緑、シアン、紫へ連続的に変化。強さは0.2〜1.3程度。
- Tone Mapping：ACESFilmicToneMapping。
- Exposure：1.1〜1.4。
- Output Color Space：SRGBColorSpace。
- 霧：FogExp2、density 0.0015〜0.0030、色 `#789BC5` を基準とする。空のシェーダーには適用しない。
- ブルーム：strength 0.45〜0.85、radius 0.35〜0.55、threshold 0.8〜1.1を初期値とする。
- クライマックスのブルーム：短時間だけstrength 1.0〜1.2程度に増加させ、滑らかに元へ戻す。

発光表現は、中心部の高輝度領域と周囲へ減衰する光を組み合わせる。画面全体が白く飛ぶほどの発光や、強い点滅は避ける。

ブルームが無効でも美しく見えるように、オーロラや光の点そのもののシェーダーに光の勾配を持たせる。

## 3. 舞台と登場するもの

すべての地形、物体、テクスチャ、エフェクト、音をプロシージャル生成する。外部の画像、3Dモデル、音声ファイルは一切使用しない。

### 3.1 氷の湖

直径600〜900m程度の、北方の山々に囲まれた湖を制作する。

湖面の大部分は静かな水面とし、ところどころに半透明の薄氷が浮かぶ。舟の周囲には水の通り道がある。

水面は専用シェーダーで表現する。

- 方向と周期の異なる3〜4種類の微小な波を重ねる。
- 波の高さは0.015〜0.06m程度。
- フレネル効果によって、遠方ほど空やオーロラの反射が強くなるようにする。
- 水面の法線を時間経過によって変化させる。
- 月光と星の反射を、水面の波に沿って細かく分断する。
- オーロラの反射は実際の発光色、形状、揺らぎと同期させる。

highでは低解像度の反射用RenderTargetなどを使用し、mid・lowではオーロラの形状と色を水面シェーダーで近似する。

### 3.2 薄氷

薄氷は不規則な多角形を組み合わせて生成する。単純な白い板に見えないよう、透明感、内部の細かな亀裂、縁の厚みを表現する。

MeshPhysicalMaterialまたは専用シェーダーを使用し、次の質感を目安とする。

- 基本色：`#BBDCEB`
- Roughness：0.12〜0.28
- IOR：1.31
- 厚さ：0.005〜0.03m
- 亀裂：プロシージャルなVoronoi模様
- 表面：微細な法線の揺らぎ

光の点をタップすると、舟から離れた位置にある薄氷まで順番に光が伝わり、小さな反射光が走るようにする。

薄氷が割れて舟が沈むなどの危険な演出は不要。

### 3.3 雪山と湖岸

湖の周囲には、高さ80〜220m程度の雪山を複数配置する。

地形メッシュにフラクタルノイズを適用し、山頂、尾根、谷、斜面を形成する。標高と斜面角度に応じて、雪、岩肌、氷の色をブレンドする。

湖岸には少量の針葉樹を配置してもよい。遠景の樹木はInstancedMeshを使用し、個々の枝葉を過剰に作り込まない。

遠景ほど霧と青紫色の大気遠近法を強め、空間の広大さを感じさせる。

### 3.4 空・月・星・雲

空は大型の球体または専用のスカイシェーダーで生成する。

星は大小、輝度、色温度に差をつけ、1000〜2500個程度をPointsで描画する。星の点滅は微弱で周期的なものに限る。

月はプロシージャルなクレーター模様と陰影を持つ円盤または球体として生成する。

雲は薄い高層雲を少量配置する。ノイズシェーダーを利用し、月光やオーロラの色が雲の縁に反映されるようにする。

空の主役はオーロラであり、雲や星で画面を埋め尽くさない。

### 3.5 小舟

全長3.2m、幅1.25m程度の、木製の小舟を制作する。

舟体は曲線に沿って断面を変化させたメッシュから生成する。船底、舷側、木板の継ぎ目、座板、真鍮製の小さな金具などを設ける。

- 木材色：`#9A6841`、`#C59B70`
- 木目：プロシージャルな筋状ノイズ
- Roughness：0.35〜0.55
- Metalness：木材0、真鍮製金具0.7〜0.9

舟の縁には、小型のガラス製ランタンを一つ取り付ける。暖色の光を灯し、冷色中心の風景に温かみを加える。

舟は湖面の波に合わせてわずかに上下する。ただし、カメラまで同じ揺れを伝えない。

人間、人物の顔、人体モデルは登場させない。プレイヤーは舟に乗っている存在として扱う。動物も本作では登場させず、オーロラと舟の関係に集中する。

### 3.6 オーロラ：最も重要な描画対象

オーロラは単なる半透明の板、平面画像、粒子の集合として表現してはならない。

空間内で複雑にうねる、巨大な半透明の光のカーテンを制作する。

**形状**

- 長さ120〜350m、高さ30〜100m程度の帯を複数生成する。
- CatmullRomCurve3などによって立体的な中心曲線を作る。
- 中心曲線に沿って縦方向に頂点を展開し、カーテン状のメッシュを形成する。
- 時間依存のサイン波と複数周波数のノイズによって形状を変形させる。
- 帯ごとに位相、振幅、移動速度を変える。
- 頂点変形は可能な限りGPU側で行う。

**発光と質感**

- 下縁は発光密度が高く、上方に向かって徐々に透明になる。
- 縦方向に細かな光の筋を形成する。
- 光の筋は緩やかに移動し、発光強度も変化する。
- 緑を基調とし、進行に応じて青、紫、桃色の領域が増える。
- 透明な帯同士が重なることで、立体的な光の層を生み出す。
- AdditiveBlendingなどを利用する場合も、重なり部分の白飛びを抑える。

**タップへの反応**

タップされた位置を発生源として、光の波がオーロラの曲線に沿って左右へ伝播する。

単なる色の変更ではなく、実際にカーテンの形状が押し広げられ、波打つようにする。音楽の振動が目に見える現象になったかのような表現を目指す。

## 4. 指1本のゲームループ

### 4.1 基本構造

プレイヤーが操作する対象は、オーロラの中に現れる一つの光の点である。

楽譜の読み方、音程、リズム、順番などの知識は一切必要としない。

毎回、以下の流れを繰り返す。

**① 課題：空に光の点が現れる**

オーロラの一部分に光が集まり、中心が白金色、周囲が淡い発光色の光球が形成される。

光球は約1.2秒周期で呼吸するように輝く。周囲の星や装飾とは明確に区別できる見た目とする。

次に触る対象は常に一つだけとする。

**② 取り組み：光の点に指で触れる**

タップすると、光球が瞬間的に収縮し、直後に光が解放される。

入力から最初の視覚的・聴覚的な反応までの遅延は80ms以内を目標とする。

長押し、ドラッグ、複数回のタップ、正確なタイミングは要求しない。

**③ 結果：空と湖が音楽に応える**

成功時には、次の現象を連動して起こす。

| タップ後の時間 | 発生する現象 |
|---|---|
| 0〜0.08秒 | 光球が収縮し、鈴の音が鳴る |
| 0.08〜0.5秒 | 光の輪が球体から広がる |
| 0.2〜1.5秒 | オーロラの帯が左右へ波打つ |
| 0.4〜2秒 | 新しい色の筋が空に加わる |
| 0.6〜2.5秒 | 湖面の反射と薄氷が連鎖的に輝く |
| 1〜3秒 | オーロラの裾が少し湖へ近づく |
| 2〜4秒程度 | 次の光球が形成される |

この反応は、過去に触れた光の点の影響を消去しない。成功するたびに色、光の筋、音楽、オーロラの高さが累積的に変化する。

### 4.2 次の操作への誘導

開始画面から、舟と湖、オーロラ、最初の光球を表示する。最初の光球へのタップを、ゲーム開始と第1回の成功として扱う。

文字による説明は行わない。

操作がない場合は、次のように誘導する。

- 3秒経過：光球の脈動をやや強める。
- 6秒経過：周辺の光の粒が光球へ吸い寄せられる。
- 10秒経過：光球から小さな光の輪が広がり、存在を再提示する。

誘導を繰り返しても、画面や音が騒がしくならないようにする。

対象外の場所をタップしても、減点、警告音、赤い表示、ゲームオーバーは発生させない。光球は消失せず、何度でも操作できる。

## 5. 盛り上がりの設計

全体を4段階、各6回、合計24回の成功で構成する。

自然な操作間隔を含め、初回プレイは約3〜5分を想定する。制限時間や強制的な待機は設けず、操作の速いプレイヤーは短時間で進められるようにする。

### 第1段階：湖に響く最初の音（1〜6回目）

- 舟は静かな湖に浮かんでいる。
- 空には緑色を主体としたオーロラが一帯だけ存在する。
- タップするたびに単音の鈴が響き、光の波が伝わる。
- 薄氷に反射光が走る。
- オーロラの裾が徐々に下降する。

6回目の成功で、オーロラの隣に新しい青色の帯が出現する。

### 第2段階：空に音楽が広がる（7〜12回目）

- 緑色と青色のオーロラが重なり合う。
- タップによって異なる帯にも光の波が伝わる。
- 成功音にハープのような響きが加わる。
- 湖面に複数の色が映り込む。
- 舟がオーロラの裾へ向かって、ゆっくりと進み始める。

12回目の成功で、紫色の光が天空を横断し、湖全体に映り込む。

### 第3段階：オーロラが湖へ降りてくる（13〜18回目）

本作における重要な転換点とする。

オーロラの下縁が湖面へ近づき、やがて舟の前方に幅6〜10m程度の光の帯が形成される。

この帯は天空へ続く緩やかな坂道となる。人工的な道路や橋ではなく、オーロラが湾曲して舟を支えられる形状に変化したように見せる。

- 光球を触れるたびに、光の帯がさらに遠くまで伸びる。
- 舟の下に光の粒が集まり始める。
- 湖面に円形の波紋が広がる。
- 和音の響きが加わり、音楽が壮大になる。

18回目の成功では、オーロラの帯が舟の船底に届く。

舟が水面から離れる瞬間には、船底から水滴が落ち、湖面に残った波紋が広がるようにする。水上から空中へ移行したことを、視覚的に理解できる演出とする。

### 第4段階：音楽に乗って空へのぼる（19〜24回目）

舟はオーロラの帯の上を滑らかに進み始める。

ここでは、タップが単なる発光ではなく、舟をさらに高く、遠くまで進ませる力になる。

- タップするたびに前方へ新しい光の波が走る。
- 舟の速度が段階的に増加する。
- 舟の進行速度は約2m/sから8m/s程度まで上昇させる。
- 雪山と湖が眼下に広がっていく。
- オーロラの色は緑、シアン、青、紫、桃色へと豊かになる。
- 舟の左右を光の粒が後方へ流れていく。

上昇中も次の光球は常に画面中央付近に表示する。

速度感は、舟の近くを流れる光、地形との視差、オーロラの曲線によって表現する。カメラの振動や急旋回には頼らない。

### クライマックス：天空の交響曲

24回目の成功から約15〜20秒間、特別な演出を行う。

舟がオーロラの帯の頂上付近に到達すると、最後の光球から巨大な光の波が解き放たれる。

光の波は複数のオーロラを順番に駆け抜け、空全体に発光するカーテンを形成する。

眼下の湖にも同じ色彩が反射し、空と湖が一体になったような風景を作る。

その瞬間に、本作で最も豊かな和音を響かせる。

クライマックスの対象となるオーロラの頂点は画面中央に置き、巨大な発光によって見切れないよう、事前にカメラを引いておく。

派手さは光の規模、色彩、音楽の広がりで表現し、爆発、急落下、激しい点滅は使用しない。

### 余韻とフリープレイ

クライマックス後は舟を減速させ、約10秒間、天空を穏やかに漂わせる。

その後も、舟の前方に新たな光球が自然に現れる。

触れると音が鳴り、オーロラに光の波が広がり、舟が天空を進むフリープレイへ移行する。

完成した天空を突然消去せず、プレイヤーが自分の作り上げた世界を引き続き楽しめるようにする。

## 6. カメラ

### 6.1 基本構図

舟の後方上部から、舟の進行方向とオーロラを見上げる三人称視点とする。

初期値の目安：

- PerspectiveCamera
- 垂直FOV：48〜58度
- 舟からの水平距離：5〜9m
- 舟からの高さ：2〜4m
- near：0.1
- far：1800

舟の一部を画面下方に配置し、自分が舟に乗っている感覚を維持する。

### 6.2 目標を中央に保つ

最優先事項は、次に触る光球を画面中央に置くことである。

光球の投影位置は、画面中央から横方向・縦方向ともに原則として画面寸法の±8%以内に収める。

光球は小さな星のように遠くへ配置せず、画面短辺の8〜12%程度の視覚的な大きさを確保する。

次の光球が出現する位置を事前に計算し、カメラの移動と光球の形成を同期させる。カメラ移動中も操作対象が画面端へ移動しないようにする。

### 6.3 縦画面・横画面への対応

アスペクト比に応じて水平・垂直FOVと対象のバウンディング領域を計算し、必要なカメラ距離を求める。

縦画面では、舟と光球、周囲のオーロラが収まるようにカメラを引く。

クライマックスでは、光の解放地点と主要なオーロラの帯が画面内に収まることを確認する。

### 6.4 酔いを防ぐ

カメラ位置と注視方向は、時間に依存したダンピングによって補間する。

- 角度変化：毎秒8〜15度程度を上限の目安とする。
- カメラのロール：原則0度。
- 急なズームは禁止。
- 舟の細かな揺れはカメラへ伝えない。
- クライマックスでも地平線の急激な傾斜を生じさせない。

プレイヤーによる自由なカメラ回転操作は実装しない。

## 7. 操作

iPad Safari、iPhone Safari、PCブラウザに対応する。

Pointer Eventsを使用し、タッチとマウスを共通の入力処理で扱う。

- 操作は指1本によるタップのみ。
- 光球の当たり判定は見た目の1.4〜1.8倍程度とする。
- 最小当たり判定は直径64 CSS pxを目安とする。
- 3D座標を画面座標へ投影した判定を利用してもよい。
- 複数の指が触れた場合は最初の有効なポインターのみ処理する。
- 同一の光球に対する成功処理は1回だけとする。
- `pointercancel`発生時は入力状態を適切に解除する。

`touch-action: none`、`overscroll-behavior: none`、`user-select: none`などを適切に設定する。

ゲーム領域内でのピンチズーム、ダブルタップズーム、スクロール、長押しメニュー、テキスト選択を抑止する。必要に応じてSafari固有のジェスチャーイベントにも対応する。

## 8. 音

すべてWebAudio APIによって手続き的に合成する。

最初のユーザータップでAudioContextを生成またはresumeする。音声ファイルや外部音源は使用しない。

### 8.1 成功音

鈴、ガラスのチャイム、ハープなどを想起させる、透明感のある音色を設計する。

OscillatorNodeによる正弦波を基本とし、複数の倍音、短いアタック、指数関数的な減衰、合成した残響を組み合わせる。

使用する音階は、どの音が連続しても調和しやすい長調のペンタトニックスケールを基本とする。

例：C、D、E、G、A。

既存の楽曲を再現せず、24回のタップで独自の旋律が完成するように音列を設計する。

| 段階 | 音の変化 |
|---|---|
| 第1段階 | 単音の鈴 |
| 第2段階 | 鈴とハープの二重奏 |
| 第3段階 | 2〜3音の和音と長い残響 |
| 第4段階 | 高音域の旋律と広がりのある和音 |
| クライマックス | 低音から高音まで広がる壮大な協和音 |

タップの間隔が不規則でも、心地よい音楽として成立させる。

### 8.2 環境音

ノイズ生成、フィルター、音量変調などを利用して、以下の環境音を合成する。

- 静かな湖のさざ波。
- 薄氷が触れ合う微かな音。
- 北の空を流れる風。
- 舟が水面を離れる際の水滴の音。
- 上昇中に舟の周囲を通り過ぎる空気の音。

環境音は成功音よりも十分小さくする。

マスターゲインとコンプレッサーを設け、複数音が重なった場合にも突然大きな音が出ないようにする。

## 9. 画面の文字

ゲーム画面に文字、数字、スコア、残り時間、進行率、ボタンラベル、操作説明を一切表示しない。

開始画面にもタイトルや開始ボタンを置かない。最初から世界を表示し、光球に触れることで自然に遊びが始まる構成とする。

進行状況は、オーロラの色、帯の本数、湖面までの距離、舟の高度、音楽の豊かさによって伝える。

矢印、手のアイコン、一般的なゲーム用HUDも使用しない。

## 10. 画質の自動調整

2020年モデル相当のiPad ProのSafariでも、50fps以上で滑らかに動作することを目標とする。

写実性を維持しつつ、特にオーロラの半透明描画、水面反射、ブルームによるGPU負荷を管理する。

| 項目 | high | mid | low |
|---|---:|---:|---:|
| ピクセル比上限 | 1.5 | 1.0 | 0.75 |
| オーロラの主要メッシュ数 | 5〜7 | 3〜5 | 2〜3 |
| 帯1枚の分割数の目安 | 256×32 | 128×16 | 64×12 |
| 水面反射 | 低解像度の反射描画 | シェーダー近似 | 簡易近似 |
| 影の解像度 | 1024 | 512 | 無効 |
| ブルーム | 有効 | 低解像度 | 無効 |
| 星の数 | 2500 | 1500 | 800 |
| 動的パーティクル上限 | 1200 | 500 | 180 |

起動時はmidを基準とし、最初の数秒間の実測FPSを参考に調整する。

実行中も移動平均FPSを監視し、48fps未満の状態が約3秒継続した場合は1段階下げる。57fps以上の状態が約15秒継続した場合は、負荷の低いタイミングで1段階上げてもよい。

頻繁な画質変更を避けるため、切替には十分なクールダウン時間を設ける。

以下のURLパラメーターによる強制指定にも対応する。

- `?q=high`
- `?q=mid`
- `?q=low`

強制指定時はFPSによる自動画質切替を停止する。

lowでも、光球への反応、オーロラの下降、舟の上昇、クライマックスを省略してはならない。ゲームの本質的な体験は全画質で共通とする。

## 11. 技術構成

### 11.1 ファイル構成

実装先は以下の1ファイルとする。

`site/games/d11/index.html`

HTML、CSS、JavaScript、シェーダー、プロシージャル生成処理をすべてこのファイル内に記述する。

Three.jsはリポジトリに同梱されている以下のライブラリをimportmapで参照する。

- `site/vendor/three/build/three.module.min.js`
- `site/vendor/three/examples/jsm/`

index.htmlからの相対パスは、それぞれ`../../vendor/three/build/three.module.min.js`、`../../vendor/three/examples/jsm/`とする。

CDN、外部API、外部アセットへの通信は禁止する。

`<head>`内には以下を必ず含める。

`<meta name="robots" content="noindex">`

`</body>`の直前には以下を必ず含める。

`<script src="../../gf-playlog.js" defer></script>`

### 11.2 状態管理

ゲームの状態を明示的に管理する。

| 状態 | 内容 |
|---|---|
| INTRO | 最初の光球を表示 |
| STAGE_1 | 湖に響く最初の音 |
| STAGE_2 | オーロラの多層化 |
| STAGE_3 | オーロラの下降 |
| STAGE_4 | 舟の上昇 |
| CLIMAX | 天空の交響曲 |
| AFTERGLOW | 余韻 |
| FREEPLAY | 継続して遊べる状態 |

成功回数、オーロラの下降量、舟の高度、舟の速度、発光強度、音楽の段階を独立した状態変数として管理する。

すべての演出はフレーム数ではなく経過時間に基づいて更新する。

### 11.3 パフォーマンス管理

- オーロラの頂点変形はGPU側を優先する。
- 星、薄氷、光の粒にはPointsやInstancedMeshを活用する。
- パーティクルはオブジェクトプールで再利用する。
- 毎フレームの不要なオブジェクト生成を避ける。
- 動的な環境マップの全方位描画は行わない。
- 半透明オブジェクトの過剰な重なりを避ける。
- 画面外の演出は可能な範囲で停止する。
- 画面回転、リサイズ、バックグラウンドからの復帰に対応する。
- 長時間のフリープレイでもメモリ使用量が増加し続けないようにする。

### 11.4 準備完了・エラー管理

`window.__ready`を初期状態ではfalseとし、シーン構築、入力処理の登録、最初の正常な描画が完了した時点でtrueにする。

ユーザーの音声有効化操作を待つために、準備完了を遅らせてはならない。

`window.__errors`はエラー情報を保持する配列とする。

通常の実行エラー、未処理のPromise rejection、初期化エラーを記録する。

### 11.5 自動プレイ

`?autotest`によって、ユーザー操作なしで全段階を進行できるようにする。

自動プレイ専用の簡略化された成功処理を作らず、通常のタップと同じ成功処理および状態遷移を利用する。

光球の準備完了を待って順番に操作し、24回の成功、クライマックス、余韻、フリープレイへの移行まで確認できるようにする。

ブラウザの自動再生制限によりAudioContextを起動できない場合は、音声なしで自動テストを継続する。

### 11.6 制作上の禁止事項

気持ち悪い生き物、おばけ、怪物、不穏な世界、シュールな表現、お姫様、既存のキャラクター、ブランド要素、既存作品の固有要素を登場させない。

別紙の禁止語は、コード、コードコメント、変数名、画面表示、その他の実装成果物に使用しないこと。表記を変えて使用することも禁止する。

## 13. 最優先の完成基準

実装工数や端末性能に制約がある場合は、次の優先順位で品質を確保すること。

1. オーロラそのものの立体感、色彩、自然な揺らぎ。
2. タップした地点から光の波が伝わる気持ちよさ。
3. 音楽とともにオーロラが湖まで降りてくる驚き。
4. 舟が水面を離れ、天空へ上昇する爽快感。
5. クライマックスにおける光と音楽の一体感。
6. 湖面、薄氷、舟、雪山の写実性。
7. その他の装飾的な演出。

細かな装飾を増やすことよりも、プレイヤーの一度のタップが、広大な世界を変化させる体験を作り込むこと。

本指示文の回数、寸法、照明強度、描画負荷に関する数値は実装時の設計目安であり、実際のレンダリング結果と端末性能に応じて調整してよい。

最終的に、子どもが「自分で空に音楽を奏でたら、オーロラが降りてきて、その上を舟で飛べた」と直感的に感じられるゲームを完成させること。
