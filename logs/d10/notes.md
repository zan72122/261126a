# D10 満月に光る花の冠を川に流す — 実装メモ

## 実装の要点

- 1ファイル `site/games/d10/index.html`（HTML＋CSS＋JS＋GLSL）。Three.js は同梱版を importmap で読む。外部画像・モデル・音声・フォントなし。地形・草花・木・石の門・花の冠・小舟・月・雲・星・光の粒・音はすべてコード内で生成。
- **川**: 中心線 `cx(s)`（ゆるい2つの正弦の和）、川幅 13〜14m → 第2段階で約18m → 第3段階で幅約70mの湖へ。左右の岸は別々の揺らぎで非対称。地形は岸に沿った2本の帯（岸の近くほど密）で、低周波＋細かいノイズ、頂点カラーで砂利・砂・土・草・森を混ぜる。草・白い花・小石・低木・木は InstancedMesh（120m ごとに分けて視錐台カリング）。
- **水面**: 専用シェーダー。頂点変位の波 2/3/4 成分（low/mid/high）＋法線だけの細かい波4本と2層ノイズ、フレネル反射（空のグラデーション）、岸からの距離で浅瀬/深みの色、月の銀色の反射帯（指数と強さを点灯数で変え、帯が長く太くなる）、冠の V 字の航跡、波紋 8 個のリング、点灯した門の光の映り込み（近い4基）、第2段階以降は青紫桃の光が川を流れる、星の映り込み（第2段階から増える）。高解像度のミラー反射は使っていない。
- **花の冠**: 直径 1.2m。3本の茎を編んだ輪（Tube）、葉 44 枚（中央脈で折れた曲面）、白い花 9・桃色の花 7（3層の花びら）・紫の小花 10 房、花芯と雄しべ、水滴 40 個。花びらは曲面メッシュで付け根→先端の色変化。逆光の透過・縁の光・後半の虹色を独自に追加（常時発光はしない）。波に合わせて上下し、傾きは最大約3度、滑走中はゆっくり回る。補助の点光源（約6000K）。
- **石の門**: 15基すべて手続き生成（積み石の柱・半円/尖頭/かご形のアーチ・要石・装飾・結晶の形が門ごとに違う）。最後の門は約1.8倍の高さで二重のアーチ。石は角を落として凹凸を付けた個別ブロック、色むら・青灰色・水際の濡れ（暗く・光沢）・苔・細かい凹凸をシェーダーで追加。起動すると柱の根元から頂点へ光が駆け上がり、石の中の光脈と結晶が輝き続ける。次の門は結晶が呼吸するように光る。最初は次の3基だけが見え、それより先の門は近づくと水面から静かに現れる（10基目の起動で残りが全部現れ、輪郭が月光に浮かぶ）。
- **月・空**: 月は画面に対して固定（横は常に中央、縦は上から20%、クライマックスで31%）。クレーター・海・光条は手続きで描いた円盤テクスチャ＋周辺減光。視直径は約6度 → 点灯ごとに大きく → 約10度、クライマックスで約17度（上端の余白を割らないよう上限あり）。空のグラデーション・月の周りの光・雲（月の近くでは薄くなり月を隠さない）・星 450〜900 個。
- **配色**: 指示文の4列（天頂・地平線・水面・月光・門の光）を、点灯数から決めた進行度で約4秒かけて連続補間。霧 FogExp2（#788EC3 系、0.0095 → 0.0058）、ACES、露出 1.02 → 1.14。
- **操作**（Pointer Events、最初の1本の指だけ）: 冠の近く（半径 70px 以上、見た目の約2.2倍）に触れると冠が沈み、波紋と水滴の音。次の門の方向（画面上の冠→門の向き）へ 28px 以上（離した時は 22px 以上）、左右 65 度以内でなぞると送り出し。冠は指に少しついて動き、成立後は慣性で門をくぐって次の位置で止まる。逆方向・短い・途中で離す操作は何も起きずに元に戻るだけ。冠以外に触れると水面に小さな波紋と光の粒。滑走中の入力は無視（二重起動なし）。
- **誘導**: 開始前は光が冠の周りを回り続ける。入力がないと 3 秒で月光が冠の縁を一周し、6 秒で冠が門の方へ少し進んで戻り、門の結晶が強く光る（7 秒周期で繰り返し。送り出しや起動は自動では起こらない）。
- **進行**（状態: IDLE / AIM / DRAG / GLIDE / ACTIVATE / ADVANCE / STAGE_TRANSITION / CLIMAX / AFTERGLOW / RESET）: 速度 2.6 / 3.8 / 5.2 m/s。5基目で岸の白い花へ光が連鎖、第2段階は門ごとに花が光り色の光が水面を流れる、10基目で反射帯が奥へつながり遠くの門が現れる、第3段階は門から光の粒が空へのぼる。
- **クライマックス**（約25秒＋余韻12秒）: 0〜2秒 最後の門の結晶が順に輝き光が頂点へ集まる → 1.5〜5秒 水面に光の道ができる → 3〜8.5秒 道の先端から空へ持ち上がる → 5〜9秒 冠が進み始める → 9〜20秒 最大約15m/sまで加速（虹色の光の粒が左右を流れる）→ 20秒 月の手前で真珠色と虹色の粒が広がる → 余韻（空の水面を漂い、粒が降りる）→ 淡い月光の霧で最初の川へ戻る（ページ再読み込みなし）。空中の川は波・反射・流れる筋を持つ立体の水路（縁が少し高い）。カメラはロール0、揺れ・白い閃光なし。
- **カメラ**: 冠の後ろ上から、冠と次の門の間を注視。毎フレーム仮のカメラで門の頂点と左右を投影し、上 8.5%・左右 9% の余白に収まるよう距離を自動調整、冠が上から約63〜65%になるよう注視点を調整、小舟の舳先が下から約10%に来るよう舟の位置を調整。縦長は縦の画角を広げる。回転・リサイズでは再計算のみ（進行は維持）。
- **音**（WebAudio のみ）: 最初の pointerdown/touchend で AudioContext を生成・再開。コンプレッサー＋生成した残響。環境音（水・風・遠い和音、合計約0.07）、触れる音、滑走のノイズ、段階ごとに単音→分散和音→高音を加えた和音（段階内で少しずつ上昇）、最後の門の上昇音、クライマックスの長い和音と水・風、到着の鐘、余韻の鐘。非表示で suspend。
- **画質**: 初期 mid。0.5 秒ごとの FPS で、50 未満が 2 秒続けば 1 段下げ、58 以上が 10 秒続けば 1 段上げ、変更後 10 秒は待つ、非表示・長いフレームは除外。`?q=low|mid|high` で固定（自動調整は停止）。low: ピクセル比 1.0・影なし・ブルームなし（光のスプライトで代用）・波2・粒子200・草花40%。mid: 1.25・影1024・半解像度ブルーム・波3・500・65%。high: 1.75・影2048・ブルーム・波4・1000・100%。水面・地形のメッシュ密度は起動時の画質で決める。
- **必須項目**: `<meta name="robots" content="noindex">`、`</body>` 直前に `gf-playlog.js`、`window.__ready`（3フレーム描画後に true）、`window.__errors`（最初の script で error / unhandledrejection を記録、フレーム内例外・初期化エラーも記録）、`?autotest`（通常の onDown/onMove/onUp に合成座標を渡す。逆方向・短い・外れたタッチも混ぜてから送り出し、15基→クライマックス→余韻→霧で戻る→再プレイ開始まで。時間は既定3倍、`&speed=` で変更）。ゲーム画面に文字・数字なし（読み込み中は中央の小さな光の輪だけ）。
- WebGL コンテキスト消失中は停止し復帰で再開。バックグラウンドから戻った時は時間を進めない。粒子・波紋・メッシュは再プレイでも作り直さない。テスト用の読み取り専用フック `window.__d10`。見た目の調整用に `?dbgskip=N`（N基が点灯済みの状態から始める。通常プレイ・テストでは使わない）。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ Playwright の Chromium（ヘッドレス、`--use-angle=swiftshader --enable-unsafe-swiftshader`）。結果は `logs/d10/test.txt`。`games/d10/index.html?autotest&q=low` を最初から通しで実行（途中を飛ばす仕組みは使っていない）。
- この環境は外部へ通信できないため、`gf-playlog.js` の送信先（workers.dev）への要求だけテスト側で空の応答を返した（返さないと接続失敗がコンソールエラーとして出る。ゲーム本体の問題ではない）。
- 1024x768（横）: `__ready`=true（約4.2秒）、`__errors`=[]、コンソールエラー 0。10状態すべて通過、クライマックス到達・月の手前に到着・霧で戻り再プレイ開始。PASS。
- 768x1024（縦）: 同上（`__ready` 約4.6秒）。PASS。
- 構図（約150msごと）: 送り出し待ちの間、門の中心の横ずれ・頂点の上端 8%・左右 7〜93%・冠の位置のはみ出し 0/135（横）・0/122（縦）。月の上端 8% と横中央の違反 0/2052・0/1439。クライマックスと余韻で冠が画面の 10〜90% から外れたサンプル 0/168・0/150。
- 最後にブルームの強さを下げた（mid/high のみに影響。low の通しテストには影響しない）後、mid・high・low で読み込みを確認し `__errors`=[]。
- スクリーンショット（low、1024x768）: `shot-1.jpg` 序盤（2基目→3基目への滑走）、`shot-2.jpg` 中盤（8基目の起動）、`shot-3.jpg` クライマックス（月へのぼる空の川）。サムネイル `site/thumbs/d10.jpg`（640x480、mid、第2段階の滑走、文字なし）。
- 禁止語の grep（ゲーム本体・メモ）: 該当なし。

## 未解決の点・注意

- iPad 実機での FPS・見え方・音・タッチは未確認。ヘッドレスは SwiftShader（CPU 描画で非常に遅い）なので FPS は参考にならず、自動画質調整の動作も実機では未検証。
- 送り出し待ちの間、次の門の中心は上から約31〜34%（指示文の目安は 40〜50%）。冠を 62〜65% に置き、門の頂点を画面内に収めることを優先した結果。月（上から20%）と門の頂点が重なることがある。
- 最後の門に向かう間はカメラが大きく下がるため、小舟の舳先が画面下端の外に出ることがある（横 1024x768 で確認）。
- 花の冠は画面の中では小さめ（横画面で幅の約 10〜12%）。当たり判定は見た目より広くしてある。
- 低木・木は単純な形の組み合わせで、近くで見ると簡素。
- 実際のマウス操作（1024x768 mid）と iPhone 相当 390x844（low）で、冠からの上方向ドラッグで送り出せることを確認（門の左右 9〜91%、門の中心 43%）。画面回転の最中・複数の指・実機タッチは未確認（処理は実装済み）。
