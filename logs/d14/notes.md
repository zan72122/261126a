# D14 朝の風と雲の帆船 — 実装メモ

## 実装の要点

- 1ファイル `site/games/d14/index.html`（HTML＋CSS＋JS＋GLSL）。Three.js は同梱版を importmap で読む。外部画像・モデル・音声・フォントは使っていない。海・空・雲・島・帆船・海鳥・音はすべてコード内で生成。
- **遊びの1回**（状態 `START → WAIT_WIND → WIND_BURST → SUNLIGHT → ASCEND → NEXT_TARGET`）: 画面を横になぞって 22 CSS px 動いた時点で成立（左右どちらでも可、指を離す前でよい、1ジェスチャーで1回だけ）。指が動いた瞬間から風の流線・帆の張り・雲の傾き（指の方向へ最大 2.2m）で予備反応。成立後は 0〜0.1 秒 風の効果音＋流線、0.1〜0.5 秒 帆が張り雲が航路の外へ流れる（指の向きにかかわらず必ず航路から外れる距離）、0.3〜1.2 秒 雲の切れ目から光芒が差し海面の光の円が開く（成功音はここで鳴る）、0.5〜2 秒 海のきらめき・加速、1.2〜3.8 秒 海面上昇（光の帯が船まで伸び、船が入る瞬間に追加のきらめき音と航跡強調）、4〜6 秒 次の雲が視界に入りカメラの中心が次の目標へ移る。
- **雲影**: 雲の位置から太陽と反対側へ投影した楕円の影（輪郭はノイズで不規則）を水面シェーダーで最大16個計算。目標の雲は影がちょうど目標の海面にかかる位置に置く。風で雲が流れると影も一緒に動き、そこへ光が差す。
- **海面**: Gerstner 波6本（うねり 24m/19m、中波 7.5m/5.5m、小波 1.8m/1.1m、振幅は指示の範囲）。中心ほど細かい極座標メッシュ（画質で 64〜160 リング）を船に追従させ、波は世界座標で計算。細部は生成した周期ノイズの法線テクスチャを3層スクロール。Fresnel、空の反射、青緑の深さ、太陽の細かな鏡面反射＋きらめく光の粒（時間で出現・消失）、雲影、光の円と船へ伸びる光の帯、船尾のV字航跡と泡、船体まわりの泡と接地影、遠景での細部減衰。
- **海が空へ持ち上がる**: 成功ごとに海面の基準高度が上がる（第1段階 4m、第2段階 6m、第3段階 7m、第4段階 6m、クライマックスで残り 16m。合計 125m で上限）。持ち上がった海は「浮かぶ水のレンズ」として扱い、船から離れるほど縁が下がる形にした。高くなるほど半径が縮み（420m→約245m）、縁の向こうに下の世界が見える。下の海（高さ 0）と島・岩礁、雲（高さ 38〜82m）、雲海（高さ 72m の層）は世界に固定したままなので、島が低く見え、雲が頭上→同じ高さ→足もとへと変わる。縁には細い滝（半透明の円筒＋流れるノイズ、下は霧）を置いた（遠景のみ。船は近づかない）。
- **帆船**: 断面を24本並べてつないだ船体（白い塗装・木の帯・水線下の色）、木目の CanvasTexture の甲板と手すり、小さな船室、マスト・ブーム、真鍮の金具（環境マップで反射）。主帆（12×16 分割）と前帆（9×12）は毎フレーム変形：風が弱いと浅くたるみ・しわ・端のはためき、強いと深く張る。帆布は繊維と縫い目の CanvasTexture。シートは弱いとたるみ、強いと張る。揺れはロール最大2°、ピッチ最大1.5°（カメラには伝えない）。人物なし。
- **空・雲**: 空はドームのシェーダー（天頂・地平線・太陽周辺・太陽円盤 約1.5°）。雲は生成した密度ノイズ（4種類）に上からの光の減衰を焼き込んだテクスチャを、1回の描画のビルボード群で表示（遠い順に並べ替え）。受光部・陰影部の色、縁の朝日の縁取り（逆光で強まる）、水面付近での溶け込み。環境マップは空から PMREM で生成し、段階の色が変わったときだけ作り直す。
- **段階**（全4段階×5回、計20回）: 空・海・雲・太陽光・霧の色は指示の表の値を段階に合わせて補間（トーンマッピングに合わせて霧色を地平線色に少し寄せた）。太陽高度 12°→30°。船速は通常 1.8/2.2/2.6/3.0、成功時 4.0/5.5/7.0/8.5 m/s。第1段階5回目は遠くへ続く金色の航路、第2段階からは風が少し遅れて奥の雲にも伝わる（10回目は雲が左右に分かれ広い光の帯）、第2段階から海鳥が船と並んで飛ぶ。第3段階は雲が海面と同じ高さに並び、霧の雲の向こうに海が現れる。第4段階は雲海の上の海。
- **クライマックス**（約13.5秒）: 帆が大きく張り加速 → 大きな雲が左右へ分かれる → 光芒と太陽の輝きが広がる → 金色のきらめきの帯が海面を奥から手前へ走る → 霧の粒が朝日に照らされる → 海面が最後の一段を上昇 → 海鳥が光の前を横切る、C4・G4・C5・E5・G5・C6 の和音とベル、最後は風が静まり波の音が残る。中心は常に船の行き先の光の円。カメラは回転せず少し引くだけ。その後は約8秒かけて減速し `FREE_PLAY`（なぞるたびに雲・帆・加速・きらめき。海の高さは上限で止まる）。
- **カメラ**: 船の斜め後方（水平約20°）から見下ろす。注視点＝目標の海面で、常に画面中央。船の外接箱（帆・マスト・ブームを含む）と目標の周囲を投影し、四辺 9% の余白に収まる最小距離を毎フレーム二分探索（縦画面は画角も広げる）。位置と注視点は時定数 0.6 秒の追従（船の等速移動分は先回りして遅れを出さない）。ロールなし、急な旋回・ズームなし。
- **誘導**: 無操作 2.5 秒で目標の雲の縁を金色の光が横切り、続いて雲と海面を横切る短い風の流線と小さな揺れ。5 秒以上は少し強く繰り返す。文字・矢印・手の絵は使わない。誘導だけでは成功しない。
- **失敗なし**: 短すぎる操作は何も減らさず、その場の状態を維持。待機中は船が微速で進み、目標の手前 25m 付近で目標と一緒にゆっくり進む（通り過ぎない）。
- **入力**: Pointer Events（タッチ・マウス共通）。最初の `pointerId` だけを追跡、`setPointerCapture`、`pointerup/pointercancel/lostpointercapture`/blur で解除。`touch-action:none` などでピンチ・ダブルタップ・スクロール・長押しメニュー・選択・ドラッグを抑止。
- **音**（WebAudio のみ）: 最初の操作で AudioContext を生成・resume（失敗しても進行は止めない）。マスター 0.36＋コンプレッサー＋生成した残響。波（ノイズ＋ローパス、ゆっくり変化、ループのつなぎ目はクロスフェード）、風（ピンクノイズ＋バンドパス、風の強さで音量と周波数が連続変化）、帆のはためき（短いノイズ）、航跡（船速連動）、成功音（C メジャー・ペンタトニックのベル、段階ごとに C5-E5 / +G5 / +A5 / C6、回ごとに倍音と余韻を少し変える）、海面上昇（ゆっくり上がる3音）、海鳥（周波数変調の短い声）、長い持続音（段階で厚くなる）。タブ非表示で停止。
- **画質**: `low / mid / high`（ピクセル比 1.0/1.25/1.75、水面 64/96/160 リング、影 なし（水面シェーダーの接地影）/1024/2048、雲の要素 35/70/120、粒子 120/300/600、海鳥 3/5/8、ブルーム なし/半解像度/通常、光芒 1/2/4 本）。初期 mid。直近 2.5 秒のフレーム時間から FPS を出し、48 未満が 2 秒で1段下げ、55 以上が 8 秒で1段上げ、切替後 8 秒は待つ。タブ復帰直後は除外。`?q=low|mid|high` で固定。
- **必須項目**: `<meta name="robots" content="noindex">`、`</body>` 直前に `gf-playlog.js`、`window.__ready`（初期化後3フレーム描画で true）、`window.__errors`（error／リソース失敗／unhandledrejection／フレーム内の例外）、`?autotest`（通常の pointer ハンドラーに合成イベントを渡す。20回→クライマックス→フリープレイ2回。途中で無操作の誘導2回、短すぎる操作、2本目の指を含む。時間倍率は既定 2.5、`&speed=` で変更）。ゲーム画面に文字・数字なし。テスト用の読み取り専用フック `window.__d14`、`?dbg` のときだけ内部を `window.__dbg` に出す。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ Playwright の Chromium（ヘッドレス、`--use-angle=swiftshader --enable-unsafe-swiftshader`）。スクリプトは `logs/d14/autotest.js`、結果は `logs/d14/test.txt`（tee で保存）。プレイログの送信先（外部）はこの環境から接続できないため、その通信だけ Playwright で 204 を返し、外部通信の一覧からは除いた（ゲーム本体からの外部通信はなし）。
- `games/d14/index.html?autotest&q=low`（時間倍率 2.5）:
  - 1024x768（横、8 回目の上昇中に 768x1024 へ回転し 9 回目で戻す）: `__ready`=true（約 3.1 秒）、`__errors`=[]、コンソールエラー 0、20 回成功 → 4 段階 → CLIMAX → FREE_PLAY（フリープレイ 2 回）。通過した状態 START>WAIT_WIND>WIND_BURST>SUNLIGHT>ASCEND>NEXT_TARGET>CLIMAX>FREE_PLAY。海面高度 125m（上限）。RESULT: PASS。回転しても進行は保持。
  - 768x1024（縦）: 同じく `__ready`=true、`__errors`=[]、コンソールエラー 0、全段階・クライマックス・フリープレイ到達。RESULT: PASS。
  - 待機中の目標は横・縦とも画面の 50%,50%（5% 以上ずれたサンプル 0/32）。船の外接箱が画面外に出たサンプル 0（横 0/247、縦 0/250）。クライマックス中の光の中心も 50%,50%。
  - 短すぎる操作（10px）では成功せず、2本目の指は無視され、成功は 20 回で止まった（taps=25, gestures=22）。無操作時の誘導が発生（hints=3）。
- スクリーンショット（low 画質、横）: `shot-1.jpg` 序盤（最初の風のあと雲の切れ目から光が差す）、`shot-2.jpg` 中盤（雲海の上に浮かぶ海）、`shot-3.jpg` クライマックス。サムネイル `site/thumbs/d14.jpg`（640x480、文字なし、雲海の上の海）。
- `?q=mid` で開始画面の表示と `__errors` 空を個別に確認（ブルームあり）。
- 禁止語の grep（`site/games/d14`、`logs/d14`）: 該当なし。

## 未解決の点・注意

- iPad 実機での性能（50fps 目標）・見え方・音・タッチの感触は未確認。ヘッドレスは SwiftShader（CPU 描画）でフレームレートが低く、自動画質調整のしきい値は実機で未検証。high 画質は通しテストをしていない（mid は開始画面のみ確認）。390x844 のスマートフォン相当は今回は通しで確認していない（縦画面は画角を広げる処理を共通で使う）。
- 自動テストの状態のサンプリングが遅く、クライマックス中の中央判定は 2 サンプルのみ。
- 第3〜第4段階は地平線付近の色が白に近く（指示の色表どおり）、霧と雲海で全体がやや白っぽい。太陽高度 30° の最終段階では太陽本体は画面の外（光芒と空の輝きで表現）。
- 滝は浮かぶ海の縁の向こう側にあるため、カメラ位置によってはほとんど見えない。
- 雲はビルボードのため、近くで横から見ると平面感が出ることがある（カメラ近くでは薄くして回避）。
- PC のマウス操作・実機のタッチは、ヘッドレスでの合成ポインターイベントによる確認のみ。音はヘッドレスで生成エラーが出ないことのみ確認（聴感は未確認）。
