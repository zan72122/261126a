# D02 灯台の朝 — 実装メモ

## 実装の要点

- 1ファイル `site/games/d02/index.html`（HTML＋CSS＋JS＋GLSL）。Three.js は同梱版を importmap で読む。外部画像・モデル・音声・フォントなし。テクスチャ（石積み・漆喰・スレート瓦・木目・地面・室内の灯り・雲・光の輪）はすべて Canvas で手続き生成。
- 舞台: 海面 Y=0、1単位≒1m。西が低い港、東へ行くほど高くなる崖上の村（前列10棟＋後列4棟＋灯台守の家＋灯台の付属棟＝16棟）、東端の岩場に高さ約23mの白い灯台（手すり・ガラスの灯室・金属屋根・回るレンズ・淡い光の筋）。桟橋、係留された小舟3艘、岩、木、花壇、柵、遠景の島。
- 静的な建物は材質ごとに結合（石・漆喰・瓦・木・塗装・金属の6メッシュ）、窓は「枠・ガラス・室内の灯り・壁に落ちる加算グロー」の4つの InstancedMesh。low 品質で描画コール約30。
- 海: 同心円グリッドのメッシュ＋自前シェーダー（複数の正弦波＋ノイズの法線、フレネルで空の解析反射、地形から作った水深テクスチャで浅瀬色と岸の泡、点灯した窓・光の玉・灯室の疑似反射、朝日の金色の帯）。
- 空: グラデーションのスカイドーム（星・夜明けの光・太陽円盤）。同じ空から PMREM で環境マップを作り、段階が進むたびに更新。雲は InstancedMesh のビルボード。
- 4段階の色は指示文の表の値を基準に補間（日の出の段だけ、白っぽく見えたので天頂・水平線・霧を少し濃く調整）。HemisphereLight 1.65→1.85、DirectionalLight 0.8→約3.0、ACES、露出 1.14→0.86、Fog 35/150→90/380。
- ブルーム: high/mid は UnrealBloomPass（mid は半解像度）、low は加算グローのみ（擬似発光）。
- 状態遷移: INITIALIZING → WAITING_FOR_WINDOW → WINDOW_LIGHTING → ORB_ASCENDING → STEP_FORMING → BOAT_ASCENDING → NEXT_WINDOW → … → GRAND_SUNRISE → AFTERGLOW → RESET。進行・タイマーは `update()` の1か所で管理。
- 1回のループ: タップ直後に窓が点灯・光の輪・粒子・ベル（反応は同じフレーム内）→ 0.4秒で光の玉が生まれ、ベジェ曲線で弧を描いて上昇 → 到着で光り、粒子が集まり、横に広がって半透明の金色の足場になり、縁を光が走る（完成済みの段も下から順に光る）→ 舟が水平を保ったまま次の段へ（金の粒がこぼれ、着地で光の輪）→ 次の窓へ。
- 誘導: 対象の窓は1つだけ。1.4秒周期の脈動、枠を回る金の粒、3秒で光が広がる、6秒で光の輪を1回。最後の灯室の窓は大きく脈動。外れたタップは小さなきらめきだけ（否定的な反応なし）。
- 段階ごとの音: 単音 → 二音 → 三和音 → 分散和音、日の出で Cmaj9 系の和音。波・風・海鳥の声・穏やかなパッドはすべて WebAudio で合成。最初のタップで AudioContext を作成/再開。コンプレッサーでクリップ防止、同時発音数を制限。
- カメラ: 舟の後ろ上方（舟の一部が画面下に見える）から、状態ごとの目標を `lookAt` で画面中央に置く。窓・次の段・弧の頂点を3D点として投影し、画面の72%以内に収まるまでカメラを後退させる距離を毎フレーム求める（見切れ防止）。回転は毎秒15〜20°程度に制限、位置は減衰補間。縦向きは垂直FOV 50°、横向き 42°。
- クライマックス: 20段を下から光が駆けのぼる → 灯台上部から光の輪が2つ広がって上昇 → カメラが東の水平線へ向き、太陽が昇る（画面中央）→ 海に金色の帯、空・霧・光源が朝の色へ → 余韻では湾の上空から朝日を浴びた村全体を見せ、その後中央に再開用の光の玉。タップ、または15秒で金色の光に包まれて最初の港へ戻る。
- 画質: 初期 mid。平均FPS<48が2秒で1段下げ、≥57が8秒で1段上げ、変更後5秒は再変更なし、非表示/復帰直後は計測しない。`?q=low|mid|high` で固定。
- 必須項目: `<meta name="robots" content="noindex">`、`</body>` 直前の `gf-playlog.js`、`window.__ready` / `window.__errors`（error と unhandledrejection を記録）、`?autotest`（受付状態になった窓へ通常のタップと同じ処理 `handleTap()` を呼ぶ。再開の光の玉も同様にタップしてリセットまで進む）。
- 開発用: `?skip=N`（最初から N 個点灯した状態で始める。確認用）、`?debug`（内部オブジェクトを公開）。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ Playwright の Chromium（ヘッドレス、`--use-angle=swiftshader --enable-unsafe-swiftshader`）。
- `games/d02/index.html?autotest&q=low` を 1024x768（横）と 768x1024（縦）で、ページ読込からリセット後の最初の窓まで通しで実行。結果は `logs/d02/test.txt`。
- 1024x768（横）: `__ready`=true（約4秒）、`__errors`=[]、コンソールエラーなし、20窓すべて点灯→GRAND_SUNRISE→AFTERGLOW→RESET→最初の窓まで到達（約221秒）。PASS。
- 768x1024（縦）: 同上（約210秒）。PASS。
- 見切れ確認（`G.probe()` で投影座標を 250ms ごとに取得）: 操作待ちの窓は画面中心から最大 2.1%（横）/ 2.7%（縦）。光の玉の飛行中に玉・次の段が画面外に出たサンプル 0。日の出の太陽は中心から最大 3.1%（横）/ 2.6%（縦）。
- 補足: `?q=mid&skip=17`（ブルーム・影あり）でもクライマックス〜リセットまでエラーなし。low の描画コール約29、mid 約57（影パス込み）。
- スクリーンショット: `shot-1.jpg`（序盤・2個目の光の玉）、`shot-2.jpg`（中盤・11個目）、`shot-3.jpg`（クライマックス・日の出）。サムネイル `site/thumbs/d02.jpg`（640x480）。
- 禁止語の grep（ソース・メモ）: 該当なし。

## 未解決の点・注意

- iPad 実機での性能（50fps 目標）は未検証。ヘッドレスは SwiftShader（CPU 描画）のため FPS は参考にならない。mid/high（影・ブルーム）の見た目は実機で要確認。
- テスト環境からは gf-playlog の送信先に接続できないため、テストではそのリクエストだけ 204 を返すようにした（ゲーム本体は変更していない）。
- low 品質（ブルームなし）では光の階段がやや平板な黄色に見える。実機の mid/high ではブルームで発光感が出る想定。
- 木・島はローポリ寄りで、近景の写実感に比べると簡素。
- 1周は自動プレイで約3分半（20回×約8.5秒＋日の出13秒＋余韻約14秒）。
