# D03 動物が集まる平原の、輝く空 — 実装メモ

## 実装の要点

- 1ファイル `site/games/d03/index.html`（HTML＋CSS＋JS＋GLSL）。Three.js は同梱版を importmap で読む。外部画像・モデル・音声・フォントなし（テクスチャは Canvas とシェーダーで手続き生成）。
- 舞台: 600m 四方の地形（複数周波数ノイズ＋道沿いの平坦化＋終点の丘＋水場2か所の窪み）、遠景の丘リング。進行経路は CatmullRom スプライン（約370m）、終点は丘の頂上。土の道は 1024² のマスクテクスチャ（道からの距離）で描き、小石・踏み固めの色差あり。草は InstancedMesh（風で穂先が揺れる、成功時の光の波紋を受ける）、アカシア風の樹木（枝分かれ＋平たい樹冠、2描画呼び出しに結合）、岩はインスタンス。
- 水場: 平面＋自前シェーダー（2〜4方向の正弦波の法線、フレネル、空色の近似反射、夕日の細長い反射）。色 `#769FA6` / 浅瀬 `#A8C2AF`。
- 空: シェーダーのドーム（天頂〜地平線のグラデーション、太陽の光彩、ノイズ雲：太陽側が金色・影側が桃〜紫、クライマックスで輪の中心から光の筋）。ACES の前段で空・霧・水の色を補正し、白飛びを防いでいる。
- 色: 指示文の表（天頂・地平線・雲・霞・草原・色温度・太陽仰角）を 0〜3 の連続値で補間。1回の呼びかけごとに 0.1 ずつ、段階移行で整数へ、時定数 1.6 秒で滑らかに移行。
- 動物: 断面形状を補間する自作の「ロフト」メッシュ（楕円断面＋半径のスプライン補間＋法線の傾き補正）で胴・首・頭・脚（上下2関節）・耳・尾を作り、関節ごとのグループで動かす。模様はオブジェクト空間のシェーダー（キリン＝3D ボロノイの網目、シマウマ＝部位ごとの向きを持つ縞、ゾウ＝皺とまだらの肌＋微細な法線の揺らぎ）。耳・首・背中の輪郭に太陽側の金色のリムライト。
  - キリン（全高約4.8m）：側対歩寄りの歩行、首の上下動、瞬き、耳、尾。
  - ゾウ：7関節の鼻、大きな耳のはためき、牙、重い歩行。
  - シマウマ：たてがみ、蹄、速度で常歩→速歩に切り替え。
  - 鳥（シラサギ風、4〜5羽×6群＝27羽）：内翼＋外翼（初列風切を扇状に並べた羽根）の関節構造を InstancedMesh で描画。地上で餌をついばみ、飛び立ち、行進の上空を旋回・滑空。
  - 個体差：大きさ、歩行周期、耳・尾の揺れの位相。
- 行進: 仲間は左右の列に並び、新しく来た動物が先頭（キリンの横）に入り、他は後ろへずれる。経路追従＋速度補間＋接地＋簡易な間隔調整（物理エンジンなし）。
- ループ: 対象の動物の頭上に金色の光（1.5 秒周期の脈動）→ タップで光が弾け、成功音、動物が反応（耳・首・鼻・翼）→ シマウマ約5m/s・ゾウ約3m/s で駆け寄り減速して合流 → 砂ぼこり、金色の花粉、地面の光の波紋、空の色が一歩進む（第3段階では光の筋も）。
- 何もしない時: 2.5秒で光彩が強まり、5.5秒で光が上下・動物が顔を上げ・地面に同系色の光が3秒ごとに広がる。外れたタップは小さなきらめきのみ。
- 段階: 3段階×6回（第1：シマウマ3・ゾウ1・鳥2、第2：シマウマ2・ゾウ2・鳥2、第3：シマウマ1・ゾウ3・鳥2）。歩行速度 1.5 / 1.78 / 2.05 m/s。段階の切り替えでカメラが引いて行進全体を見せる（約5秒）。
- クライマックス（約24秒＋余韻）: 頂上で停止・仲間が両脇に集まる → 3〜6秒で全員の足元から花粉の流れが空の中央へ、中心に光が生まれる → 6〜10秒で3層の光の輪（主輪 `#FFF2AE` 系、内側 `#FFFBE8`、外縁 `#FFD4C9`）が広がり、空の光の筋、雲・草原・動物の背へ金色が伝わる、和音と鐘 → 余韻で光の粒が降り、キリンが首を上げ、ゾウが鼻を上げる。その後、キリンの背の上に小さな光（カメラが落ち着いてから出現）。触れると金色のフェードで最初に戻る。触れなければそのまま。
- カメラ: キリンの斜め後方上（距離約11m・高さ約8m・横20°前後、操作対象と反対側）。操作対象の光を注視点とし、キリンの頭・対象の動物が四辺の余白 8%（縦向き 9%）に入るよう、カメラ距離を閉形式で求めて自動で引く。位置・注視点は時間ベースの減衰補間（0.55〜0.75秒）。光はカメラが落ち着いてから出現。クライマックスは専用の構図で、輪の半径を毎フレーム「現在のカメラから見て余白 8% 以内」に収まるよう計算するため、縦横どちらでも見切れない。
- 音: すべて WebAudio。風（帯域ノイズ）、草の擦れ、ゾウの低い足音、シマウマの蹄、キリンの足音、小鳥のさえずり（FM）、羽音、持続パッド。成功音は段階ごとに C-E-G → +A → +C6 と豊かに、クライマックスは C2〜C6 の和音＋鐘＋残響。マスター 0.28＋コンプレッサー。最初のタップで AudioContext を生成/再開。
- 画質: low/mid/high プリセット（ピクセル比、影 512なし/1024/2048、草 3000/8000/18000、発光粒子 160/450/1000、ブルーム なし/半解像度/通常、水面の詳細）。初期 mid。移動平均 FPS が 50 未満 3 秒で下げる、58 以上 10 秒で上げる、切替後 12 秒は据え置き、非表示・回転直後・起動直後は計測しない。`?q=low|mid|high` で固定。low は影の代わりに接地影（ぼかし円）。
- 入力: Pointer Events、最初のポインターのみ追跡、光は見た目の約1.7倍（最低半径 62px）、対象の動物の体もレイキャストで有効。ピンチ・ダブルタップ・長押しメニュー・選択・スクロールを抑止。
- 状態機械: INIT → TITLE_IDLE → TRAVEL → TARGET_READY → ANIMAL_JOIN →（STAGE_TRANSITION）→ … → CLIMAX → AFTERGLOW。
- 必須項目: `<meta name="robots" content="noindex">`、`</body>` 直前の `gf-playlog.js`、`window.__ready`（3フレーム描画後 true）、`window.__errors`（error / unhandledrejection / WebGL コンテキスト喪失）。`?autotest` は通常のタップと同じ `handleTap()` に光の画面座標を渡して進める（時間は 1.8 倍速）。開発者ツール用に `window.__game.probe()`（光・キリンの頭・輪の投影座標）、`window.__autotest`（完了時の結果）。
- 確認用パラメータ: `?skip=N`（開始時に N 回分の仲間を合流済みにする。`?skip=18` でクライマックス直前から）。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ Playwright の Chromium（ヘッドレス、`--use-angle=swiftshader --enable-unsafe-swiftshader`）。
- `games/d03/index.html?autotest&q=low` を 1024x768（横）と 768x1024（縦）で、読み込み → 18回の呼びかけ → 3段階 → クライマックス → 余韻 → 再スタートの光をタップ → 最初の画面に戻るまで通しで実行。結果は `logs/d03/test.txt`。
  - 1024x768: `__ready`=true（約3秒）、`__errors`=[]、コンソールエラーなし、クライマックス到達、PASS（約195秒）。
  - 768x1024: 同上、PASS（約195秒）。
  - 見切れ確認（`probe()` を約150〜400msごと）: 操作待ちの光の中心からのずれ 最大0%（横・縦）、光の輪 48〜50サンプルすべて画面内、キリンの頭が画面外になったサンプル 0。
  - 外部リクエストは gf-playlog の送信のみ（テストでは 204 を返した）。ゲーム本体は外部リソースを読まない。
- スクリーンショット: `shot-1.jpg`（序盤・3回目の呼びかけ待ち）、`shot-2.jpg`（中盤・12回目、桃色の空と鳥の群れ）、`shot-3.jpg`（クライマックスの光の輪）。サムネイル `site/thumbs/d03.jpg`（640x480、クライマックス）。
- 禁止語の grep（ソース・メモ、ひらがな・カタカナ表記含む）: 該当なし。

## 未解決の点・注意

- iPad 実機での性能（50fps 目標）と見た目は未検証。ヘッドレスは SwiftShader（CPU 描画）のため FPS は参考にならず、確認は low 品質のみ。mid/high（影・ブルーム）の見え方は実機で要確認。
- low（ブルームなし）では光の輪がやや白く強めに見える。mid/high ではブルームで滲みが加わる想定。
- 動物はロフトメッシュ＋シェーダー模様で、近くで見ると造形はまだ簡素（特にゾウを後ろから見た形、シマウマの頭部）。LOD 切り替えは未実装（全頭同じ詳細度、描画呼び出しは low で約 200）。
- 草は low だと疎ら。
- 鳥の群れがキリンの頭の近くで操作対象の光と重なって見える瞬間がある（鳥は地上の群れの中心に光を置いているため）。
- iPhone 390x844 は今回テストしていない（縦向きの視野角 55° と余白計算で対応する設計）。
